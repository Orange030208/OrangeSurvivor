# 统一内容池系统使用指南

## 1. 系统目标

统一内容池系统负责从一组候选内容中，根据上下文、条件策略、权重规则、历史状态和全局 Modifier 抽出结果。

当前接入用途：

- 升级卡三选一
- 宝箱奖励三选一
- 商店商品刷新
- 掉落结果
- 波次刷怪候选
- 随机武器奖励

内容池只负责候选筛选、权重计算、抽取和历史记录。购买、装备、应用升级、生成敌人、发放掉落等行为仍由业务系统执行。

## 2. 基本概念

### 2.1 ContentPoolSO

`ContentPoolSO` 表示一个抽取用途。

关键字段：

- `Purpose`：池用途，例如 `UpgradeCard`、`Shop`、`Drop`、`WaveSpawn`。
- `DefaultRollCount`：默认抽取数量。
- `AllowDuplicateResults`：同一次抽取是否允许重复结果。
- `Entries`：候选条目列表。

一个池只表达一类用途，不要把商店、掉落、宝箱、刷怪混到同一个池里。

### 2.2 ContentPoolEntry

`ContentPoolEntry` 是池中的单个候选。

关键字段：

- `EntryId`：稳定条目 ID，用于历史统计、互斥和次数限制。
- `Content`：候选内容资产。
- `BaseWeight`：基础权重。
- `MaxRollCount`：当前历史作用域内最多被抽出多少次。
- `MaxPickCount`：当前历史作用域内最多被选择多少次。
- `MinLevel` / `MaxLevel`：业务元数据，常用于武器等级范围。
- `QualityValue`：业务元数据，常用于品质或稀有度。
- `DomainFlags`：业务元数据，常用于领域枚举 bit mask，例如刷怪标签。
- `PriceMultiplier`：业务元数据，常用于商店价格倍率。
- `Conditions`：进入候选池前必须满足的条件策略。
- `WeightRules`：进入候选池后用于调整权重的规则。

`Content` 是通用引用，业务系统应在抽取时用 `entryFilter` 限制类型。例如升级卡池只接受 `UpgradeCardSO`，刷怪池接受 `EnemySO` 或 `WaveSpawnPackSO`。

### 2.3 ContentRollContext

`ContentRollContext` 是抽取上下文输入，替代旧的中间抽取表。

当前可提供的核心变量：

- `Purpose`
- `Player` / `Source`
- `PropertiesManager`
- `WeaponsHolder`
- `CharacterData`
- `WaveSpawn`
- `ProgressionSnapshot`
- `WaveId`
- `WaveTrackId`
- `WaveProgressPercent`
- `ShopRefreshCount`
- `ShopRerollCount`
- `HistoryScope`
- `History`

条件策略和权重规则通过 `ContentPoolEvaluationContext` 读取这些变量。新增规则时优先在规则类里明确读取需要的上下文变量，不要新增散落的中间映射层。

### 2.4 ContentHistoryState

`ContentHistoryState` 是内容系统统一维护的运行时历史。

它记录：

- Entry 被抽出次数。
- Entry 被选择次数。
- 内容资产被选择次数。
- 上一次抽取提供过哪些 Entry。
- 升级卡标签选择次数。

`ContentHistoryScope` 用于隔离不同用途、池和拥有者。升级卡、商店、宝箱、掉落、刷怪和武器奖励都应把历史写入内容系统，不再由各自模块维护一套私有抽取历史。

## 3. 抽取流程

一次抽取的流程：

1. 业务系统构造 `ContentRollContext`。
2. `ContentPoolRollService` 创建 `ContentPoolEvaluationContext`。
3. 按 `ContentPoolEntry.Conditions` 过滤不可用候选。
4. 按 `BaseWeight` 和 `WeightRules` 计算候选权重。
5. 执行已注册的 `IContentPoolModifier`。
6. 按最终权重随机抽取。
7. 根据重复、互斥、次数限制继续抽取后续结果。
8. 把 roll 结果记录到 `ContentHistoryState`。
9. 业务系统消费 `ContentRollResult`，并在玩家确认购买、领取或选择后记录 pick。

`ContentRollItem` 包含：

- `Content`
- `Entry`
- `EntryId`
- `FinalWeight`
- `MinLevel`
- `MaxLevel`
- `QualityValue`
- `DomainFlags`
- `PriceMultiplier`

业务系统不要重新计算权重，只消费抽取结果和元数据。

## 4. 条件策略

条件只决定候选能不能进入池，不修改权重。

常用条件：

- `AlwaysContentCondition`
- `CandidateTypeContentCondition`
- `CandidateAssetContentCondition`
- `CurrentWaveCondition`
- `WaveTrackCondition`
- `WaveIdCondition`
- `WaveProgressCondition`
- `RunProgressionValueCondition`
- `PlayerPropertyCondition`
- `ShopRefreshCountCondition`
- `ShopRerollCountCondition`
- `OwnedWeaponCountCondition`
- `OwnedWeaponTagCountCondition`
- `OwnedWeaponCondition`
- `UpgradeCardTagCondition`
- `UpgradeCardTagPickCountCondition`
- `ContentPickCountCondition`
- `MutuallyExclusiveEntryCondition`
- `UniqueUpgradeCardTagCondition`
- `UniqueContentTypeCondition`
- `UniqueAssetCondition`
- `ContentOfferHistoryCondition`

常见例子：

- 第 3 波后出现：`CurrentWaveCondition >= 3`。
- 只在某条刷怪轨道出现：`WaveTrackCondition`。
- 波次 50% 后出现：`WaveProgressCondition >= 50`。
- 拥有某类武器后出现：`OwnedWeaponTagCountCondition >= 1`。
- 已选某类升级卡后提高流派相关内容：用升级卡标签历史条件或权重规则。
- 同轮两张卡互斥：用 `MutuallyExclusiveEntryCondition`。

## 5. 权重规则

权重规则只修改已通过条件的候选权重。

当前支持：

- `AddWeightContentRule`
- `MultiplyWeightContentRule`
- `PreviousRollWeightContentRule`
- `PlayerPropertyScaleWeightRule`
- `CandidateUpgradeCardTagWeightRule`
- `UpgradeCardTagPickCountWeightRule`

常见例子：

- 幸运值提高宝箱掉落权重：使用 `PlayerPropertyScaleWeightRule(PropType.Luck)`。
- 已选攻击类升级卡越多，攻击类升级卡越容易出现：使用 `UpgradeCardTagPickCountWeightRule`。
- 指定升级卡标签整体加权：使用 `CandidateUpgradeCardTagWeightRule`。
- 上一次已经出现过的商品降低权重：使用 `PreviousRollWeightContentRule`。

## 6. Modifier

`IContentPoolModifier` 可以在抽取前修改候选权重或元数据。

已有可配置 Effect：

- `UpgradeCardTagContentPoolWeightModifierEffect`
- `AssetContentPoolWeightModifierEffect`
- `UpgradeCardTagContentPoolMetadataModifierEffect`
- `AssetContentPoolMetadataModifierEffect`
- `WaveEnemyWeightModifier`

Modifier 通过 `ContentPoolModifierRegistry` 安装和卸载，通常由升级卡、Buff、饰品或角色能力的效果系统驱动。

Modifier 应保持职责单一：只调整候选，不直接发奖、不购买、不装备、不生成场景对象。

## 7. 各业务接入

### 7.1 升级卡池

资产：`Assets/GameContent/Upgrades/Pools/Upgrade Card Pool.asset`

内容类型：`UpgradeCardSO`

运行时入口：

- `RewardSelectionManager`
- `UpgradeCardRollService`

升级卡标签直接使用 `UpgradeCardSO.Tags` 的掩码。内容池条件和权重规则直接读取该掩码，不再维护重复的内容标签资产。

### 7.2 宝箱奖励池

资产：`Assets/GameContent/Catalog/Pools/Chest Reward Pool.asset`

内容类型：`AccessoryDataSO`

运行时入口：`RewardSelectionManager`

饰品品质写入 `QualityValue`，价格或等级相关元数据仍通过 Entry 配置。

### 7.3 商店池

资产：`Assets/GameContent/Catalog/Pools/Shop Pool.asset`

内容类型：`WeaponDataSO` 和 `AccessoryDataSO`

运行时入口：`ShopManager`

商店刷新时传入 `ShopRefreshCount`、`ShopRerollCount`、玩家属性、武器持有状态和统一历史。玩家购买成功后记录 pick。

### 7.4 掉落池

资产：`Assets/GameContent/Catalog/Pools/Drop Pool.asset`

内容类型：`CollectionSO`

运行时入口：`DropManager`

幸运值、当前波次和推进快照都通过 `ContentRollContext` 输入。金币单个掉落值和击杀经验仍由掉落/击杀奖励业务决定。

### 7.5 刷怪池

资产：`Assets/GameContent/Waves/Pools/Wave Spawn Pool.asset`

内容类型：`EnemySO` 或 `WaveSpawnPackSO`

运行时入口：`WaveSpawnExecutionService`

波次和轨道节奏仍由 `WaveSpawnPlan` / `WaveSegment` 控制。候选敌人、刷怪包、权重、标签和条件在 `Wave Spawn Pool.asset` 中维护。`DomainFlags` 存 `WaveEnemyTag` 的 int 值。

### 7.6 随机武器奖励池

资产：`Assets/GameContent/Catalog/Pools/Weapon Reward Pool.asset`

内容类型：`WeaponDataSO`

运行时入口：`AddRandomWeaponCard`

武器奖励使用内容系统历史记录 pick，避免与升级模块私有状态耦合。

## 8. 程序接入示例

### 8.1 从已有池抽取

```csharp
ContentHistoryScope scope = new(ContentPoolPurpose.Shop, pool.name, player.name);
ContentRollContext context = new(
    ContentPoolPurpose.Shop,
    player: player,
    progressionSnapshot: RunProgressionRuntime.CurrentSnapshot,
    historyScope: scope,
    history: shopHistory,
    shopRefreshCount: refreshCount,
    shopRerollCount: rerollCount);

ContentRollResult result = contentPoolRollService.Roll(
    pool,
    context,
    entryFilter: entry => entry.Content is WeaponDataSO || entry.Content is AccessoryDataSO);
```

### 8.2 玩家确认后记录 Pick

```csharp
ContentRollItem selected = result.Items[index];
shopHistory.RecordPick(scope, selected);
```

只在玩家购买、领取或确认选择后记录 pick。刷新或展示不应记录 pick。

### 8.3 新增自定义条件

```csharp
[System.Serializable]
public sealed class MyContentCondition : ContentCondition
{
    public override bool IsSatisfied(ContentPoolEvaluationContext context, ContentPoolEntry entry)
    {
        return context.CurrentWaveNumber >= 5;
    }
}
```

新增条件应直接读取 `ContentPoolEvaluationContext` 中明确存在的变量。需要新的上下文变量时，先评估它是否属于内容抽取的核心输入，再扩展 `ContentRollContext`。

### 8.4 新增自定义权重规则

```csharp
[System.Serializable]
public sealed class MyWeightRule : ContentWeightRule
{
    public override float ModifyWeight(
        float currentWeight,
        ContentPoolEvaluationContext context,
        ContentPoolEntry entry)
    {
        return currentWeight;
    }
}
```

规则只返回新权重，不应执行结果逻辑。

## 9. 常见排查

### 9.1 抽不到任何结果

检查：

- Pool 是否为空。
- Entry 的 `Content` 是否为空。
- `BaseWeight` 是否为 0。
- 所有候选是否都被 Conditions 过滤。
- Modifier 是否把候选权重降到 0。
- `MaxRollCount` 或 `MaxPickCount` 是否已经达到上限。
- 业务 `entryFilter` 是否过滤掉了所有候选。

### 9.2 权重看起来不生效

检查：

- 候选是否先被条件过滤。
- 当前抽取是否传入了规则需要的上下文变量。
- 是否使用了正确的 `ContentHistoryScope`。
- Modifier 是否安装且 `targetPurpose` 匹配。
- 多个 Modifier 或 WeightRule 是否互相抵消。

### 9.3 MaxPickCount 不生效

检查：

- 玩家确认选择后是否调用了 `ContentHistoryState.RecordPick(scope, item)`。
- Roll 和 Pick 是否使用同一个 `ContentHistoryScope`。
- EntryId 是否稳定。

### 9.4 刷怪池候选不出现

检查：

- Entry 是否绑定 `EnemySO` 或 `WaveSpawnPackSO`。
- 当前上下文的 `CurrentWaveNumber`、`WaveTrackId`、`WaveProgressPercent` 是否匹配条件。
- `WaveSpawnPackSO` 是否至少包含一个有效条目。
- `DomainFlags` 是否误填。
- `WaveManager` 是否能从 Catalog 读取 `WaveSpawnPool`。

## 10. 维护约束

- 不在通用内容池里写购买、装备、应用升级、生成敌人、发放掉落等业务逻辑。
- 不在业务代码中重新实现随机权重。
- 不保留旧抽取表、旧标签映射或旧运行态适配层。
- 新增业务池先扩展 `ContentPoolPurpose`，再在 Catalog 中加显式字段和校验。
- 新增规则优先新增 `ContentCondition`、`ContentWeightRule` 或 `IContentPoolModifier` 实现，不改 `ContentPoolRollService` 主流程。
- 每次内容迁移后运行编译、关键内容池测试和残留扫描。
