# 统一内容池系统使用指南

## 1. 当前目标

内容池系统负责“从候选内容中按条件、权重、历史和 Modifier 抽出结果”。购买、装备、应用升级、生成敌人、发放掉落等业务行为仍由各自系统执行。

当前项目采用并行 V2 架构：

- V2 抽取内核：只处理候选、权重、随机、去重、互斥、历史记录。
- 业务适配层：把玩家、波次、商店、掉落、奖励等事实转换成抽取请求，并解释结果 metadata。
- Legacy 兼容层：继续支持现有 `ContentPoolSO` 资产、`ContentCondition` 和 `ContentWeightRule`。

现阶段不删除旧资产和旧类型。业务调用方应优先使用 V2 领域适配服务，不再直接创建 `ContentPoolRollService` 或自行持有 `ContentHistoryState`。

## 2. 核心类型

V2 核心类型：

- `ContentPoolProfileSO`：V2 池资产，包含 `PoolId`、`ContentPoolKind`、默认抽取数量、重复策略和条目。
- `ContentPoolEntryDefinition`：V2 条目定义，包含内容引用、基础权重、次数限制、互斥条目和 metadata。
- `ContentRollScope`：历史隔离键，由 `scopeId`、`poolId`、`ownerId` 组成。
- `ContentFactSet`：业务事实容器。V2 内核不直接依赖玩家、组件或场景对象。
- `ContentRollRequest`：一次抽取请求，显式携带条目、scope、历史、事实、随机源和过滤器。
- `ContentPoolServiceV2`：V2 抽取服务。
- `RunContentHistory`：单局共享内容历史，内部包装 `ContentHistoryState`。
- `ContentPoolLibrarySO`：Catalog 的 V2 池索引，按 `ContentPoolKind` 查找 V2 profile。

Legacy 兼容类型：

- `LegacyContentPoolAdapter`：把现有 `ContentPoolSO` 和旧 `ContentRollContext` 转成 V2 request。
- `LegacyGlobalContentModifierSource`：把现有 `ContentPoolModifierRegistry` 暂时接入 V2 service。

## 3. 历史生命周期

内容历史采用“局内共享 + scope 隔离”。

`GameManager` 从非商店状态进入 `Game` 时调用 `RunContentHistoryRuntime.BeginRun()`，创建一局新的历史。商店继续下一波不会重置历史。

| 业务 | scopeId | poolId | ownerId | 说明 |
| --- | --- | --- | --- | --- |
| 升级卡 | `upgrade_card` | 池资产名 | 玩家实例 ID | 记录升级卡 offer、pick、标签 pick 统计 |
| 宝箱奖励 | `chest_reward` | 池资产名 | 玩家实例 ID | 与升级卡共用单局历史对象，但 scope 独立 |
| 商店 | `shop` | 池资产名 | 玩家实例 ID | 商品购买后记录 pick；刷新只记录 offer |
| 掉落 | `drop` | 池资产名 | 空 | 掉落池按局共享，不按玩家隔离 |
| 刷怪 | `wave_spawn` | 池资产名 | 空 | 刷怪候选按局共享历史 |
| 武器奖励 | `weapon_reward` | 池资产名 | 玩家实例 ID | 随机武器奖励独立 scope |

新增业务池时先确定 `ContentPoolKind` 和 scope 规则，再接入 `RunContentHistoryRuntime.Current`。不要在业务 Manager 内部 `new ContentHistoryState()`。

## 4. 业务接入

业务层应使用领域适配服务：

- `ShopContentRoller`
- `RewardContentRoller`
- `DropContentRoller`
- `WaveSpawnContentSelector`

示例：

```csharp
ContentRollItem item = shopContentRoller.RollItem(
    shopPool,
    player,
    shopRefreshCount,
    totalRerollCount,
    RunContentHistoryRuntime.Current);

shopContentRoller.RecordPick(
    shopPool,
    player,
    RunContentHistoryRuntime.Current,
    item);
```

适配服务负责：

- 创建 `ContentRollScope`。
- 构造旧资产兼容用的 `ContentRollContext`。
- 构造 V2 `ContentFactSet`。
- 调用 `ContentPoolServiceV2`。
- 把 `ContentRollSelection` 转回当前 UI 和业务仍在使用的 `ContentRollItem`。

## 5. V2 Profile 与 Legacy 资产

现有运行时仍可消费旧 `ContentPoolSO`。旧池通过 `LegacyContentPoolAdapter` 转成 V2 请求，旧条件和旧权重规则只在兼容层执行。

新增内容池建议创建 `ContentPoolProfileSO`，并在 `ContentPoolLibrarySO` 中按 `ContentPoolKind` 绑定。迁移旧池时使用菜单：

```text
Tools/Survivors/Content Pools/Create V2 Profiles From Selected Legacy Pools
```

该工具会把选中的旧池复制为旁路 V2 profile，默认输出到旧池目录旁的 `PoolsV2` 子目录，并打印迁移报告。它不会删除或覆盖旧池资产。

## 6. 维护约束

- 不在 V2 内核中访问 `Player`、`Entity`、`GameObject`、`PropertiesManager`、`WeaponsHolder` 或 `RunProgressionRuntime`。
- 不在内容池内核中写购买、装备、应用升级、生成敌人、发放掉落等业务行为。
- 不让业务 Manager 直接持有内容历史；统一通过 `RunContentHistoryRuntime.Current`。
- 不直接删除旧 `ContentPoolSO`、旧条件、旧权重规则或旧 metadata 类型；删除必须等迁移扫描和测试通过后单独执行。
- 新增规则优先放在业务适配层或 V2 fact 规则中，避免继续扩张旧 `ContentCondition.cs`。

## 7. 验证

关键验证项：

- V2 权重抽取、重复策略、互斥、次数限制行为正确。
- 同一局内共享 `RunContentHistory`，不同 scope 不互相污染。
- 旧 `ContentPoolSO` 经 `LegacyContentPoolAdapter` 的简单抽取结果与旧服务一致。
- 商店、奖励、掉落、刷怪调用方不再各自 `new ContentHistoryState()`。
- 编译通过，Unity EditMode 内容池测试通过。
