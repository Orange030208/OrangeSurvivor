# 游戏开发专项规则

## 数值规范职责边界

- 玩法数值的总口径、属性单位、百分比点口径、预算模型、经济、经验、掉落、武器、Buff、角色与敌人数值规范统一维护在 `数值设计/玩法数值规范.md`。
- 升级卡与饰品的专属设计规则分别维护在 `数值设计/升级卡设计规范.md` 和 `数值设计/饰品设计规范.md`。
- 本文件只维护游戏开发过程中的行为职责、组件边界、状态流程与配置职责，不再承载具体数值口径、预算表、公式或投放建议。
- 设计或修改角色属性、武器属性、升级卡、饰品、Buff、敌人属性、商店经济、经验收益、掉落收益等玩法数值前，应先查看 `数值设计/玩法数值规范.md`；涉及升级卡或饰品专属规则时，再分别查看对应独立文档。

## 敌人设计

### 攻击范围职责

- 敌人默认由对应 Brain 持续追踪或站位，不再维护独立检测范围属性。
- `AttackRange` 是敌人范围判定的唯一基础属性，同时用于攻击入场、近战命中区域、范围查询半径、投射物最大飞行距离等距离相关行为。
- 攻击入场可以叠加攻击自身的显式范围倍率，但倍率必须和攻击提交后的实际覆盖保持一致，避免能远距离开火但弹体或命中区域覆盖不到目标。
- Boss 远程投射物需要同时校准释放距离和弹体最大飞行距离。`GolemMechaStoneBossSO.ShootRangeMultiplier` 必须同时作用于射击入场检测和投射物 `maxTravelDistance`。

### 攻击点位职责

- 敌人的近战点、射击点、激光点等攻击点位属于具体 Brain 与 Prefab 的显式依赖，应在对应 Brain 上声明 `Transform` 字段，由 Prefab 子物体拖引用。
- `EnemyAttackController` 不持有统一射击点；它只负责普通攻击槽、技能槽、攻击层与投射物发射等通用攻击控制职责。
- 攻击策略需要空间点位时，由 Brain 构造策略时直接传入对应 `Transform`；不要为点位再引入 `AttackConfig` 等包装结构，也不要把点位配置放进敌人 SO。
- 近战实际伤害区域默认是以近战点位为圆心、以 `AttackRange` 及攻击自身范围倍率为半径的圆形区域；不要再通过前向偏移类策略模拟攻击点。

### 普通攻击槽与技能槽

- 敌人攻击冷却必须区分普通攻击槽与技能槽：普通攻击槽用于近战、远程等基础攻击；技能槽用于激光、护盾、阶段技等显式技能。
- 普通攻击槽用于受通用攻速属性调节的常规攻击；技能槽使用技能自身的显式冷却。具体攻速单位、收益系数、冷却公式和数值投放口径维护在 `数值设计/玩法数值规范.md`。
- 普通攻击槽应在策略初始化时注册，并在 `AttributeManager` 的 `AttackSpeed` 变化事件中刷新间隔；禁止在每帧攻击判定中反复读取攻速。
- 普通攻击默认通过敌人基础攻击属性作为伤害入口，不在敌人 SO 上再配置通用 `damageMultiplier`、`cooldown`、`actionId` 或攻击音效包装。
- 普通攻击的 `actionId` 应作为代码常量写在对应敌人类型或行为代码中；攻击音效在具体攻击执行代码中播放，不作为敌人 SO 攻击配置。

### 攻击状态入场与提交

- 近战或远程普通攻击的范围检测首先用于“是否允许进入攻击状态/下达攻击指令”；一旦攻击状态已经入场，应播放完整攻击动画。
- 攻击提交点不得因为目标离开释放判定范围而取消动作或跳出状态；远程投射物仍应按提交时方向发出并消耗冷却。
- 攻击状态中目标临时离开范围时，敌人应停止移动并完成当前攻击动画；动画完成后再根据目标位置、冷却与优先级选择 Idle、追击、远程或其他技能状态。
- 近战、命中盒、范围扫掠或持续伤害区域等攻击，伤害结算必须按提交时的实际攻击区域查询可伤害目标；区域内没有合法目标时应表现为空挥，但动画、攻击挥出特效、音效与普通攻击冷却仍正常提交。

### 运行时属性修改

- 敌人运行时临时修改攻击范围、移动速度、攻击力、攻速等基础属性时，统一使用 `PropModifierData` 与 `AttributeManager.AddModifiers/RemoveModifiers`。具体单位、倍率写法和数值限制维护在 `数值设计/玩法数值规范.md`。
- 不要在具体敌人行为脚本里直接改写基础属性、缓存属性结果，或额外传入临时倍率参数绕过属性系统。
- 可调的临时属性变化应放在敌人 ScriptableObject 中，例如 `List<PropModifierData>`，保持 Inspector 可配置、可调试、可复用。
- 临时属性修改必须使用稳定的 `sourceId`，状态进入时添加，状态退出时移除。
- `StopBrain`、`StartBrain`、`OnDisableComponent` 等中断入口必须清理可能残留的 Modifier。
- 同一状态可能重复进入或中断重入时，应避免重复 Add，并保证 Remove 幂等。

#### 例外

- 动画播放速度、状态计时、命中特效、Hit Shape 选择等不属于基础属性结算的数据，可以保留在行为状态或攻击定义中。
- 如果现有属性系统无法表达需求，应优先评估补充 `PropType`、`PropModifierType` 或属性结算扩展，而不是在具体玩法脚本中写死临时分支。
