# 局内推进系统设计与使用说明

本文档记录当前项目中“随着游戏进度改变难度、经济、商店和内容池条件”的统一设计。它描述的是已经落地的运行时系统口径，不是未来规划草案。

## 1. 目标

局内推进系统用于解决两个问题：

- 玩家会随局内发育变强，敌人不能只增加数量而不增加质量和数值。
- 怪物数量增加后，商店价格、内容开放和刷怪质量需要同步推进，避免后期只靠数量堆压迫。

当前目标体验是 20 波固定关卡内逐步加压，15-20 波进入构筑校验和崩盘压力区；21 波以后按同一套曲线进入无尽扩展。

核心原则：

- 不做按玩家 DPS 实时追平的橡皮筋难度。
- 金币和经验暂时不参与局内推进系统，当前金币掉落固定为 `1金币`，普通怪击杀基础经验固定为 `1经验`。
- 敌人缩放只作用于运行时属性修饰，不修改 `EnemySO` 或基础属性资产。
- 商店通过局内价格倍率和刷新成本消耗经济增量。

## 3. 运行时数据流

1. `WaveManager.Awake` 从 `GameContentRuntime.Provider.RunProgressionProfile` 读取配置，创建 `RunProgressionService`。
2. `WaveManager` 调用 `RunProgressionRuntime.SetProvider`，让全局运行时查询可以读取当前快照。
3. 每波开始时，`WaveManager.StartWave` 调用 `BeginWave` 更新当前波次快照。
4. 每帧推进时，`WaveManager.Update` 调用 `runProgressionService.Tick(Time.deltaTime)`。
5. 刷怪时，`WaveSpawnExecutionService` 把当前 `RunProgressionSnapshot` 传给 `EnemyFactory`。
6. `EnemyFactory` 根据快照计算敌人运行时倍率，并通过 `Enemy.Configure` 注入初始属性修饰。
7. `AttributeManager.InitializeAttributes` 初始化敌人基础属性后，调用 `Enemy.ApplyInitialProgressionModifiers` 应用推进修饰。
8. 敌人死亡时，`DropManager` 直接给击杀来源结算基础经验，并按固定 `CoinRewardData(1)` 配置金币掉落；二者都不读取推进系数。
9. 商店生成和显示时，`ShopManager` 读取 `RunProgressionRuntime.CurrentSnapshot.ShopPriceMultiplier` 计算商品与刷新价格。
10. 内容池条件和权重通过 `ContentRollContext.ProgressionSnapshot` 读取推进快照。

## 4. 快照字段

`RunProgressionSnapshot` 是运行时只读结果，当前字段如下：

| 字段 | 含义 | 主要使用者 |
| --- | --- | --- |
| `WaveNumber` | 当前波次，从 1 开始 | 刷怪、掉落、商店、内容池 |
| `TotalWaves` | 当前关卡配置波数 | 无尽判断、归一化进度 |
| `RunMinutes` | 局内运行分钟数 | 预留给后续按时间规则 |
| `EndlessLoop` | 无尽整数轮次，20 波配置下 21-40 波为第 1 轮 | 内容池条件、危险层级 |
| `DifficultyCoefficient` | 难度系数 | 敌人属性缩放、内容池权重 |
| `EconomyCoefficient` | 经济系数 | 当前仅作为内容池事实和未来扩展预留，不影响金币或击杀经验 |
| `ShopPriceMultiplier` | 商店价格倍率 | 商品价格、刷新价格 |
| `DangerTier` | 危险段位 | 内容池条件、后续 UI 或刷怪权重 |

## 5. 默认数值曲线

当前 `authoredWaveCount` 为 20。20 波内使用归一化波次曲线，默认关键点如下：

| 波次 | 难度系数 | 经济系数 | 商店价格倍率 | 体验定位 |
| ---: | ---: | ---: | ---: | --- |
| 1 | 1.00 | 1.00 | 1.00 | 起步期 |
| 5 | 1.25 | 1.12 | 1.15 | 轻压 |
| 10 | 1.75 | 1.35 | 1.45 | 中压 |
| 15 | 2.55 | 1.65 | 1.85 | 构筑校验 |
| 20 | 3.60 | 2.05 | 2.30 | 崩盘压力 |

注意：表格是设计锚点。实际曲线通过 `AnimationCurve` 评估，非锚点波次会按曲线插值得到结果。

## 6. 无尽扩展

21 波后沿用第 20 波的曲线终点，再按无尽进度连续指数增长。

```text
endlessProgress = (当前波次 - authoredWaveCount) / authoredWaveCount
难度系数 *= endlessDifficultyMultiplierPerLoop ^ endlessProgress
经济系数 *= endlessEconomyMultiplierPerLoop ^ endlessProgress
商店价格倍率 *= endlessShopPriceMultiplierPerLoop ^ endlessProgress
```

当前默认倍率：

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| `endlessDifficultyMultiplierPerLoop` | 1.18 | 每完整 20 波，无尽难度额外乘 1.18 |
| `endlessEconomyMultiplierPerLoop` | 1.10 | 每完整 20 波，无尽经济额外乘 1.10 |
| `endlessShopPriceMultiplierPerLoop` | 1.16 | 每完整 20 波，无尽商店价格额外乘 1.16 |

`EndlessLoop` 仍是整数轮次，方便内容池写“第几轮无尽后开放”的条件。倍率本身按 `endlessProgress` 连续增长，避免同一轮内压力不变。

## 7. 敌人影响范围

敌人数值缩放入口是 `RunProgressionProfileSO.EvaluateEnemyScale`。

配置入口在：

```text
Assets/GameContent/RunProgression/Run Progression Profile.asset
```

当前敌人压力分三层：

- `enemyPropScaleCurves`：基础敌人属性曲线，可新增任意 `PropType`。
- `bossPropMultipliers`：Boss 额外属性倍率，可新增任意 `PropType`。
- `tagPressureRules`：刷怪标签额外压力，可按 `WaveEnemyTag` 配置任意 `PropType` 倍率。

`enemyPropScaleCurves` 的每一项由 `propType` 和 `multiplierByDifficulty` 组成。曲线横轴是 `DifficultyCoefficient`，纵轴是该属性最终倍率。默认保留现有四项：

```text
PropType.MaxHealth
PropType.Attack
PropType.MoveSpeed
PropType.AttackSpeed
```

默认基础倍率曲线：

| 难度系数 | 生命倍率 | 攻击倍率 | 移速倍率 | 攻速倍率 |
| ---: | ---: | ---: | ---: | ---: |
| 1.00 | 1.00 | 1.00 | 1.00 | 1.00 |
| 1.25 | 1.20 | 1.10 | 约 1.01 | 约 1.03 |
| 1.75 | 1.65 | 1.32 | 1.04 | 1.08 |
| 2.55 | 2.45 | 1.68 | 1.08 | 1.16 |
| 3.60 | 3.70 | 2.10 | 1.12 | 1.25 |

新增属性曲线示例：

```text
propType = Armor
multiplierByDifficulty: 1.00 -> 1.30
```

表示敌人护甲会随难度系数提高，并在生成时转成 `PropType.Armor` 的 `FinalMultiplier`。基础曲线中同一个 `PropType` 不建议重复配置；如果重复，后面的条目覆盖前面的基础倍率。

Boss 额外倍率通过 `bossPropMultipliers` 配置，只在 `EnemySO.role == EnemyRole.Boss` 时生效。默认配置：

| PropType | 默认额外倍率 |
| --- | ---: |
| `MaxHealth` | 1.35 |
| `Attack` | 1.15 |

Boss 额外倍率会乘在基础曲线结果之后。例如 20 波默认生命倍率是 `3.70`，Boss 生命最终倍率是：

```text
3.70 * 1.35 = 4.995
```

刷怪标签额外压力通过 `tagPressureRules` 配置。默认规则：

| 标签 | 影响 |
| --- | --- |
| `Elite` | 生命再乘 1.18，攻击再乘 1.12 |
| `BossLike` | 生命再乘 1.25，攻击再乘 1.10 |
| `Ranged` | 攻击再乘 1.05 |
| `Fast` | 移速再乘 1.08 |

标签来自刷怪内容池条目的 `DomainFlags`，由 `WaveSpawnExecutionService` 转成 `WaveEnemyTag` 后传给 `EnemyFactory`。一个敌人可同时拥有多个标签，匹配到的规则会继续相乘。

最终通过 `RunProgressionEnemyScaling.BuildModifiers` 转成 `PropModifierData`，统一使用 `FinalMultiplier` 作用于对应 `PropType`：

```text
EnemySO 基础属性
* enemyPropScaleCurves[prop]
* bossPropMultipliers[prop]（仅 Boss）
* tagPressureRules[tag][prop]
```

这套链路只改运行时生成敌人的属性修饰，不回写 `EnemySO`、基础属性组或 Prefab。

## 8. 金币与经验边界

金币和击杀经验当前不参与局内推进系统，也不根据波次、难度系数、经济系数、敌人标签或敌人缩放做变化。

当前固定口径：

| 参数 | 默认值 |
| --- | ---: |
| 每个金币掉落提供金币 | 1 |
| 普通怪击杀基础经验 | 1 |

重要约束：

- 不要把金币和击杀经验接回 `DifficultyCoefficient`、`EconomyCoefficient`、`DangerTier` 或敌人标签。
- 金币掉落数量仍由掉落池和击杀数量决定；每个实际掉出的 `Coin` 固定提供 `1金币`。
- 经验由敌人死亡事件直接结算到击杀来源，不再通过金币拾取物发放。
- 如果后续要重新设计经济成长，应单独立项，不混入当前敌人难度推进链路。

## 9. 商店影响范围

商店价格由 `ShopPricingService` 统一计算。

商品价格公式：

```text
商品价格 = 基础价或武器等级价
       * 局内商店价格倍率
       * 玩家折扣倍率
```

刷新价格公式：

```text
刷新价格 = 当前刷新基础价格 * 局内商店价格倍率
```

玩家折扣来自 `PropType.ShopPriceDiscount`，最终价格倍率下限由 `PropValueUtility.MIN_EFFECTIVE_SHOP_PRICE_MULTIPLIER` 控制，当前口径是最低 50%。

锁定商品会保留 `ItemData`、等级；进入下一波或状态刷新显示时，会重新套用当前波次的局内价格倍率和玩家折扣倍率。

## 10. 内容池上下文变量

内容池通过 `ContentRollContext` 输入 `RunProgressionSnapshot`，条件策略和权重规则可直接读取以下推进变量：

| 变量 | 类型 | 含义 |
| --- | --- | --- |
| `RunProgressionValue.DifficultyCoefficient` | Float | 当前难度系数 |
| `RunProgressionValue.EconomyCoefficient` | Float | 当前经济系数，当前不影响金币或击杀经验 |
| `RunProgressionValue.ShopPriceMultiplier` | Float | 当前商店价格倍率 |
| `RunProgressionValue.EndlessLoop` | Int | 当前无尽整数轮次 |
| `RunProgressionSnapshot.IsEndlessWave` | Bool | 是否无尽波。若需要条件化使用，应新增明确的条件策略。 |
| `RunProgressionValue.DangerTier` | Int | 危险段位 |

使用场景：

- 商店池：高波次开放高品质商品，提高高等级武器权重。
- 掉落池：高危险层级可以提高稀有掉落权重，但不要改变金币单个掉落数值或普通怪击杀基础经验。
- 刷怪池：高难度系数或危险层级提高精英、远程、快速、特殊包权重。
- 无尽模式：用 `endless_wave` 或 `endless_loop` 控制无尽专属内容。

## 11. 如何调参

常用调参入口是：

```text
Assets/GameContent/RunProgression/Run Progression Profile.asset
```

推荐调参顺序：

1. 先调 `difficultyByWave`，确认第 10、15、20 波压力节奏。
2. 再调 `enemyPropScaleCurves`。普通怪优先调 `MaxHealth` 和 `Attack`，谨慎提高 `MoveSpeed`、`AttackSpeed`，需要时再新增 `Armor`、`DamageReduction`、`AttackRange` 等属性曲线。
3. 再调 `bossPropMultipliers` 和 `tagPressureRules`。Boss、精英、远程、快速包应该承担更明显的后期压迫，不要把所有压力都堆到普通怪血量。
4. 再调 `shopPriceMultiplierByWave`，让后期购买力增长但不过度淹没战斗压力。
5. `economyByWave` 当前只作为内容池事实和未来扩展预留；不要用它调金币或击杀经验。
6. 无尽模式只调三个 `endless...PerLoop` 参数，避免破坏 1-20 波体验。

建议先不要把 `economyByWave` 接入运行时经济收益，避免再次把金币和击杀经验混进推进系统。

## 12. 如何接入新系统

新系统需要读取当前推进状态时，优先使用：

```csharp
RunProgressionSnapshot snapshot = RunProgressionRuntime.CurrentSnapshot;
```

如果系统已经由 `WaveManager` 或刷怪流程传入上下文，优先使用上下文中的快照，避免在测试中依赖全局状态。

新增内容池规则时，优先通过 `ContentRollContext` / `ContentPoolEvaluationContext` 读取推进快照，而不是在内容池规则里直接访问 `WaveManager`。

新增敌人压力规则时，优先扩展：

```text
RunProgressionProfileSO
RunProgressionEnemyScaling
WaveEnemyTag
```

新增商店价格规则时，优先扩展：

```text
ShopPricingService
RunProgressionSnapshot.ShopPriceMultiplier
PropType.ShopPriceDiscount
```

## 13. 测试与验收

相关测试文件：

```text
Assets/Tests/Editor/RunProgressionTests.cs
```

当前覆盖点：

- 默认推进曲线单调递增且有限。
- 无尽第 25、40 波继续增长。
- 金币掉落保持固定 `1金币`，普通怪击杀基础经验保持固定 `1经验`。
- 商店价格正确叠加等级、内容池倍率、局内倍率和玩家折扣。
- 敌人运行时倍率随难度提高，且不修改敌人资产。
- 敌人基础曲线支持新增任意 `PropType`。
- Boss 和刷怪标签可以通过配置追加任意属性倍率。
- 内容池条件能读取推进快照上下文。

调整曲线后至少验证：

- 第 1、5、10、15、20 波倍率符合预期。
- 新增 `PropType` 曲线能在生成敌人时变成对应 `FinalMultiplier`。
- Boss 与标签压力叠加后符合预期，不污染敌人资产。
- 第 25、30、40 波没有负数、无穷或停滞。
- 锁定商店商品跨波后显示价格会按当前波次重算。
- 高频击杀场景下，每个金币掉落仍固定为 `1金币`，经验仍由击杀事件直接结算。

## 14. 当前边界

当前版本不包含：

- 按玩家 DPS、受伤次数或经济状态实时追平的动态难度。
- 金币或击杀经验随波次、难度、标签变化。
- 自动根据玩家购买力回调商店价格。
- 对已生成敌人进行中途重新缩放。

这些能力如果后续要做，应单独设计，并优先保持“玩家构筑收益不被抹平”的体验边界。
