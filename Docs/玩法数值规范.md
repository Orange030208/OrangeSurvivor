# 玩法数值规范

本文档是项目后续设计角色、武器、敌人、经济、经验和掉落时的独立数值口径文档。

本文档只规定数值目标、单位、公式、预算和填表口径；工程字段、结算入口和落地方式见 `数值系统落地规范.md`。

## 1. 通用单位口径

### 1.1 百分比点

所有可配置的百分比数值统一使用百分比点：

- `1` 表示 `1%`
- `10` 表示 `10%`
- `50` 表示 `50%`

禁止在数值表中写 `0.01` 表示 `1%`，也禁止写 `0.5` 表示 `50%`。需要换算为比例时，统一按 `value / 100` 处理。

### 1.2 距离点

距离相关属性统一使用距离点：

- `100` 表示 `1` 格距离，也等价于 Unity 世界空间中的 `1` 个距离单位。
- `MoveSpeed 100` 表示每秒移动 `1` 格。
- `AttackRange 100` 表示攻击范围 `1` 格。
- `PickupRadius 100` 表示拾取半径 `1` 格。

数值表中不再直接写 `1` 表示 `1` 格距离。需要换算为实际距离或速度时，统一按 `value / 100` 处理。

### 1.3 攻速点

攻击速度统一使用攻速点：

- `100` 表示每秒攻击 `1` 次。
- `120` 表示每秒攻击 `1.2` 次。
- `50` 表示每 `2` 秒攻击 `1` 次。

数值表中不再直接写 `1` 表示每秒攻击 `1` 次。需要换算为每秒攻击次数或攻击间隔时，统一使用攻速点口径；最低有效攻速见属性单位表。

### 1.4 乘区

`BaseMultiplier`、`BonusMultiplier`、`FinalMultiplier` 也使用百分比点：

- `value: 50` 表示乘以 `1.5`
- `value: -10` 表示乘以 `0.9`

属性由五个区构成：

- 基础区：角色、敌人或其他属性提供方配置的基础属性，进入 `base`。
- 加成区：升级卡、饰品、临时效果等获得属性，进入 `Add`。
- 基础乘区：`BaseMultiplier`，只乘基础区。
- 加成乘区：`BonusMultiplier`，作用于基础区经过基础乘区后的值与加成区之和。
- 最终乘区：`FinalMultiplier`，作用于前面全部结果。

属性最终值按下面顺序计算：

```text
baseAfterBaseMultiplier = base * (1 + BaseMultiplier)
result = (baseAfterBaseMultiplier + Add) * (1 + BonusMultiplier)
final = result * (1 + FinalMultiplier)
```

乘区数值必须谨慎配置，尤其是 `BonusMultiplier` 和 `FinalMultiplier`。默认按下面分级使用：

| 使用等级 | 推荐表达 | 单来源常规上限 | 同属性常驻总量建议 | 适用场景 |
| --- | --- | ---: | ---: | --- |
| 普通奖励 | `Add` | - | - | 升级卡、普通饰品、武器等级常规数值、无条件永久成长。 |
| 构筑核心 | `BonusMultiplier` | `10%-15%` | `30%` 内 | 明确流派核心、需要组合条件、持续时间有限或有覆盖率限制的效果。 |
| 终局/代价效果 | `FinalMultiplier` | `5%-10%` | `15%-20%` 内 | 终局稀有效果、强条件效果、带明显负面代价或短窗口爆发。 |

乘区风险规则：

- 普通奖励只使用 `Add`，不要为了显示更强把普通数值奖励写成乘区。
- `BaseMultiplier` 只用于少量改变基础区定位的效果，不作为常规奖励投放。
- `BonusMultiplier` 会放大基础区、基础乘区和加成区的合计结果；超过单来源 `15%`，必须写明条件、覆盖率和叠加上限。
- `FinalMultiplier` 位于结算末端，会放大前面所有属性、武器收益率、类型攻击贡献和其他乘区；常驻单来源超过 `10%` 或同属性常驻总量超过 `20%`，必须有终局定位、明显代价或严格触发窗口。
- 同一来源不要同时给多个乘区；不同来源叠加乘区前，必须先按预期覆盖率和最大叠加层数核算理论上限。
- 乘区类效果需要在配置说明中写明来源、覆盖率、持续时间、触发条件和预期上限，避免后续叠加时无法追踪强度来源。

属性来源只累计真实数值，不在来源处截断。所有有效边界，包括下限、上限、取整、百分比点换算、攻速点换算、距离点换算、价格折扣和概率有效范围，都必须使用统一口径；同一属性不能在不同模块各自定义不同边界。

### 1.5 Add 的单位

`Add` 的单位取决于属性语义：

- `CriticalChance +6` 是暴击率 `+6%`
- `ExperienceGain +12` 是经验获取 `+12%`
- `AttackSpeed +5` 是攻击速度增加 `5` 攻速点
- `MoveSpeed +16` 是移动速度 `+16` 距离点/秒
- `PickupRadius +100` 是拾取半径增加 `1` 格
- `HealthRecoverySpeed +10` 是每秒恢复 `+1` 点生命
- `Attack Add +1` 是固定攻击点，不是全局 DPS `+1`；玩家通用词条不要使用该写法，应使用 `Damage` 百分比属性。
- `Damage +10` 是最终伤害提升 `+10%`；`100` 表示最终伤害提升一倍。
- `MeleeAttack +10` 等四类攻击属性是类型攻击池点数，不是百分比乘区；只有武器上的对应收益率按百分比点换算。

## 2. 价值定义

`价值` 是项目内部数值预算单位，用 `BP`（Budget Point）表示。它用于横向比较不同属性的强度成本，不是游戏内金币、伤害、概率、权重或 UI 显示值。

基础锚点：

```text
100 BP = 一条标准普通主属性档
```

`价值/点` 表示每增加 1 个配置单位需要消耗的 BP：

```text
属性预算 = 属性变化量 * 价值/点
```

例如：

```text
Damage +5% = 5 * 20 = 100 BP
AttackSpeed +5 = 5 * 20 = 100 BP
MaxHealth +20 = 20 * 5 = 100 BP
Armor +1 = 1 * 80 = 80 BP
CriticalChance +2% = 2 * 50 = 100 BP
Dodge +3% = 3 * 33 = 99 BP
```

### 2.1 金币购买力

金币购买力用于估算商店价格和强度预算的关系，不表示金币本身是属性价值。

```text
1 金币 = 4 BP
参考价格 = 基础价值 / 4
```

商店价格可以围绕参考价格上下浮动。稀有度、可选择性、机制强度、负面代价、刷新成本和获取入口都会影响最终定价。

### 2.2 机制价值表

机制价值只记录当前已经存在的特殊机制，不提前为未实现机制预留预算。新增机制进入项目后，再补进本表。

属性型机制：

| 机制 | 基准 BP | 说明 |
| --- | ---: | --- |
| `ProjectilePierceCount +1` | 200 | 增加 1 次弹射物穿透。价值取决于弹道宽度、敌人密度和单发伤害。 |
| `WeaponSlotCount +1` | 400 | 增加 1 个武器槽。属于构筑容量机制，应谨慎投放。 |

特殊 Feature 机制：

| 机制 | 推荐 BP | 说明 |
| --- | ---: | --- |
| 武器收益率加成 | 按下表逐项累加 | 会放大后续升级卡、饰品和持有者属性，不能只按当前裸面板计价。 |
| 强制暴击 | `4000 * 覆盖率 * 暴击倍率修正 * 未暴击概率修正` | 基准按 `80% * 100 * CriticalChance 每点价值 50 BP = 4000 BP` 计算。 |

武器收益率加成按每 `+1` 收益率点计价。下表默认按外部属性预期为 `100` 点、影响一把主力武器估算；实际填表时可以按 `外部属性预期 / 100` 缩放。如果收益率加成由持有者或全局 Feature 提供，并且会影响多把武器，应再按受影响武器的输出占比或有效武器数量折算。

```text
收益率加成 BP = 收益率增加点数 * 每点收益率 BP * 外部属性预期 / 100 * 受影响武器系数
```

| 收益率字段 | 每 `+1` 收益率点 BP | 计算依据 |
| --- | ---: | --- |
| `AttackSpeedBenefitPercent` | 20 | 标准外部 `AttackSpeed +100` 时，`+1` 收益率点约等于多吃 `AttackSpeed +1`。 |
| `CriticalChanceBenefitPercent` | 50 | 标准外部 `CriticalChance +100` 时，`+1` 收益率点约等于多吃 `CriticalChance +1%`。 |
| `CriticalPercentBenefitPercent` | 12 | 标准外部 `CriticalPercent +100` 时，`+1` 收益率点约等于多吃 `CriticalPercent +1%`。这是后期暴击成型后的收益率价值，前期无暴击入口或低暴击率时应明显折扣。 |
| `RangeBenefitPercent` | 8 | 标准外部 `AttackRange +100` 时，`+1` 收益率点约等于多吃 `AttackRange +1`。 |
| `KnockbackStrengthBenefitPercent` | 5 | 标准外部 `KnockbackStrength +100` 时，`+1` 收益率点约等于多吃 `KnockbackStrength +1`。 |
| `MeleeAttackUsagePercent` | 20 | 标准外部 `MeleeAttack +100` 时，`+1` 收益率点约等于多吃 `MeleeAttack +1`。 |
| `RangedAttackUsagePercent` | 20 | 标准外部 `RangedAttack +100` 时，`+1` 收益率点约等于多吃 `RangedAttack +1`。 |
| `MagicAttackUsagePercent` | 20 | 标准外部 `MagicAttack +100` 时，`+1` 收益率点约等于多吃 `MagicAttack +1`。 |
| `SummonAttackUsagePercent` | 20 | 标准外部 `SummonAttack +100` 时，`+1` 收益率点约等于多吃 `SummonAttack +1`。 |

强制暴击基准假设暴击伤害为 `180%`，也就是暴击额外收益 `80%`。实际计价时使用：

```text
强制暴击 BP = 4000
  * 覆盖率
  * max(0, (实际暴击倍率 - 1) / 0.8)
  * max(0, 1 - 当前有效暴击率)
```

如果强制暴击只影响下一次攻击、低频触发窗口或少量命中段，覆盖率必须按实际命中占比折算；高频武器、范围武器和暴击伤害构筑会显著放大该机制。

机制评估规则：

- 机制 BP 是单件物品或单级成长预算的一部分，不是额外赠送项。
- 如果机制可以重复获得，先判断是否会非线性放大；只有终极强机制或明显质变机制需要唯一性或适量上限。
- 普通属性饰品和明确构筑饰品不因为可重复就自动做价值衰减。

### 2.3 局内推进曲线

局内推进曲线是波次、刷怪、掉落、商店和内容池条件共享的数值上下文，不按玩家实时 DPS 做橡皮筋追平。

默认目标体验是 20 波内逐步加压，后期进入崩盘区间，并兼容 21 波后的无尽扩展：

| 波次 | 难度系数 | 经济系数 | 商店价格倍率 |
| ---: | ---: | ---: | ---: |
| 1 | 1.00 | 1.00 | 1.00 |
| 5 | 1.25 | 1.12 | 1.15 |
| 10 | 1.75 | 1.35 | 1.45 |
| 15 | 2.55 | 1.65 | 1.85 |
| 20 | 3.60 | 2.05 | 2.30 |

21 波后按无尽进度连续指数增长，不等整轮结束再跳变；整数轮次只用于内容池条件和权重规则判断。

敌人缩放只作用于局内实际面板，不改变怪物基础模板。默认缩放属性包含 `MaxHealth`、`Attack`、`MoveSpeed`、`AttackSpeed` 四项。Boss 额外倍率和刷怪标签压力同样按属性配置，默认由 Boss、精英、远程、快速标签承担更明显的后期压迫。

```text
敌人实际属性 = 怪物基础属性 * 敌人缩放倍率
```

商店使用价格消耗池对冲局内进度带来的购买力变化：

```text
商品价格 = 基础价或武器等级价 * 内容池价格倍率 * 局内商店价格倍率 * 玩家折扣倍率
刷新价格 = 基础刷新价格 * 局内商店价格倍率
```

`ShopPriceDiscount` 的最终价格倍率下限为 `50%`。经济类升级卡和饰品需要额外保守，尤其是 `ExperienceGain`、`ShopPriceDiscount`、`WaveGoldRewardBonus`，因为它们会放大后续购买力和升级速度。

#### 2.3.1 关键波次玩家状态目标

关键波次目标用于校验整局节奏，不是硬性约束。实际玩家会因为武器选择、掉落、商店刷新和操作水平上下浮动，但配置武器、敌人、商店和波次时，应优先让普通构筑落在这些范围内。

以下目标按合理的 20 波局内节奏估算，不参考现有临时配置。默认目标是战斗总时长约 `16-18` 分钟，商店在大多数波次后都能形成至少一次购买决策。普通击杀经验为 `1` 点，每次升级给 `1` 张升级卡。表中的金币为累计获得金币，不等于当前背包余额。

推荐波次时长：

| 波次段 | 普通波时长 | 节点波时长 | 说明 |
| --- | ---: | ---: | --- |
| 1-4 | 40 秒 | - | 前期节奏短，快速进入构筑循环。 |
| 5-9 | 45 秒 | 50 秒 | 5 波可作为第一次小压力节点。 |
| 10-14 | 50 秒 | 60 秒 | 10 波开始进入 Boss 或强精英节点，需要更完整的输出检验。 |
| 15-19 | 55 秒 | 65 秒 | 后期给构筑足够时间发挥，同时提高刷怪密度和压力峰值。 |
| 20 | - | 75 秒 | 终局波，允许更长 Boss 与密度压力。 |

该时长是设计目标，不是现有配置必须已经满足的状态。后续配置波次时，应优先按这个节奏反推刷怪数量、掉落总量、经验总量和商店经济。

| 完成波次 | 玩家等级 | 升级卡数量 | 累计金币 | 当前留存金币 | 累计购买商品 | 累计付费刷新 | 武器状态 | 饰品数量 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- | ---: |
| 5 | 6-7 | 5-6 | 120-180 | 10-35 | 4-6 | 1-3 | 1 把主力 Lv2，并有 1 把副武器或关键饰品 | 2-4 |
| 10 | 10-12 | 9-11 | 360-540 | 20-60 | 9-13 | 4-8 | 1 把主力 Lv3，副武器至少 Lv2 | 5-8 |
| 15 | 15-17 | 14-16 | 750-1100 | 35-100 | 16-22 | 8-14 | 1 把主力 Lv4 或双 Lv3，副武器 Lv2-Lv3 | 9-13 |
| 20 | 20-23 | 19-22 | 1300-1900 | 60-160 | 24-32 | 12-22 | 1 把主力 Lv4，至少 2 把副武器 Lv3 左右 | 13-18 |

解释口径：

- 玩家等级目标是“完成该波后”的目标。如果商店、宝箱或奖励会额外给升级卡，应从升级卡数量中扣除对应等级预期，避免升级收益过密。
- 累计金币用于验证经济投放总量；当前留存金币用于验证商店价格和刷新价格是否把玩家压到需要取舍。
- 累计购买商品包括武器和饰品，不包括免费奖励。若后续加入消耗品，应单独列出，不混入长期构筑商品数量。
- 20 波结束前，普通玩家应经历多次“买当前强度”与“刷新找构筑件”的取舍。购买量过低说明金币投放、商品价格或掉落入口太保守；购买量过高则说明经济压力不足。
- 付费刷新次数不应太低，否则商店选择压力不足；也不应太高，否则说明基础商店池可见性、商品权重或构筑入口不合理。

关键波次战斗能力目标：

| 完成波次 | 有效单体 DPS | 群体等效 DPS | EHP | 危险接触可存活时间 | 普通怪清理节奏 |
| ---: | ---: | ---: | ---: | ---: | --- |
| 5 | 70-110 | 150-250 | 120-170 | 4.0-6.0 秒 | 普通怪进入近身前能清掉大部分，漏怪可接受。 |
| 10 | 180-300 | 400-700 | 190-280 | 3.5-5.5 秒 | 普通怪应稳定快杀，重型怪开始形成阻挡。 |
| 15 | 400-650 | 900-1600 | 320-480 | 3.0-5.0 秒 | 玩家需要依赖范围、穿透、攻速或高伤害构筑清场。 |
| 20 | 750-1200 | 1800-3200 | 500-800 | 2.5-4.5 秒 | 终局应能清普通怪，但会被精英、Boss 和密度压迫。 |

这些目标的使用方式：

- 有效单体 DPS 用于验证普通怪、重型怪、精英和 Boss 的目标击杀时间。
- 群体等效 DPS 用于验证波次总生命池和刷怪密度，包含范围伤害、多弹、穿透、弹跳、持续区域和命中覆盖率。
- EHP 指玩家在护甲、闪避、直接减伤等生存属性后的等效生命，不是单纯 `MaxHealth`。
- 危险接触可存活时间用于校验容错。它不是要求玩家站桩挨打，而是确保失误后还有反应窗口。
- 如果某个构筑单体 DPS 很高但群体等效 DPS 很低，应在波次压力中安排更多小怪密度来暴露短板；反之则用重型、精英或 Boss 检验单体输出。

关键波次目标击杀时间：

| 波次段 | 普通怪 | 快速小怪 | 重型怪 | 精英怪 | Boss |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1-4 | 0.8-1.5 秒 | 0.5-1.0 秒 | 2.5-4.5 秒 | 不常规出现 | 不出现 |
| 5-9 | 0.7-1.3 秒 | 0.5-0.9 秒 | 3.0-5.0 秒 | 8-14 秒 | 不常规出现 |
| 10-14 | 0.6-1.1 秒 | 0.4-0.8 秒 | 3.5-5.5 秒 | 10-18 秒 | 35-55 秒 |
| 15-19 | 0.5-1.0 秒 | 0.35-0.75 秒 | 4.0-6.5 秒 | 12-22 秒 | 45-70 秒 |
| 20+ | 0.4-0.9 秒 | 0.3-0.7 秒 | 4.5-7.5 秒 | 15-28 秒 | 60-90 秒 |

如果某类敌人的实际击杀时间超过上限，应优先检查波次数量、同屏密度、奖励价值和敌人行为强度，而不是只降低 `MaxHealth`。如果实际击杀时间低于下限，应检查玩家输出是否过早成型，或该敌人是否应该提高数量、换成更高阶模板、提高出现波次。

### 2.4 商店与内容池

商店从商店内容池抽取商品。商店刷新、内容池价格倍率、局内价格倍率和玩家折扣只影响结算价格，不改变物品自身基础价。

默认商店配置：

| 项 | 默认值 | 说明 |
| --- | ---: | --- |
| 商品格数量 | `4` | 少于 4 格会降低构筑选择密度，多于 5 格会显著提高商店可选性。 |
| 刷新基础价 | `5` 金币 | 每次付费刷新后，下一次刷新基础价 `+1`。 |
| 免费刷新 | `0` | 只能由独立奖励或效果授予，不纳入默认经济。 |
| 锁定商品 | 保留商品、等级、内容池价格倍率 | 进入下一波或刷新显示时，重新套用当前局内商店价格倍率和玩家折扣。 |
| 重复商品 | 默认不允许同一次商店出现完全相同商品 | 同一刷新结果中不应出现同一件饰品、同一把同等级武器或同一张完全相同的商品条目。 |

商店重复与唯一性：

- 同一商店刷新结果中，默认不允许重复商品。若需要重复，必须是金币包、消耗品或后续明确允许堆叠的特殊商品。
- 同一把武器可以出现不同等级版本，但同一刷新中不应同时出现同一武器的多个等级，避免选择变成机械买高等级。
- 已拥有的唯一饰品不再进入普通商店池；非唯一饰品可以再次出现，只有明确配置了持有上限时才按上限过滤。
- 商店锁定商品不计入下一次抽取的重复判定时，会提高重复风险；默认应把锁定商品也纳入当前展示结果的去重集合。
- 高品质或高等级商品如果允许重复出现，会显著提高构筑稳定性，应降低权重或提高出现波次。

刷新价格口径：

```text
当前刷新基础价 = 刷新基础价 + 本局已付费刷新次数
刷新价格 = round(当前刷新基础价 * 局内商店价格倍率)
```

默认 4 格商店中，内容池的基础权重建议如下：

| 内容 | 基础权重 | 说明 |
| --- | ---: | --- |
| 饰品 | `2` | 饰品是商店主要构筑件，默认出现频率高于单把武器。 |
| 武器 | `1` | 武器是输出入口和合成入口，出现太多会稀释饰品选择。 |

该权重表示“每个条目”的基础权重，不是最终商店中武器和饰品的固定占比。实际占比还会受候选池数量、条件过滤、重复限制、权重规则和刷新历史影响。若候选池中饰品远多于武器，可以通过池内分组、权重修正或独立条目规则把最终商店体感拉回到“饰品略多、武器稳定可见”的区间。

商品品质和等级随波次逐步开放，不应在前几波直接投放大量高品质或高等级商品：

| 波次 | 饰品品质权重建议 | 武器等级权重建议 | 说明 |
| ---: | --- | --- | --- |
| 1-4 | Common `85`，Rare `15`，Epic `0`，Legendary `0` | Lv1 `100` | 只提供基础构筑入口。 |
| 5-9 | Common `65`，Rare `30`，Epic `5`，Legendary `0` | Lv1 `80`，Lv2 `20` | 开始出现少量中档选择。 |
| 10-14 | Common `45`，Rare `40`，Epic `14`，Legendary `1` | Lv1 `55`，Lv2 `35`，Lv3 `10` | 中期构筑成型，允许少量高投入选择。 |
| 15-19 | Common `30`，Rare `42`，Epic `25`，Legendary `3` | Lv1 `35`，Lv2 `40`，Lv3 `22`，Lv4 `3` | 后期商店应提供明确升级目标。 |
| 20+ | Common `20`，Rare `40`，Epic `34`，Legendary `6` | Lv1 `25`，Lv2 `35`，Lv3 `32`，Lv4 `8` | 终局提高高品质和高等级可见性，但不应稳定刷满顶级商品。 |

`Luck` 应影响商店中的品质权重和武器等级权重，但不改变商品格数量、刷新价格、物品基础价格或单个商品的入口价格倍率。幸运带来的收益是“更容易看到高品质/高等级选项”，不是“同样商品更便宜”。

商店幸运权重修正：

```text
商店调整后权重 = 基础权重 * max(商店幸运倍率下限, 1 + Luck / 250 * 商店幸运系数)
```

默认商店幸运系数：

| 商店产物 | 商店幸运系数 | 说明 |
| --- | ---: | --- |
| Common 饰品 | `-0.4` | 幸运提高后，低品质权重应被轻微挤出。 |
| Rare 饰品 | `0.4` | 中档品质可稳定受益，但不应完全替代 Common。 |
| Epic 饰品 | `0.9` | 高幸运时更容易看到高品质构筑件。 |
| Legendary 饰品 | `1.4` | 只提高权重，不保证出现；低波次仍受开放条件限制。 |
| Lv1 武器 | `-0.3` | 幸运提高后，低等级武器权重轻微下降。 |
| Lv2 武器 | `0.3` | 中低等级升级入口小幅受益。 |
| Lv3 武器 | `0.8` | 高等级入口明显受益。 |
| Lv4 武器 | `1.2` | 只提高权重，不绕过波次开放限制。 |

商店幸运倍率下限默认 `0.50`，不设置上限。如果 `Luck` 为负，允许高品质/高等级权重下降，但不应降到完全不出现，除非内容池本身通过波次条件关闭该条目。由于没有上限，高幸运的价值需要通过 `Luck` 属性本身的投放量、价格和稀有度控制。

幸运不绕过波次开放规则。例如 1-4 波 Legendary 饰品基础权重为 `0`，无论 `Luck` 多高都仍为 `0`；10-14 波 Legendary 饰品基础权重为 `1` 时，幸运才开始提高它在已开放范围内的相对权重。

内容池价格倍率用于修正“同一物品在不同入口、不同波次、不同条件下出现”的实际购买力价值。推荐区间：

| 用途 | 推荐倍率 | 说明 |
| --- | ---: | --- |
| 默认商品 | `1.00` | 普通商店条目。 |
| 低波次提前出现 | `1.10-1.25` | 例如 Rare 饰品或 Lv2 武器提前开放。 |
| 高品质或高等级保底入口 | `1.15-1.35` | 选择性强、可控性高时要加价。 |
| 后期清仓或低档补位 | `0.80-0.95` | 只能用于低品质、低等级或弱构筑商品。 |
| 带明显代价或低适配商品 | `0.75-0.90` | 不应用低价掩盖超预算强度。 |
| 强力武器、高价值饰品、经济雪球商品 | `1.20-1.50` | 同时还应降低权重或提高开放波次。 |

内容池价格倍率的常规配置应保持在 `0.75-1.50`。超过该区间时，应优先检查物品自身基础价、内容池权重、出现波次和品质划分是否合理，而不是只用倍率硬调。

商店调参顺序：

1. 先确定物品自身基础价是否符合 BP 价值。
2. 再调商品格数量和刷新基础价，确定商店选择密度与刷新频率。
3. 再调内容池基础权重，让武器、饰品的可见性合理。
4. 再用波次条件和权重规则控制品质、武器等级和强力商品的出现时间。
5. 最后小范围调整内容池价格倍率，只修正入口价值，不承担物品本体定价。

### 2.5 掉落与奖励

金币拾取物和击杀基础经验保持固定，不随波次、难度系数、经济系数、敌人缩放倍率或幸运改变：

```text
金币拾取物 = 1 金币
击杀普通怪基础经验 = 1 经验
```

掉落设计分为三层：

1. 击杀经验：决定玩家升级节奏，默认不受 `Luck` 影响，由怪物死亡时直接结算到击杀来源。
2. 奖励掉落：决定金币、小宝箱或其他奖励入口的产出，受怪物掉落配置和 `Luck` 影响。
3. 宝箱/奖励入口：打开后再进入奖励池或内容池，决定饰品、武器、金币包、升级选择等奖励。

默认不要把经验和金币放在同一个互斥池里抢权重。经验是击杀节奏入口，金币和宝箱是经济/奖励入口；二者可以来自同一只怪物，但应分别判定。

#### 2.5.1 怪物掉落基准

| 怪物来源 | 击杀经验 | 奖励掉落率 | 奖励池权重 | 说明 |
| --- | ---: | ---: | --- | --- |
| 普通近战 / 普通远程 | `1` | `18%` | 金币 `100` | 1 波普通怪应大多能被快速击杀，基础经验稳定给。 |
| 快速小怪 | `1` | `10%-14%` | 金币 `100` | 数量和接触压力更高，经验暂时保持 1 点，后续可通过怪物经验倍率下调。 |
| 重型怪 | `2` | `30%-40%` | 金币 `90`，小宝箱 `10` | 生命更高、击杀耗时更长，允许更高经验和少量宝箱入口。 |
| 精英怪 | `4-6` | `100%` | 金币 `70`，小宝箱 `30` | 精英必须有可感知奖励，但不能每次都等同于高品质宝箱。 |
| Boss | `10-16` | 固定奖励入口 | Boss 奖励 `100` | Boss 奖励不靠普通金币掉落表达，应进入独立奖励池。 |

上表是默认基准，不是硬编码。实际配置时可以按怪物数量、出现波次、击杀难度和波次目标微调，但应保持以下方向：

- 高频、大量、低生命怪：单体经验和奖励掉率更低。
- 低频、高生命、高威胁怪：经验更高，奖励掉率更高。
- 远程怪的奖励不因远程身份天然提高，除非它在该波次中承担精英或特殊单位职责。
- Boss 和阶段奖励优先走奖励入口，不用大量 1 金币拾取物堆视觉噪音。

#### 2.5.2 奖励池权重

奖励池使用权重，不直接写成百分比。一次奖励判定成功后，按池内调整后的权重随机选择产物：

| 奖励池 | 金币 | 小宝箱 | Boss 奖励 | 说明 |
| --- | ---: | ---: | ---: | --- |
| 普通奖励池 | `100` | `0` | `0` | 普通怪只掉金币，不直接掉宝箱。 |
| 重型奖励池 | `90` | `10` | `0` | 重型怪提供少量小宝箱入口。 |
| 精英奖励池 | `70` | `30` | `0` | 精英稳定给奖励，其中一部分转化为小宝箱。 |
| Boss 奖励池 | `0` | `0` | `100` | Boss 固定进入专用奖励，不和普通掉落混池。 |

金币奖励仍然以 1 金币拾取物表达。若需要一次性给更多金币，应使用金币包或结算奖励入口，不要通过同一位置瞬间生成大量单金币拾取物。

#### 2.5.3 宝箱与奖励入口

宝箱和奖励入口用于承载比单个金币或单次普通击杀经验更高价值的内容。默认入口如下：

| 入口 | 来源 | 默认内容 | 说明 |
| --- | --- | --- | --- |
| 小宝箱 | 重型怪、精英怪的奖励池 | 金币包、Common/Rare 饰品、低档武器或升级选择 | 主要提供小惊喜，不应稳定产出高品质内容。 |
| Boss 奖励 | Boss 击杀、阶段目标 | 武器、饰品、升级选择或较高金币包 | 应稳定提供一次有选择价值的奖励。 |
| 波次/事件奖励 | 波次目标或事件房间 | 按事件配置进入对应奖励池 | 不从普通击杀掉落率里扣预算。 |

宝箱内容也要按 BP 预算核算。宝箱绕过商店价格时，不能只用“稀有”或“随机”来平衡强度；高价值饰品、强力武器和经济雪球奖励应降低出现权重或放到更晚入口。

#### 2.5.4 幸运影响

`Luck` 不改变金币拾取物价值，也不直接提高击杀经验。`ExperienceGain` 才是提高经验获取量的属性。幸运影响奖励层以及商店中的品质/等级权重：

```text
有效奖励掉落率 = clamp(基础奖励掉落率 * (1 + Luck * 0.004), 0, 奖励掉落率上限)
调整后权重 = 基础权重 * max(0, 1 + Luck / 250 * 幸运系数)
```

默认奖励掉落率上限：

| 怪物来源 | 奖励掉落率上限 |
| --- | ---: |
| 普通近战 / 普通远程 | `35%` |
| 快速小怪 | `25%` |
| 重型怪 | `60%` |
| 精英怪 | `100%` |
| Boss | 固定奖励，不提高次数 |

默认幸运系数：

| 产物 | 幸运系数 | 说明 |
| --- | ---: | --- |
| 经验 | `0` | 不受幸运影响，避免升级曲线失控。 |
| 金币 | `0.3` | 小幅提高金币在奖励池中的占比。 |
| 小宝箱 | `0.8` | 明显但受控地提高宝箱入口权重。 |
| Boss 奖励 | `0` | Boss 奖励次数固定，幸运只影响内部品质权重。 |
| 宝箱内 Rare+ 品质 | `1.0` | 提高较高品质权重，不直接保证高品质。 |

如果某个奖励同时吃“奖励掉落率提升”和“奖励池权重提升”，它的实际收益会被双重放大。幸运、掉落收益、宝箱收益类升级卡和饰品必须额外保守计价，并在配置说明中写清楚影响的是掉率、权重、品质，还是三者中的多个部分。

表中的 `价值/点` 默认描述永久、无条件、立即生效、无负面代价、无冷却、常规覆盖率的基础裸值。

条件型、短时型或低覆盖率效果应先计算属性预算，再按覆盖率修正：

```text
有效预算 = 属性预算 * 时间覆盖率 * 触发可靠性 * 目标覆盖率
```

机制型效果不能只按线性属性相加。涉及特殊机制时，应按 2.2 机制价值表单独核算。

## 3. 属性单位表

本节只定义属性的数值单位、配置含义和基础价值口径。属性表中同时标注负值、取整和消费侧边界，避免边界规则散落在正文里。

属性值本身不做强制截断，属性面板应保留真实累计值，例如玩家拥有 `Dodge 80` 时属性仍显示为 `80%`。有效下限、上限、取整、概率范围、折扣范围和单位换算必须使用统一口径，不能在不同模块重复定义边界。

| 属性 | 配置单位 | 说明 | 常规属性 | 负值口径 | 取整口径 | 消费侧边界 | 价值/点 |
| --- | --- | --- | --- | --- | --- | --- | ---: |
| `Attack` | 点数 | `Add +1` 表示基础攻击增加 1 点；配置在玩家身上时，会提高玩家武器伤害结算中的基础攻击值。 | 否 | 可降低攻击 | - | 最终有效攻击不低于 `0` | 40 |
| `Damage` | 百分比点 | 全局最终伤害提升，`1` 表示最终伤害 `+1%`，`100` 表示最终伤害提升一倍。 | 是 | 可降低伤害倍率 | - | 最终伤害不低于 `0` | 20 |
| `MeleeAttack` | 点数 | `Add +1` 表示近战攻击增加 1 点。 | 是 | 可降低对应类型贡献 | - | 最终武器伤害不低于 `0` | 20 |
| `RangedAttack` | 点数 | `Add +1` 表示远程攻击增加 1 点。 | 是 | 可降低对应类型贡献 | - | 最终武器伤害不低于 `0` | 20 |
| `MagicAttack` | 点数 | `Add +1` 表示魔法攻击增加 1 点。 | 是 | 可降低对应类型贡献 | - | 最终武器伤害不低于 `0` | 20 |
| `SummonAttack` | 点数 | `Add +1` 表示召唤攻击增加 1 点。 | 是 | 可降低对应类型贡献 | - | 最终武器伤害不低于 `0` | 20 |
| `AttackSpeed` | 攻速点 | `100` 表示每秒攻击 1 次；`Add +10` 表示攻击速度增加 10 攻速点；攻击间隔为 `100 / finalAttackSpeedPoints`。 | 是 | 可降低攻速 | - | 最终有效攻击速度不低于 `1` 攻速点 | 20 |
| `CriticalChance` | 百分比点 | `1` 表示 `1%` 暴击率。 | 是 | 可降低暴击率 | - | 有效判定范围 `0%` 到 `100%` | 50 |

| `MoveSpeed` | 距离点/秒 | `100` 表示每秒移动 1 格；`Add +1` 表示移动速度增加 0.01 格/秒。 | 是 | 不建议 | - | 不建议依赖负值；消费侧按局部最小值保护 | 10 |

| `HealthRecoverySpeed` | 回复点 | `10` 表示每秒恢复 1 点生命；`Add +1` 表示每秒恢复 0.1 点生命。 | 是 | 负值按 `0` 处理 | - | 最低为 `0` | 10 |

| `LifeSteal` | 百分比点 | `1` 表示 `1%` 生命偷取。 | 否 | 负值按 `0` 处理 | - | 消费侧最低为 `0` | 20 |
| `PickupRadius` | 距离点 | `100` 表示 1 格拾取半径；`Add +1` 表示拾取半径增加 0.01 格；乘区使用百分比点。 | 否 | 不建议 | - | 消费侧最低为 `0` | 5 |
| `ProjectileSpeed` | 点数 | `Add +1` 表示投射物速度增加 1 点；乘区使用百分比点。 | 否 | 不建议 | - | 当前无统一下限 | 5 |
| `AttackRange` | 距离点 | `100` 表示 1 格攻击距离；`Add +1` 表示攻击距离增加 0.01 格；乘区使用百分比点。 | 是 | 不建议 | - | 最终攻击距离不低于 `0.1` 格 | 8 |
| `ProjectilePierceCount` | 点数 | `+1` 表示增加 1 次穿透。 | 否 | 不建议 | 向下取整 | 最终不低于 `0` | 200 |
| `KnockbackStrength` | 点数 | `+1` 表示击退强度增加 1 点；乘区使用百分比点。 | 否 | 可降低击退 | - | 最终击退强度不低于 `0` | 5 |
| `KnockbackResistance` | 百分比点 | `1` 表示 `1%` 击退抗性。 | 否 | 负值按 `0` 处理 | - | 有效折减范围 `0%` 到 `100%` | 5 |
| `ExperienceGain` | 百分比点 | `1` 表示经验获取 `+1%`。 | 否 | 负值按 `0` 处理 | - | 消费侧最低为 `0` | 15 |
| `ShopPriceDiscount` | 百分比点 | `1` 表示商店折扣 `1%`。 | 否 | 负值按 `0` 处理 | - | 有效折扣最高 `50%`，最终价格倍率不低于 `50%` | 15 |
| `WaveGoldRewardBonus` | 点数 | `+1` 表示每波额外获得 1 金币。 | 否 | 不建议 | 向下取整 | 最终不低于 `0` | 12.5 |
| `DamageReduction` | 百分比点 | `1` 表示直接减伤 `1%`。 | 否 | 负值按 `0` 处理 | - | 有效直接减伤范围 `0%` 到 `50%` | 25 |
| `HealingPower` | 百分比点 | `1` 表示治疗效果 `+1%`。 | 否 | 当前无统一语义 | - | 当前未形成统一消费口径 | 10 |
| `WeaponSlotCount` | 点数 | `+1` 表示增加 1 个武器槽。 | 否 | 不建议 | 四舍五入 | 最终不低于当前已装备槽位数，且不低于 `0` | 400 |

## 4. 玩家基础与经验

本节只定义玩家 1 级基础属性和局内经验升级口径，不绑定具体角色职业、天赋或角色差异。后续如果移除角色体系，仍应保留一份统一的玩家基础属性基准。

### 4.1 1 级基础属性

玩家 1 级基础属性推荐基准如下：

| 属性 | 基准值 | 说明 |
| --- | ---: | --- |
| `MaxHealth` | 90 | 初始最大生命。以 1 波普通近战 `12-18` 单次伤害为基准，玩家约承受 `5-8` 次命中死亡。 |
| `MoveSpeed` | 420 | 初始移动速度，即每秒 `4.2` 格。玩家应略快于普通近战，慢于快速追击怪。 |

| `Damage` | 0 | 初始无全局最终伤害加成。 |

| `Armor` | 0 | 初始无护甲。 |
| `Dodge` | 0 | 初始无闪避。 |
| `HealthRecoverySpeed` | 0 | 初始无生命恢复。 |

### 4.2 经验曲线

玩家经验推荐配置如下：

| 参数 | 默认值 | 说明 |
| --- | ---: | --- |
| 初始等级 | 1 | 局内初始等级。 |
| 初始经验 | 0 | 局内初始经验。 |
| 经验需求关键点 | 见下表 | X 为当前等级，Y 为升到下一级所需经验。关键等级之间线性插值，最后一个关键等级之后按最后一段斜率外推。 |
| 单级经验需求下限 | 1 | 单级经验需求下限。 |
| 每级升级点 | 1 | 每次升级获得的升级点数量。 |

经验需求曲线关键点：

| 当前等级 | 升到下一级所需经验 |
| ---: | ---: |
| 1 | 8 |
| 2 | 13 |
| 3 | 19 |
| 4 | 26 |
| 5 | 34 |
| 10 | 89 |
| 15 | 169 |
| 20 | 274 |

经验需求计算口径：

```text
当前等级 <= 最后关键等级：
  在经验需求关键点之间线性插值

当前等级 > 最后关键等级：
  按最后两个关键点的斜率继续外推

最终经验需求 =
  max(单级经验需求下限, round(曲线结算值))
```

当前默认配置下，前期升级较快，中后期需求明显抬升：

| 当前等级 | 升到下一级所需经验 | 从 1 级累计到该等级所需经验 |
| ---: | ---: | ---: |
| 1 | 8 | 0 |
| 2 | 13 | 8 |
| 3 | 19 | 21 |
| 4 | 26 | 40 |
| 5 | 34 | 66 |
| 7 | 56 | 145 |
| 10 | 89 | 346 |
| 15 | 169 | 951 |
| 20 | 274 | 2006 |

击杀普通怪当前提供 `1` 点基础经验。`ExperienceGain` 使用百分比点提高击杀经验获取，并按小数累计后向下取整发放实际经验。例如 `ExperienceGain +25` 时，连续获得 4 点基础经验会实际结算为 5 点经验。

经验只负责给升级卡片选择提供节奏，不直接提高玩家基础属性。玩家升级后的具体收益应通过升级卡片、武器升级、饰品或其他局内奖励表达。

## 5. 生存与 EHP 口径

本节用于把 `MaxHealth`、`Armor`、`DamageReduction`、`Dodge`、回复和吸血折算到统一生存口径。设计者配置生存属性时，应先算瞬时 EHP，再单独评估持续生存，不要把所有生存来源简单线性相加。

### 5.1 护甲与减伤

护甲先转换为护甲减伤率：

```text
有效护甲 = max(Armor, -95)

护甲减伤率 = 有效护甲 / (abs(有效护甲) + 25)
```

`DamageReduction` 使用百分比点，并在消费侧限制到有效范围。护甲减伤和直接减伤按序列减伤合成：

```text
直接减伤率 = clamp(DamageReduction / 100, 0, 0.5)
单项减伤率上限 = 0.95
总减伤率 = min(1 - (1 - min(护甲减伤率, 0.95)) * (1 - min(直接减伤率, 0.95)), 0.95)
承伤倍率 = 1 - 总减伤率
```

负护甲会提高承伤，不能把负护甲减伤率截为 `0`。例如 `Armor = -25` 时，护甲减伤率为 `-50%`，即承伤变为 `150%`，再与直接减伤按同一公式合成。

### 5.2 闪避与瞬时 EHP

闪避不降低单次命中的伤害，但会降低长期期望承伤。EHP 估算时按期望承伤处理：

```text
有效闪避率 = clamp(Dodge / 100, 0, 0.5)
瞬时 EHP = MaxHealth / max(0.05, 承伤倍率 * (1 - 有效闪避率))
```

示例：

```text
MaxHealth = 100
总减伤率 = 30%
Dodge = 20%

瞬时 EHP = 100 / ((1 - 0.30) * (1 - 0.20)) = 178.6
```

闪避的体感波动高于护甲和直接减伤。低生命、高闪避构筑可能在期望 EHP 上合理，但容易被连续命中秒杀；Boss、精英和高单次伤害场景下，闪避预算应打折。

### 5.3 回复、吸血与持续生存

回复和吸血不进入瞬时 EHP，进入持续生存预算。它们只在玩家没有被短时间击杀、且有足够输出或战斗时间时生效。

当前实战基准下，生命恢复的稳定性和体感强度明显高于吸血。吸血经常受有效输出、命中频率、目标数量、溢出伤害和安全输出窗口限制，不能按理论 DPS 直接高估；生命恢复只要玩家存活就持续生效，应按更高基础价值计价。

```text
生命恢复 HPS = max(0, HealthRecoverySpeed / 10) * (1 + HealingPower / 100)
吸血 HPS = 有效输出 DPS * max(0, LifeSteal / 100) * 吸血触发覆盖率
持续治疗 HPS = 生命恢复 HPS + 吸血 HPS + 其他治疗 HPS
持续 EHP/s = 持续治疗 HPS / max(0.05, 承伤倍率 * (1 - 有效闪避率))
可持续作战时间 = MaxHealth / max(1, 敌方实际 DPS - 持续治疗 HPS)
```

回复和吸血的计价限制：

- 低压清怪阶段，回复和吸血价值较低，因为玩家本来就不持续承伤。
- 高密度持续承伤阶段，回复和吸血价值提高，但会被爆发伤害和控制窗口限制。
- 吸血必须依赖有效输出。当前基础口径按低稳定性处理；只有远程安全输出、高频多段和大范围武器稳定触发吸血时，才应按输出覆盖率上调计价。
- 回复、吸血、护甲、减伤和闪避同时出现时，持续生存会发生乘法放大，不能按各自 BP 简单相加。

### 5.4 生存属性价值衰减

生存属性之间存在明显叠加放大。设计时先计算每项属性带来的边际 EHP 增量，再按叠加数量做价值衰减。

```text
边际 EHP 增量 = 新 EHP - 旧 EHP
边际价值比例 = 边际 EHP 增量 / 旧 EHP
```

推荐衰减规则：

| 同一来源包含的生存链路数量 | 计价建议 | 说明 |
| ---: | ---: | --- |
| 1 | 100% | 单一生存方向，按属性价值表计价。 |
| 2 | 第二条按 70%-85% 生效 | 例如生命 + 护甲、生命 + 回复。 |
| 3 | 第三条按 45%-65% 生效 | 开始形成复合生存构筑，必须压预算。 |
| 4+ | 后续按 25%-45% 生效 | 只适合高品质、唯一、带代价或终局效果。 |

闪避、减伤、护甲同时堆叠时，优先用 EHP 边际增量而不是原始属性点判断强度。若一件饰品同时提供 `MaxHealth`、`Armor`、`Dodge` 和 `DamageReduction`，即使每项数值都不高，也应按复合生存件处理，不能按普通多属性饰品放行。

### 5.5 填表口径

配置任何生存卡、饰品或武器持有者属性时，至少填写：

| 项 | 填写内容 |
| --- | --- |
| 基础生命 | 未获得该项前的 `MaxHealth`。 |
| 护甲减伤率 | 按护甲公式折算后的减伤。 |
| 直接减伤率 | `DamageReduction` 的有效值。 |
| 闪避率 | `Dodge` 的有效值。 |
| 瞬时 EHP | 不含回复和吸血。 |
| 持续治疗 HPS | 生命恢复、吸血和其他治疗。 |
| 持续 EHP/s | 治疗折算到承伤后的等效恢复。 |
| 生存链路数量 | 生命、护甲、减伤、闪避、回复、吸血分别计数。 |
| 衰减后 BP | 按复合生存衰减后的最终预算。 |

## 6. 升级卡片

### 6.1 价值参考

升级卡片的基础价值只表示单张卡允许承载的属性预算，不包含卡池权重、出现条件、具体卡片配置或额外投放规则。

实际配置允许围绕基础价值上下浮动约 `10%`。超过该范围时，应单独记录原因，例如单一方向强度、触发覆盖率或前置条件。

| 稀有度 | 基础价值 |
| --- | ---: |
| Common | 100 BP |
| Rare | 150 BP |
| Epic | 225 BP |
| Legendary | 350 BP |

### 6.2 设计原则

升级卡片是局内成长选择，每张卡片只提供单一方向的纯数值正向加成，不通过负面属性回收预算，也不在同一张卡里混合多个成长方向。

基础流程：

1. 先确定卡片方向，例如输出、生存、机动、拾取、经济或攻击距离。
2. 只选择该方向下的一项主要属性。
3. 按属性价值表计算 BP，并对照稀有度基础价值。
4. 确认最终价值在基础价值约 `10%` 浮动范围内。

方向边界：

- 输出卡只提升输出方向，例如 `Damage`、攻击类型属性、`AttackSpeed`、暴击或暴击伤害。
- 生存卡只提升生存方向，例如 `MaxHealth`、`Armor`、`Dodge`、`DamageReduction`、回复或治疗效果。
- 机动卡只提升移动或距离方向，例如 `MoveSpeed`、`AttackRange` 或 `PickupRadius`。
- 经济卡只提升经济方向，例如 `ExperienceGain`、`ShopPriceDiscount` 或 `WaveGoldRewardBonus`。

设计限制：

- 不设计负面属性。
- 不用低价值副属性凑预算。
- 不在同一张卡里同时提供输出、生存、经济等多个方向。
- 不提供子弹穿透、武器槽、强制暴击等机制变化。

### 6.3 重复与权重

升级卡默认可以重复出现，也可以被重复选择；升级卡不通过硬性最大叠加次数或同类数量上限控制强度。强度控制应由单张 BP、稀有度、出现权重、波次开放、边际价值衰减和属性有效上限共同承担。

| 卡片类型 | 默认是否可重复 | 控制方式 | 说明 |
| --- | --- | --- | --- |
| 普通属性卡 | 可以 | 单张 BP 和基础权重 | 例如单项 `Damage`、`AttackSpeed`、`MaxHealth`，允许玩家围绕一个方向持续堆叠。 |
| 攻击类型卡 | 可以 | 武器收益率和属性价值 | 四类 Attack 可作为构筑主轴，不用数量上限截断成长。 |
| 暴击卡 | 可以 | 暴击期望、权重和消费侧概率上限 | 暴击率和暴击伤害相乘放大，应通过数值和权重保守处理。 |
| 生存卡 | 可以 | EHP 边际收益衰减 | 生命、护甲、闪避、减伤、回复会复合放大，按 EHP 口径判断边际价值。 |
| 经济卡 | 可以 | 稀有度、权重和单张数值保守 | 经验、折扣、金币奖励会滚雪球，但不设置硬性选择次数上限。 |

升级卡在当前数值设计中默认不配置机制卡。`UpgradeCardSO.SpecialFeatures` 仍然是通用 Feature 容器，代码层不按 Feature 类型过滤升级卡；只是设计填表和资产配置时，升级卡只使用属性型收益。子弹穿透、武器槽、强制暴击等机制变化，不作为升级卡设计内容；这些内容应放在武器等级、饰品、事件奖励或后续专门机制入口中处理。

重复卡的权重规则：

- 可以让已选过的同一张卡继续出现在后续升级选择中，不因为选择次数达到某个上限而移除。
- 重复卡可以按已选次数做软性权重调整，例如每次已选后权重乘 `0.75-1.00`。这是为了改善选择多样性，不是数量限制。
- 经济、暴击和复合生存卡如果持续被选择，应通过单张数值更保守、稀有度更高或基础权重更低来控制长期强度。
- 属性有效上限仍然生效。例如 `Dodge`、暴击率、折扣等属性可以继续累计真实值，但最终只按统一有效口径参与结算。

## 7. 饰品

### 7.1 价值参考

饰品的基础价值表示单件饰品允许承载的属性预算区间，不是每个品质固定一个值。饰品通常是长期持有项，并且可能通过商店、宝箱或奖励获得，因此不能只按升级卡片价值平移。

同一品质内允许出现低档、中档和高档饰品。价值越高，参考价格越高；品质只限定大致预算带，不把同品质所有饰品压成同一个价格。

| 品质 | 基础价值范围 | 参考价格范围 |
| --- | ---: | ---: |
| Common | 60-110 BP | 15-28 金币 |
| Rare | 110-180 BP | 28-45 金币 |
| Epic | 180-280 BP | 45-70 金币 |
| Legendary | 280-500 BP | 70-125 金币 |

参考价格按实际价值计算：

```text
饰品参考价格 = round(饰品实际价值 BP / 4)
饰品回收价格约为饰品参考价格的 30%
```

价格可以按获取入口、可选性、负面属性、机制强度和唯一性微调，但不应脱离实际 BP 太远。若价格明显偏离参考价，应在配置说明或设计记录中写明原因。回收价格允许围绕参考价格的 `25%` 到 `35%` 小幅浮动，用于处理整数取整、商店回收效率和经济节奏。

纯属性饰品可以直接按属性价值表计算。机制型饰品需要额外预算，例如 2.2 表中的特殊机制或其他明显改变战斗规则的效果。

### 7.2 设计原则

饰品是长期持有的构筑部件，设计目标不是复刻升级卡片，而是提供稳定方向、局部偏科或带代价的玩法倾向。饰品数值应先按属性价值表折算 BP，再按金币购买力估算参考价格。

基础流程：

1. 先计算所有正向属性的 BP。
2. 再扣除负面属性回收的 BP。
3. 如果包含机制效果，额外加入机制预算。
4. 对照饰品品质的基础价值区间。
5. 按 `1 金币 = 4 BP` 得到参考价格，再根据实际获取入口修正。

品质边界：

- Common 以单一轻属性为主，避免出现强机制或多个高价值属性。
- Rare 可以提供一个明确方向，允许一个主属性加一个低价值副属性。
- Epic 可以强化构筑倾向，但不应单独改变核心玩法结构。
- Legendary 可以承载构筑入口或高价值机制，但应有条件、代价、唯一性或明显方向。

价格修正：

- 商店可选性会提高实际价值，同等 BP 的饰品可以略高于参考价格。
- 宝箱或奖励可能绕过价格，因此不能只靠高价格平衡强饰品。
- 带负面属性、触发条件或低覆盖率的饰品可以低于参考价格。
- 经济收益、商店折扣和掉落收益类饰品要额外保守，因为它们会影响后续购买力。

设计限制：

- 不要在低品质饰品中投放 2.2 表中的特殊机制。
- 不要把多个生存链路同时堆在同一件饰品上，例如高生命、高闪避、高减伤和高回复同时出现。
- 不要用高价格掩盖明显超预算的属性组合。
- 负面属性只能回收与其实际影响相符的 BP，不能用无关紧要的负面项抵消核心强机制。

### 7.3 唯一性与重复

饰品默认可以重复获得，不因为已经持有同名饰品就从商店或奖励池中移除。是否唯一或限制持有数量只用于少数机制强度明显高于普通属性件的饰品。

| 饰品类型 | 默认重复口径 | 持有数量口径 | 说明 |
| --- | --- | --- | --- |
| 纯低值属性饰品 | 可重复 | 不设上限 | 例如低额生命、低额范围、低额移动速度。 |
| 明确构筑饰品 | 可重复 | 不设上限 | 例如高暴击、高攻速、特定攻击方向强化；通过 BP、价格、品质和权重控制强度。 |
| 复合生存饰品 | 可重复 | 不设上限 | 同时提供多条生存链路时，按 EHP 口径计价，但不默认限制持有数量。 |
| 经济饰品 | 通常可重复 | 按具体效果决定 | 折扣、经验、金币、掉落收益会滚雪球，应更依赖数值保守、品质、价格和权重控制。 |
| 中等或轻量机制饰品 | 按情况决定 | 不设上限或适量限制 | 例如轻量触发、低覆盖率机制、弱条件联动；如果叠加后改变玩法结构，应配置适量上限。 |
| 终极强机制饰品 | 默认唯一 | 1 | 额外武器槽、强制暴击等终局或强构筑入口。 |

重复饰品暂时不做额外价值衰减。设计时只按单件 BP、价格、品质、权重和波次开放评估；如果一件饰品重复后强度明显非线性放大，应优先把它归入机制饰品，并配置唯一性或适量持有上限。

商店和奖励池应能读取唯一性或持有数量规则。玩家已拥有唯一饰品时，该饰品不应继续进入普通商店、宝箱和奖励入口；如果需要转化，应明确转为金币、刷新券或同品质替代奖励。未配置唯一性和持有上限的饰品，默认允许继续出现。

## 8. 武器

### 8.1 数值定位

武器是局内主要输出载体。武器数值应同时决定：

- 单次命中的基础强度。
- 攻击频率与攻击节奏。
- 射程、击退、暴击等战斗手感。
- 与玩家通用属性、攻击类型属性、饰品和升级卡的联动空间。

武器自身数值只描述基础数据和等级成长。玩家属性、升级卡、饰品和局内推进修饰只作为外部来源参与强度评估，不改变武器基础定位。

### 8.2 武器标签

武器标签描述武器的玩法特性，不描述武器类型。当前只保留以下四类标签：

| 标签 | 主成长方向 | 说明 |
| --- | --- | --- |
| 重型 | 主要加基础攻击 | 强化单次命中、前摇成本和高伤害感。副属性可以少量补范围、击退或暴击，但不应明显补攻速短板。 |
| 快速 | 主要加攻速 | 强化攻击频率、触发频率和手感稳定性。副属性可以少量补基础攻击或范围，但击退、暴击和收益率要保守。 |
| 成长 | 暂不定义 | 仅预留为后续成长型机制入口，当前不写入具体数值规则。 |
| 精准 | 主要加暴击和暴击伤害 | 强化暴击期望与爆发感。副属性可以少量补基础攻击或攻速，但不要同时给高暴击率、高暴击伤害和高基础攻击。 |

标签只决定升级主基调，不是硬性唯一属性。每级升级应有一个主要收益方向，同时允许少量副属性补手感或稳定性。副属性的预算仍计入该等级总体价值，不能作为免费补偿项。

### 8.3 等级与基础参数

武器等级当前固定为 `1` 到 `4` 级。每一级都应有独立的基础参数、攻击比例、收益率和持有者属性预算。

| 参数 | 单位 | 说明 | 外部收益率 | 计算口径 | 数值边界 |
| --- | --- | --- | --- | --- | --- |
| `Attack` | 点数 | 武器自身基础攻击力，进入武器伤害计算。 | 无。`Attack` 不使用武器收益率配置。 | `max(0, (武器 Attack + 类型攻击贡献) * (1 + Damage / 100))` | 不低于 `0` |
| `AttackSpeed` | 攻速点 | `100` 表示每秒攻击 1 次，攻击间隔为 `100 / 攻速点`。 | 攻速收益率 | `武器 AttackSpeed + 外部 AttackSpeed 增量 * 收益率 / 100`，攻击间隔为 `100 / max(1, 最终攻速点)` | 不低于 `1` 攻速点 |
| `CriticalChance` | 百分比点 | 武器自身暴击率。 | 暴击率收益率 | `clamp(武器 CriticalChance / 100 + 外部 CriticalChance / 100 * 收益率 / 100, 0, 1)` | `0` 到 `100` |
| `CriticalPercent` | 百分比点 | 武器自身暴击伤害倍率，`180` 表示 `1.8x`。 | 暴击伤害收益率 | `max(1, 武器 CriticalPercent / 100 + 外部 CriticalPercent / 100 * 收益率 / 100)` | 不低于 `100` |
| `Range` | 距离点 | 武器索敌、发射最大距离或近战有效范围的基础距离。 | 范围收益率 | `武器 Range + 外部 AttackRange 增量 * 收益率 / 100`，最终距离为 `max(0.1, 最终射程点 / 100)` | 不低于 `0`，最终距离不低于 `0.1` 格 |
| `KnockbackStrength` | 点数 | 武器基础击退强度。 | 击退收益率 | `max(0, 武器 KnockbackStrength + 外部 KnockbackStrength 增量 * 收益率 / 100)` | 不低于 `0` |
| `MeleeAttackUsagePercent` | 百分比点 | 本等级吃到玩家近战攻击属性的比例。 | 攻击比例 | `MeleeAttack * MeleeAttackUsagePercent / 100`，进入类型攻击贡献。 | 不低于 `0` |
| `RangedAttackUsagePercent` | 百分比点 | 本等级吃到玩家远程攻击属性的比例。 | 攻击比例 | `RangedAttack * RangedAttackUsagePercent / 100`，进入类型攻击贡献。 | 不低于 `0` |
| `MagicAttackUsagePercent` | 百分比点 | 本等级吃到玩家魔法攻击属性的比例。 | 攻击比例 | `MagicAttack * MagicAttackUsagePercent / 100`，进入类型攻击贡献。 | 不低于 `0` |
| `SummonAttackUsagePercent` | 百分比点 | 本等级吃到玩家召唤攻击属性的比例。 | 攻击比例 | `SummonAttack * SummonAttackUsagePercent / 100`，进入类型攻击贡献。 | 不低于 `0` |
| 持有者属性 | 属性修饰 | 本等级装备时提供给武器持有者的属性收益。 | - | 计入持有者全局属性预算。 | 默认使用 `Add`，乘区需单独核算。 |

完整伤害入口如下：

```text
类型攻击贡献 =
    MeleeAttack * MeleeAttackUsagePercent / 100
  + RangedAttack * RangedAttackUsagePercent / 100
  + MagicAttack * MagicAttackUsagePercent / 100
  + SummonAttack * SummonAttackUsagePercent / 100

武器面板伤害 = max(0, (武器 Attack + 类型攻击贡献) * (1 + Damage / 100))
```

武器收益率包含五项同名属性收益率和四项攻击类型收益率。外部特性可以同时调整同名属性收益率和四项攻击类型收益率。所有收益率都使用百分比点：

- `100` 表示完整吃到玩家属性收益。
- `50` 表示只吃到玩家属性收益的一半。
- `0` 表示完全不吃该属性的玩家外部收益。

同名属性收益率只折算玩家属性、升级卡、饰品等外部来源带来的增量，不折损武器等级表里的自身基础值。收益率适合用于限制高攻速武器、散射武器或高覆盖武器对击退、攻速、范围和暴击的放大能力。

评估武器基础输出时，可以先使用下面的单体期望公式：

```text
每秒攻击次数 = 攻速点 / 100
暴击期望倍率 = 1 + 暴击率 * max(0, 暴击倍率 - 1)
单体理论 DPS = 武器面板伤害 * 每秒攻击次数 * 暴击期望倍率
```

但理论 DPS 不能直接等于最终强度。近战扫掠、多弹体、穿透、范围伤害、持续伤害、寻敌稳定性、攻击前摇、攻击序列占用和命中率都需要额外修正。

设计时不要只看 `Attack`。武器强度至少由攻击力、攻速、暴击期望、射程、命中覆盖率、目标覆盖率和机制效果共同决定。

### 8.4 等级成长

武器升级是同一把武器的局内成长，不应把低级武器升级成另一种武器。

- 低频高单次命中的武器优先提高 `Attack`、范围或击退，不宜同时大幅提高攻速。
- 高频低单次命中的武器优先提高 `AttackSpeed` 或小幅提高 `Attack`，避免叠加高暴击和高基础攻击。
- 已经围绕暴击收益设计的武器，可以提高 `CriticalChance` 或 `CriticalPercent`，同时控制基础攻击和攻速。
- 依赖距离保持输出的武器，提高 `Range` 会增加输出稳定性和安全性，应视为强度提升，而不是纯手感项。

等级成长可以带来四类收益：

| 收益类型 | 可成长内容 | 说明 | 风险 |
| --- | --- | --- | --- |
| 基础数值收益 | `Attack`、`AttackSpeed`、`CriticalChance`、`CriticalPercent`、`Range`、`KnockbackStrength` | 直接改变武器等级基础参数。这是最稳定、最容易横向比较的成长方式。 | 多项同时增长会让强度膨胀，尤其是 `Attack * AttackSpeed * 暴击期望` 同时提高。 |
| 攻击比例成长 | 四类 `AttackUsagePercent` | 每一级都可以设置四份攻击比例，用同一套等级表表达武器更吃哪类攻击。 | 会放大玩家攻击类型属性，不能只按裸面板评估。 |
| 持有者属性成长 | 持有者属性 | 装备该等级武器时添加给持有者的属性，例如少量 `Damage`、`AttackSpeed`、`CriticalChance`。 | 会影响持有者所有武器，是全局收益，预算要按全局覆盖计算。 |
| 外部收益率成长 | `AttackSpeedBenefitPercent`、暴击收益率、范围收益率、击退收益率，以及外部特性提供的攻击类型收益率修饰 | 提高武器吃玩家外部属性的能力。适合把高等级武器做成更强的构筑承载器。 | 会放大升级卡、饰品和角色属性，不能只按武器裸面板评估。 |
| 机制收益 | 连发次数、穿透、命中盒尺寸、扫掠范围、爆炸范围、索敌稳定性、攻击序列占用、特殊效果 | 改变实际命中次数、覆盖率、命中可靠性或功能性。 | 不能用属性价值表线性折算，必须按机制成长额外计价。 |

常规武器每升 1 级，总体属性价值建议提升约 `40%` 到 `50%`。默认按下面倍率估算：

```text
等级价值倍率 = 1.45 ^ (等级 - 1)
```

| 等级 | 默认总体价值倍率 | 说明 |
| ---: | ---: | --- |
| 1 | 1.00 | 基准强度。 |
| 2 | 1.45 | 第一次明显成长，应至少有一个可感知主收益。 |
| 3 | 2.10 | 中段成型，允许强化第二个次要方向。 |
| 4 | 3.05 | 完整形态，但不应补齐所有短板。 |

倍率可以按武器实际命中成本上下浮动：

- 高频、高覆盖、多段命中或强控制武器使用低档，建议每级 `1.40`。
- 常规单体或常规范围武器使用默认档，建议每级 `1.45`。
- 低频、高前摇、命中成本高或机制收益少的武器可以使用高档，建议每级 `1.50`。

这里的总体属性价值包含基础数值收益、攻击比例成长、持有者属性成长、外部收益率成长和机制收益。不能只让基础参数达到倍率后，再额外免费叠加攻击比例、持有者属性、收益率或机制变化。

基础数值成长用于提高武器的裸强度。每一级建议只强化 1 到 2 个主方向，避免同一级同时提高攻击、攻速、暴击和覆盖率：

- `Attack` 成长提高单次命中、暴击收益和类型攻击贡献前的基础伤害，适合低频、高前摇或高命中成本的武器。
- `AttackSpeed` 成长提高出手频率、触发频率和手感稳定性，适合单次伤害较低的武器，但会同步放大击退、命中特效和命中触发。
- `CriticalChance` 和 `CriticalPercent` 成长属于期望伤害成长，应优先服务已有暴击联动的武器，不要作为所有武器的通用升级填充项。
- `Range` 成长会提高安全性、索敌稳定性和有效输出时间，长距离或需要持续保持距离的武器尤其要按强度项处理。
- `KnockbackStrength` 成长提高控制能力和生存空间，高频、高范围和多段命中武器要降低击退成长或收益率。

等级成长应满足：

1. 每一级至少提升一个核心属性或明确机制。
2. 不用多个低感知小属性凑等级成长。
3. 4 级可以体现该武器的完整定位，但不应无条件覆盖同类武器的所有优势。
4. 如果升级改变穿透、命中形状、连发次数、范围伤害或特殊效果，应按机制成长额外计价。
5. 如果升级提高收益率，应同时检查玩家属性、升级卡和饰品的长期堆叠预期。
6. 如果升级提高攻击频率或覆盖率，应同步复查击退、命中触发和性能成本。
7. 如果升级给持有者属性，应按持有者全局收益预算，而不是只按单把武器预算。

暂定评估流程：

```text
1. 先计算 1 级武器的单体理论 DPS。
2. 对每一级计算裸面板 DPS 变化。
3. 再估算外部收益率提高后，在常规构筑和高投入构筑下的收益上限。
4. 估算命中覆盖率、目标覆盖率、机制可靠性和控制收益。
5. 用同类武器横向比较，避免同一武器同时拥有最高 DPS、最高范围、最高安全性和最高控制。
```

### 8.5 价格口径

武器价格要同时满足两个目标：

1. 1 级武器价格能反映它作为一个新输出入口的基础价值。
2. 高等级武器价格能反映升级后的强度、合成便利性和商店可选性，而不是只机械套一个倍率。

1 级商店基础价应先按武器 1 级总价值估算参考价：

```text
1 级参考价 = round(1 级武器总价值 BP / 4)
```

武器 1 级总价值 BP 应包含基础数值、攻击比例、初始收益率、初始持有者属性和稳定命中能力。当前武器暂时只分两个品质等级：

| 武器品质 | 1 级总价值参考 | 1 级参考价 | 说明 |
| --- | ---: | ---: | --- |
| 正常武器 | 80-120 BP | 20-30 金币 | 默认档，大多数武器使用。 |
| 强力武器 | 130-180 BP | 33-45 金币 | 初始强度、覆盖率、收益率或构筑潜力明显高于正常武器。 |

高等级武器价格以等级价值倍率为基础，再额外考虑商店直接买到高等级武器会跳过合成过程，因此价格倍率要明显高于纯强度倍率：

```text
等级价格 = round(1 级基础价 * 等级价格倍率)
```

当前代码口径和数值表采用的等级价格倍率固定为 `1.00 / 1.60 / 3.60 / 7.20`。后续若调整 `WeaponPriceHelper`，必须同步修改本表和 `Docs/玩法数值表.xlsx`。

| 等级 | 默认等级价值倍率 | 等级价格倍率（代码口径） | 说明 |
| ---: | ---: | ---: | --- |
| 1 | 1.00 | 1.00 | 基础购买入口。 |
| 2 | 1.45 | 1.60 | 直接买到 2 级约等于跳过一次合成机会，应接近两把 1 级武器的投入。 |
| 3 | 2.10 | 3.60 | 直接买到 3 级应明显贵于两把 1 级武器的裸价格。 |
| 4 | 3.05 | 7.20 | 完整形态，商店直购必须是高投入选择，不能接近普通装备价。 |

默认示例：

| 品质 | 1 级基础价 | 1 级 | 2 级 | 3 级 | 4 级 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 正常武器 | 20 | 20 | 32 | 72 | 144 |
| 正常武器 | 25 | 25 | 40 | 90 | 180 |
| 正常武器 | 30 | 30 | 48 | 108 | 216 |
| 强力武器 | 35 | 35 | 56 | 126 | 252 |
| 强力武器 | 40 | 40 | 64 | 144 | 288 |
| 强力武器 | 45 | 45 | 72 | 162 | 324 |

最终进入商店后，再叠加内容池价格倍率、局内商店价格倍率和玩家折扣倍率：

```text
商品价格 = 等级价格 * 内容池价格倍率 * 局内商店价格倍率 * 玩家折扣倍率
```

定价原则：

- 1 级基础价应先匹配 1 级武器价值，不要用 4 级强度反推 1 级价格。
- 高等级价格使用固定倍率表，不再用单一指数临时推导。
- 武器只在“正常武器”和“强力武器”两个品质等级中选择，不再细分主武器、副武器或过渡武器。
- 同品质内，明显更稳定、更高覆盖或更吃构筑的武器，可以在该品质价格区间内取高值。
- 明显偏后期、低等级较弱且依赖特定属性才能发挥的武器，可以在该品质价格区间内取低值，但优先通过内容池权重控制投放。
- 商店直接出售 3 级或 4 级武器时，不应低于推荐价格倍率；否则会削弱合成和逐步成长的价值。
- 折扣、商店价格倍率和内容池倍率属于入口价格修正，不应改变武器自身基础价。

## 9. 怪物

### 9.1 数值定位

怪物数值用于决定局内压力来源。怪物设计应先区分“基础怪物面板”和“局内推进缩放”：

- 基础怪物面板用于定义该怪物在 1 波附近的基础定位。
- 局内推进缩放根据波次统一提供，不改变基础怪物面板。
- Boss、精英、快速、远程等额外压力通过额外压力倍率表达。

怪物强度至少由生命、攻击、攻速、移速、攻击释放入场范围、攻击实际覆盖范围、攻击前摇、命中稳定性和刷怪数量共同决定。不要只看单个 `Attack` 或 `MaxHealth`。

### 9.2 基础参数

怪物基础属性优先使用以下参数：

| 参数 | 单位 | 说明 | 粗略配置边界 |
| --- | --- | --- | --- |
| `MaxHealth` | 点数 | 怪物基础生命。决定清怪时间和聚怪压力。 | 普通怪 20-180，Boss 单独配置。 |
| `Attack` | 点数 | 怪物单次基础伤害入口。普通攻击默认读取该属性。 | 普通怪 8-40，远程与高命中怪偏低。 |
| `AttackSpeed` | 攻速点 | 普通攻击频率，`100` 表示每秒攻击 1 次。 | 普通怪 25-120，高前摇怪可更低。 |
| `MoveSpeed` | 距离点/秒 | 移动速度，`100` 表示每秒 1 格。 | 普通怪 180-650。 |
| `AttackRange` | 距离点 | 敌人范围判定的唯一基础属性，同时用于攻击入场、近战伤害区域、范围查询半径或投射物最大飞行距离。 | 近战 120-240，远程 600-1000；Boss 技能按倍率单独评估。 |
| `Armor` | 点数 | 护甲，适合少量用于重型或 Boss。 | 普通怪默认 0，重型 2-8，Boss 8-20。 |
| `KnockbackResistance` | 百分比点 | 击退抗性。用于避免重型怪或 Boss 被高频击退完全锁死。 | 普通怪 0-30，重型 20-60，Boss 60-100。 |

敌人默认会持续追踪或站位，不再通过独立检测范围决定是否发现玩家。距离型攻击、技能或行为分支的入场判定统一读取 `AttackRange`，并可叠加攻击自身的显式范围倍率。

Boss 远程投射物需要额外检查射程倍率。近战攻击可以让近战倍率同时放大入场距离和命中覆盖；远程射击也必须让射击范围倍率同时放大释放入场距离和投射物最大飞行距离。

### 9.3 行为参数影响评估

怪物基础属性不能脱离行为参数单独评估。相同 `Attack` 和 `AttackSpeed` 下，前摇、后摇、命中范围和追踪稳定性不同，实际威胁可能相差很大。

| 行为参数 | 强度影响 | 数值处理建议 |
| --- | --- | --- |
| 攻击前摇短 | 玩家反应窗口更短，实际命中率更高。 | `Attack` 和 `AttackSpeed` 都要更保守；短前摇高频攻击不要再叠高单次伤害。 |
| 攻击后摇短 | 怪物更快恢复追击或连击，持续压迫更强。 | 降低 `AttackSpeed` 或减少单次 `Attack`，避免动作循环过密。 |
| 命中盒大 / 扫掠角广 | 覆盖更多玩家走位空间，近战等效射程更高。 | 按目标覆盖率提高计入威胁预算，必要时降低 `Attack` 或延长前摇。 |
| 攻击可追踪 / 可转向 | 玩家横移躲避难度更高，命中稳定性更强。 | 降低伤害或频率；强追踪不应同时配高移速和短前摇。 |
| 远程弹速快 / 弹体大 | 反应时间减少，远程实际命中率提高。 | 降低 `Attack`、`AttackSpeed` 或弹幕数量，避免远程怪成为不可读伤害源。 |
| 冲锋、跃击、瞬移 | 同时提高接触压力、位移压力和命中窗口。 | 基础面板留预算，不要再拿满普通近战的生命、伤害和攻速。 |
| 多段命中 / 持续区域 | 单次动作可能造成多次伤害或长时间封路。 | 按预期命中段数和区域覆盖率折算，不按一次攻击计价。 |

粗略评估时，可把行为参数折成命中可靠性和覆盖率：

```text
实际伤害压力 = Attack * (AttackSpeed / 100) * 命中可靠性 * 覆盖率
```

前摇越短、命中越稳定、覆盖越大，`Attack` 和 `AttackSpeed` 越要保守。行为强度已经很高的怪物，优先通过出现数量、出现波次和奖励权重表达价值，不要继续堆基础面板。

### 9.4 1 波基准模板

以下是 1 波附近的粗略基准。1 波普通怪应尽量让大部分 1 级武器可以一击击杀或接近一击击杀，前期压力主要来自数量、包围和移动，而不是厚血。后续具体怪物可以围绕模板上下浮动，但同一只怪不要同时拿满生命、伤害、速度、射程和命中稳定性。

| 怪物定位 | `MaxHealth` | `Attack` | `AttackSpeed` | `MoveSpeed` | `AttackRange` | 说明 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 普通近战 | 25-45 | 12-22 | 60-90 | 300-450 | 120-190 | 默认压力单位，1 波应大多能被常规武器一击击杀。 |
| 重型近战 | 70-120 | 22-40 | 35-65 | 180-320 | 150-240 | 承担阻挡和压迫，早期也不应厚到拖慢节奏。 |
| 快速追击 | 18-35 | 8-16 | 80-120 | 450-650 | 120-220 | 110-170 | 用贴身速度制造威胁，生命和单次伤害要低。快速怪不能靠过大的攻击入场距离提高命中。 |
| 远程怪 | 25-50 | 10-22 | 25-60 | 180-320 | 700-1100 | 600-1000 | 用攻击距离制造走位压力，生命和攻速保守。 |
| 特殊怪 | 45-90 | 10-28 | 35-80 | 220-420 | 500-900 | 120-800 | 依赖技能、召唤、冲锋或区域效果时，基础面板要留预算。 |

### 9.5 波次缩放

普通怪的基础面板不直接写后期数值。后期强度由波次缩放统一提供，默认围绕 20 波目标：

| 波次 | 难度系数 | 生命倍率 | 攻击倍率 | 移速倍率 | 攻速倍率 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 |
| 5 | 1.25 | 1.35 | 1.10 | 1.00 | 1.00 |
| 10 | 1.75 | 2.20 | 1.32 | 1.04 | 1.08 |
| 15 | 2.55 | 3.80 | 1.68 | 1.08 | 1.16 |
| 20 | 3.60 | 6.00 | 2.10 | 1.12 | 1.25 |

生命是主要后期承压项，攻击是次级承压项。由于 1 波基础生命会更低，生命曲线需要比当前基础值更陡，让中后期清怪压力真正回到生命池和数量上。移速和攻速属于手感风险项，增长必须比生命和攻击更克制，避免后期变成不可读、不可躲的贴脸压力。

### 9.6 波次规模与压力预算

波次压力由单体属性和刷怪规模共同决定。单波持续时间、生成频率、每批生成数量、最大生成批次和波内生成时间段共同决定刷怪密度。配置波次时必须同时看单体怪物、总数量、同屏数量、时间分布和生成位置。

默认 20 波模式按 `16-18` 分钟总战斗时长设计。普通波从 `40` 秒逐步增长到 `55` 秒，节点波可以延长到 `60-75` 秒。波次时长是经济、经验、掉落和商店频率的基础，不应为了贴合临时配置缩短到 `30` 秒。

关键波次刷怪规模目标：

| 波次段 | 持续时间 | 总刷怪数量 | 每分钟刷怪密度 | 目标同屏数量 | 波次总生命池 | 波次总伤害压力 | 精英 / Boss 节奏 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 1-4 | 40 秒 | 45-85 | 68-128 | 10-22 | 1200-4200 | 180-500 | 不出现精英；只用数量教会移动和清怪。 |
| 5-9 | 45-50 秒 | 95-170 | 115-225 | 20-38 | 7000-20000 | 650-1600 | 5 波可放 1 个低压精英或重型目标。 |
| 10-14 | 50-60 秒 | 180-300 | 216-360 | 34-58 | 30000-85000 | 1800-4200 | 10 波进入首个 Boss 或强精英节点。 |
| 15-19 | 55-65 秒 | 300-460 | 327-502 | 52-82 | 95000-260000 | 4200-9000 | 15 波 Boss/精英组合，17-19 波可提高精英频率。 |
| 20+ | 75 秒 | 460-680 | 368-544 | 70-110 | 240000-620000 | 8500-18000 | 20 波 Boss + 精英压力，终局允许短时间超载。 |

参数口径：

- 总刷怪数量是该波实际生成的敌人总数，包含普通怪、快速怪、重型怪、精英和 Boss。召唤物如果提供经验或掉落，也应计入总量。
- 每分钟刷怪密度 = 总刷怪数量 / 波次持续秒数 * 60。用它对比不同时长波次，而不是只看总数。
- 总刷怪数量应随时长提高，但每分钟密度不应无限抬升。后期主要通过生命池、精英比例、组合压力和短时间峰值制造难度。
- 目标同屏数量是正常清怪构筑下的平均压力区间，不是硬性上限。短时间峰值可以超过目标，但超过 `1.5x` 时应确认性能、碰撞、寻路和可读性。
- 波次总生命池 = 所有敌人的实际生命总和，包含波次缩放、精英/Boss倍率和刷怪标签压力。
- 波次总伤害压力 = Σ 单体伤害压力 * 预期接触率。它只用于横向比较，不代表玩家必定承受的实际伤害。

波内时间分布用于决定同一波压力如何释放。总数量和总生命池相同的两波，如果一波均匀生成，另一波在中段集中爆发，实际强度会完全不同。配置波次时必须填写时间段、生成占比、压力倍率和精英/Boss 插入点。

普通波默认分段：

| 波内阶段 | 时间占比 | 生成数量占比 | 密度倍率 | 主要用途 | 说明 |
| --- | ---: | ---: | ---: | --- | --- |
| 起压段 | `0%-20%` | `10%-15%` | `0.50-0.75x` | 建立方向、给玩家拾取和站位时间。 | 不放高压远程、精英或高速夹击。 |
| 主压段 | `20%-65%` | `45%-55%` | `1.00-1.25x` | 承载该波主要普通怪和构筑检验。 | 大多数怪物应在这里稳定出现。 |
| 峰值段 | `65%-85%` | `25%-35%` | `1.40-1.80x` | 制造包围、密度或精英配合压力。 | 峰值段不要同时堆满高数量、高移速、高远程覆盖和精英。 |
| 收尾段 | `85%-100%` | `5%-15%` | `0.40-0.90x` | 让玩家完成清场、拾取和处理残留威胁。 | 非终局波不应在最后几秒突然生成大量不可读压力。 |

节点波和 Boss 波可以使用不同节奏，但必须给入场和机制可读窗口：

| 节点阶段 | 时间占比 | 生成数量占比 | 设计口径 |
| --- | ---: | ---: | --- |
| 入场前缓冲 | `0%-15%` | `5%-10%` | 少量普通怪，给玩家调整位置和拾取。 |
| Boss / 精英入场 | `15%-30%` | `5%-15%` | 插入 Boss 或精英，普通怪密度短暂回落。 |
| 混合压力 | `30%-75%` | `55%-70%` | 普通怪维持清怪压力，Boss/精英提供单体与走位压力。 |
| 终段压力或回落 | `75%-100%` | `15%-25%` | 20 波可提高终段压力；普通节点波应给清场窗口。 |

时间分布验算公式：

```text
阶段持续秒数 = 波次持续秒数 * 阶段时间占比
阶段生成数量 = 总生成数量 * 阶段生成数量占比
阶段每分钟密度 = 阶段生成数量 / 阶段持续秒数 * 60
阶段密度倍率 = 阶段每分钟密度 / 全波每分钟密度
```

常规波峰值段密度建议不超过全波平均密度的 `1.8x`；节点波和终局波可以短时间到 `2.2x`，但必须降低同时段的远程覆盖、快速怪比例或精英数量。若峰值段同屏数量超过目标同屏上限 `1.5x`，应优先拉长阶段时间或降低该段生成占比，而不是继续提高怪物面板。

波次压力验算公式：

```text
单体生命池 = MaxHealth * 生命倍率 * 角色/标签生命倍率
单体伤害压力 = Attack * (AttackSpeed / 100) * 攻击倍率 * 攻速倍率 * 命中可靠性
波次总生命池 = Σ(单体生命池 * 生成数量)
波次总伤害压力 = Σ(单体伤害压力 * 生成数量 * 预期接触率)
每分钟刷怪密度 = 总生成数量 / 波次持续秒数 * 60
清场需求 DPS = 波次总生命池 / 波次持续秒数
```

推荐命中可靠性和接触率粗估：

| 怪物类型 | 命中可靠性 | 预期接触率 | 说明 |
| --- | ---: | ---: | --- |
| 普通近战 | 0.25-0.45 | 0.15-0.35 | 主要靠数量和包围制造压力。 |
| 快速追击 | 0.35-0.60 | 0.25-0.50 | 速度高，实际接触率更高，单体伤害要保守。 |
| 重型近战 | 0.20-0.40 | 0.10-0.25 | 更多承担阻挡和挤压，不一定频繁命中。 |
| 远程怪 | 0.30-0.55 | 0.25-0.60 | 取决于弹速、预警、弹体大小和攻击间隔。 |
| 精英怪 | 0.40-0.70 | 0.30-0.65 | 应有明确威胁，但不能不可读。 |
| Boss | 0.45-0.75 | 0.35-0.75 | 技能窗口、场地控制和阶段节奏比普攻面板更重要。 |

刷怪结构建议：

- 1-4 波以普通近战和少量快速怪为主，目标是让玩家学会移动和拾取，不用远程、精英或高密度特殊怪压迫。
- 5-9 波开始加入重型怪或低压精英，检验单体输出和绕行能力。
- 10-14 波开始加入 Boss 或强精英节点，同时保持普通怪密度，检验构筑的单体与群体兼容性。
- 15-19 波允许混合快速、远程、重型和精英，但同一波不要同时拿满高移速、高远程覆盖、高生命和高数量。
- 20 波可以作为终局压力峰值，但仍要给玩家可读窗口。Boss 技能、精英、密度和生成位置不应全部在同一时间堆满。

生成位置预算：

- 地图边缘持续生成适合普通怪和包围压力，数量可以高，但不应把远程怪稳定刷在玩家视野外立即攻击。
- 地图随机生成适合事件和突袭，但应控制预警、距离和数量，避免玩家被不可预读地贴脸。
- 多方向夹击会显著提高接触率；如果同波已经提高数量和移速，夹击频率要保守。
- Boss 或精英入场时，普通怪密度应给短暂回落窗口，除非该波明确是终局超载波。

### 9.7 额外压力倍率

额外压力倍率只叠加在波次缩放结果上，不应替代怪物基础面板设计。

| 来源 | 默认加成 | 说明 |
| --- | --- | --- |
| Boss | `MaxHealth * 1.60`，`Attack * 1.25` | Boss 主要提高生命池和伤害威胁，不默认提高移速和攻速。 |
| Elite | `MaxHealth * 1.30`，`Attack * 1.18` | 精英需要明显高于普通单位，但仍不应等同于新怪物模板。 |
| BossLike | `MaxHealth * 1.45`，`Attack * 1.18` | 用于波次中的类 Boss 压力单位，介于精英和 Boss 之间。 |
| Ranged | `Attack * 1.05` | 远程威胁来自距离和命中窗口，伤害倍率只小幅提高。 |
| Fast | `MoveSpeed * 1.08` | 快速标签只提供小幅速度压力，不能再叠太高基础移速。 |

如果某个怪物基础定位本身已经是高生命、高伤害或高速定位，对应额外倍率应保守使用，避免同一压力重复叠加。

### 9.8 评估流程

评估怪物数值时按以下顺序：

1. 先确定怪物定位：普通近战、重型近战、快速追击、远程怪、特殊怪或 Boss。
2. 按 1 波基准模板确定基础面板。
3. 确认敌人范围相关行为统一使用 `AttackRange`，攻击自身倍率同时影响入场距离和实际覆盖。
4. 再按攻击动作评估实际威胁：前摇越短、命中越稳定、覆盖越大，`Attack` 和 `AttackSpeed` 越要保守。
5. 放入波次池前，先按目标击杀时间检查单体强度。
6. 最后按波次规模与压力预算调整数量、权重、标签、出现时间和生成位置，不用基础属性硬塞所有强度。

粗略验算可以先使用：

```text
单体生存压力 = MaxHealth * 生命倍率
单体伤害压力 = Attack * (AttackSpeed / 100) * 攻击倍率 * 攻速倍率
接触压力 = MoveSpeed * 数量 * 命中稳定性
```

这些公式只用于横向比较，不代表最终体验。最终仍要结合刷怪数量、生成位置、攻击前摇、玩家可躲空间和掉落节奏一起验证。

## 10. 数值设计填表模板

本节是给设计者直接填表用的模板。新增升级卡、饰品、武器、怪物、波次、商店或奖励内容时，应先填模板，再进入正式配置。模板中的 BP、DPS、EHP、权重和价格都允许后续实测修正，但不能空缺。

填表时应区分配置列和校验列。配置列是后续会进入资产或表格的数据，例如属性、权重、价格、波次条件；校验列只服务数值审查，例如 BP、DPS、EHP、击杀时间、密度倍率。校验列可以由表格公式计算，但不能替代配置列。

### 10.0 表格拆分总览

建议先按下面的表格粒度拆分，不要把所有内容塞进一张大表。主表负责定义对象身份和定位，明细表负责定义等级、波次、属性列表或池内权重。

| 表格 | 行粒度 | 核心配置列 | 主要校验列 | 说明 |
| --- | --- | --- | --- | --- |
| 升级卡表 | 每张升级卡 1 行 | ID、稀有度、方向、属性、数值、开放波次、基础权重、重复权重调整 | 属性 BP、修正后 BP、稀有度偏差 | 设计口径只放纯属性，不代表代码容器只能承载属性 Feature。 |
| 饰品表 | 每件饰品 1 行 | ID、品质、定位、属性列表、机制、价格、重复口径、入口、权重、开放波次 | 正向 BP、负向回收、机制 BP、最终 BP、参考价格偏差 | 饰品允许属性组合和轻量机制，但必须写清入口和重复规则。 |
| 武器主表 | 每把武器 1 行 | ID、品质、主标签、副标签、定位、基础开放波次、基础权重、1 级价格 | 1 级总 BP、目标价格偏差 | 只放武器身份和整体定位，不放每级数值。 |
| 武器等级表 | 每把武器每级 1 行 | 武器 ID、等级、基础参数、四类攻击比例、收益率、持有者属性、等级价格 | 单体 DPS、群体修正、等效 DPS、等级价值倍率、价格偏差 | 武器核心数值都放在等级表，便于横向比较 Lv1-Lv4。 |
| 怪物主表 | 每种怪物 1 行 | ID、定位、基础面板、行为参数、奖励基准、默认标签 | 单体生存压力、单体伤害压力、命中可靠性、接触率 | 只定义基础怪物，不把后期波次缩放写死进去。 |
| 怪物波次池表 | 每个怪物在某个波次段 1 行 | 怪物 ID、波次段、权重、数量占比、额外压力标签、生成位置、奖励修正 | 关键波次面板、目标击杀时间、压力贡献 | 负责决定怪物何时出现、出现多少、承担什么波次功能。 |
| 波次表 | 每波 1 行 | 波次 ID、持续时间、总数量、时间分布、敌人结构、精英/Boss 节奏、生成位置、经济目标 | 每分钟密度、峰值密度倍率、总生命池、清场需求 DPS、总伤害压力 | 波次表用于验证节奏，不直接替代怪物表。 |
| 商店内容池表 | 每个商品入口 1 行 | 内容类型、内容 ID、品质/等级条件、开放波次、基础权重、内容池价格倍率、幸运系数 | 期望出现率、价格偏差、高品质占比 | 控制可见性和价格入口，不改物品自身基础价。 |
| 掉落奖励池表 | 每个掉落来源或奖励池条目 1 行 | 来源、掉落率、掉落率上限、奖励池、产物、基础权重、幸运系数 | 期望金币、期望经验、期望宝箱、幸运放大倍率 | 用于控制击杀、宝箱、Boss 和波次奖励。 |
| 校验汇总表 | 每个关键波次或标准构筑 1 行 | 波次、构筑、武器状态、饰品数量、升级卡数量、经济状态 | DPS、群体 DPS、EHP、击杀时间、清场需求、购买量偏差 | 用于实测后回填，判断该调武器、怪物、经济还是波次。 |

通用字段建议：

| 字段 | 用途 |
| --- | --- |
| `ID` | 稳定唯一标识，不随显示名变化。 |
| `显示名` | 面向设计和 UI 的名称。 |
| `定位` | 该对象承担的数值功能，例如单体、范围、生存、经济、重型、快速。 |
| `开放波次` | 最早进入商店、掉落、奖励或波次池的时间。 |
| `基础权重` | 默认抽取权重，后续可被波次、幸运和重复规则修正。 |
| `价格倍率 / 内容池倍率` | 只用于入口价格，不改变对象自身 BP。 |
| `BP` | 价值预算，用于横向比较。 |
| `偏差原因` | 当 BP、价格、权重或开放波次偏离推荐值时必须填写。 |
| `备注` | 记录构筑定位、限制、实测问题和后续调整原因。 |

填表推荐顺序：

1. 先填升级卡和饰品，确定玩家通用成长池。
2. 再填武器主表和武器等级表，确定构筑入口和输出基准。
3. 再填怪物主表，确定基础敌人模板。
4. 再填怪物波次池表和波次表，确定数量、密度、时间分布和压力节奏。
5. 最后填商店内容池表和掉落奖励池表，用经济和可见性把构筑节奏拉回目标区间。
6. 每轮批量改表后，回填校验汇总表，再决定下一轮调属性、价格、权重、怪物还是波次。
