# 饰品设计规范

本文档专门维护饰品的通用设计规则、价值口径、价格边界、命名、视觉基调与重复规则。

本文档只描述饰品规范，不包含具体样例。具体饰品条目见 `饰品设计稿.md`。

## 1. 价值参考

饰品的基础价值表示单件饰品允许承载的属性预算区间，不是每个品质固定一个值。饰品通常是长期持有项，并且可能通过商店、宝箱或奖励获得，因此不能只按升级卡片价值平移。

同一品质内允许出现低档、中档和高档饰品。价值越高，参考价格越高；品质只限定大致预算带，不把同品质所有饰品压成同一个价格。不同品质之间应保留明确间距，不建议把上下品质的预算带直接首尾相接，否则会削弱品质跳档的体感。

| 品质 | 基础价值范围 | 参考价格范围 |
| --- | ---: | ---: |
| Common | 80-110 BP | 20-28 金币 |
| Rare | 150-180 BP | 38-45 金币 |
| Epic | 230-280 BP | 58-70 金币 |
| Legendary | 330-600 BP | 83-150 金币 |

参考价格按实际价值计算：

```text
饰品参考价格 = round(饰品实际价值 BP / 4)
```

价格可以按获取入口、可选性、负面属性、机制强度和唯一性微调，但不应脱离实际 BP 太远。若价格明显偏离参考价，应在配置说明或设计记录中写明原因。

纯属性饰品可以直接按属性价值表计算。机制型饰品需要额外预算，例如 2.2 表中的特殊机制或其他明显改变战斗规则的效果。

## 2. 设计原则

饰品是长期持有的构筑部件，设计目标不是复刻升级卡片，而是提供稳定方向、局部偏科或带代价的玩法倾向。饰品数值应先按属性价值表折算 BP，再按金币购买力估算参考价格。

基础流程：

1. 先计算所有正向属性的 BP。
2. 再扣除负面属性回收的 BP。
3. 如果包含机制效果，额外加入机制预算。
4. 对照饰品品质的基础价值区间。
5. 按 `1 金币 = 4 BP` 得到参考价格，再根据实际获取入口修正。

命名与文案：

- 饰品名称建议控制在 `2-10` 字之间，并刻意打散长短与节奏，避免全表读起来像同一模板。
- 同一批饰品中，应混用简短名词、偏功能名、偏世界观名和少量带口语感的名称，避免全都像系统组件名或全都像诗化绰号。
- 配表字段统一使用 `描述`，不使用 `备注` 作为面向内容的数据字段。
- `描述` 用于补充介绍、吐槽、世界观短句或人物口吻，应能直接作为装备附加文本使用。

视觉风格基调：

- 饰品统一按“可装备的被动道具”来理解，强调它们会进入构筑、长期持有并持续影响战斗体验，而不是产品海报或写实实物摄影。
- 视觉上要有明确的功能方向、清晰的主形态和稳定的识别轮廓，让人一眼能认出它是什么、偏什么方向，但不要把它收束成过于抽象或过于通用的 UI 零件。
- 造型上优先采用强剪影，让主体在缩略图和远距离预览里也能保持一眼可读。
- 饰品图默认只画道具本体，不直接把饰品名称、描述文案、价格、属性词条或其他 UI 说明文字放进图里；除非明确要做带字宣传图、卡面成品或整套 UI 展示，否则一律按“无字道具图”处理。
- 边框语言优先使用双描边霓虹边框，保留项目现有的黑底高对比、热粉/电蓝/紫色主色、锐角科技线条、留白充足、层级清晰的视觉语法。
- 默认就应加强图形化分色、粗黑外轮廓、双层霓虹描边、少量漫画式切面高光和局部街头贴纸 / 改装感，而不是单纯提高发光强度或堆更多机械细节。
- 材质表达应尽量克制，少做复杂材质叠加，少做金属、玻璃、皮革等写实细节，更多依靠轮廓、描边和色块来成立。
- 结构表达应尽量简化，少堆结构细节，避免把饰品画成零件剖面、工业产品图或过度复杂的机械总成。
- 整体气质应带有明确的漫画风，允许夸张、锐利、轻涂鸦和轻街头感，但不要走写实摄影或厚重 3D 产品海报路线。
- 赛博感默认应通过“高饱和热粉 / 电蓝 / 紫色的明确分区、锐利切线、贴纸改装感、局部脉冲窗 / 配重槽 / 校准点 / 警示片”等视觉语汇建立，不要把“赛博”理解为“更像写实 3D 工业设计图”。
- 猫脸、心形、闪电、星星、X 号、警告标记这类小装饰仅作为可选语汇，需要时可少量加入，不是默认必带元素，也不应抢主体。
- 生成时不要先从“几何发光图标”出发，而要先从“物件原型”出发。先想清楚这件饰品在世界里究竟像什么，再用项目现有的霓虹视觉语法去表达它。
- 不要把饰品画成 3D 产品海报、厚重材质特写或复杂场景摆拍；不要让它看起来像一件被单独展示的真实道具。
- 同一批饰品不应只是换一个中心符号或换一套边框，而应来自不同的道具原型家族，让玩家一眼就能感到它们不是同一类物件换皮。
- 优先使用“功能性物件”而不是“抽象能量徽章”作为想象起点。它可以夸张、漫画化、赛博化，但仍应保留可辨认的现实或幻想物件影子。

  - 娱乐与媒介类：录像带、磁带、唱片、投影片、节目票根、海报卷筒、荧光麦克风头、舞台通行牌、应援灯棒、街演收音器、袖珍拍立得、拼贴相框、漫画剪报、录影模组、广播徽记、掌机卡带
- 同一件饰品应先有“物件身份”，再有“属性身份”。例如它先是一个输液舱、增压阀、义眼或军牌，然后才是加生命、加攻速或加暴击的东西。
- 高品质不等于把道具升维成“展示型神器”或“大型装置”。Epic 和 Legendary 允许更强的轮廓张力、更鲜明的稀有感和更克制的能量点缀，但仍应首先读成可携带、可佩戴、可安装的小型饰品、挂件、模块、盒、片、匣、镜片、阀芯、义体接口或便携器件。
- 当提示词中出现“核心、反应炉、王座、主阀、母核、神谕、巨型、巨大、祭坛、圣像、树状结构”等强烈诱导大体量或海报感的词时，必须同时补充“小型便携饰品 / 贴身模块 / 装备图标 / 非大型设备 / 非展示圣物”的约束，避免模型自动放大尺度、堆叠材质和增加对称构图。
- 常用的视觉母提示词如下：

```text
黑底霓虹赛博风，可装备的被动道具，小型随身饰品或贴身模块，强剪影，扁平与半图标化表达，高对比热粉/电蓝/紫色主色，锐角科技线条，双描边霓虹边框，留白充足，轮廓清晰，层级明确，少材质、少结构细节，整体干净、克制、漫画风、辨识度高；先定义清楚它属于哪一种物件原型，再用项目现有的霓虹视觉语法去表达它；可按需要少量加入街头感、涂鸦感或装饰符号，但不要默认堆满；不要 3D 产品摄影感，不要写实材质堆叠，不要复杂背景，不要大型装置感，不要祭坛感，不要神像感，不要圣物陈列感，不要把所有饰品都做成同一种抽象徽章。
```

- 建议在母提示词后固定追加一段风格强化，而不是只追加“更炫”或“更亮”：

```text
进一步强化漫画感与赛博感：更粗更明确的外轮廓，更图形化的分块与分色，更少真实结构缝隙，更强的贴纸改装感、街头感与高饱和霓虹分区；允许少量漫画式切面高光、速度感切线、灼痕、脉冲窗、校准点或配重槽，但不要变成写实机械渲染图、真实医疗照片感或厚重 3D 反应炉。
```

- 为了降低“脱离上下文后模型自动跑偏”的概率，默认应优先使用下面这段“无上下文稳态母提示词”，而不是只给一个饰品名字或只给一两个抽象关键词：

```text
这是一件用于游戏 UI 的可装备被动道具原型图，只画道具本体，不带文字，不带说明，不带价格，不带卡面；
它必须首先读起来像一件小型随身饰品、贴身模块、挂件、盒、片、匣、镜片、阀芯、义体接口或便携器件，而不是大型设备、场景装置、祭坛、圣物、神像或产品海报主物体；
整体采用黑底霓虹赛博风，强剪影，扁平与半图标化表达，高对比热粉 / 电蓝 / 紫色主色，锐角科技线条，双描边霓虹边框，轮廓清晰，留白充足，层级明确，少材质、少结构细节，整体干净、克制、漫画风、辨识度高；
先明确它属于什么具体物件原型，再表现它的属性方向；它必须让人一眼看懂“这是什么物件”，不能只是抽象发光核心、抽象徽章、抽象环形装置或抽象能量团；
允许少量局部能量发光、少量街头感、少量装饰符号，但不要默认堆满；默认优先强化粗黑描边、双层霓虹描边、图形化分色、少量贴纸改装感和漫画式切面高光，而不是增加写实材质；不要复杂背景，不要写实摄影感，不要厚重 3D 材质，不要大体量结构，不要过多管线、腔体、翅片、王座结构、祭器结构或树状外延。
```

- 为了保证所有品质都落在同一种饰品原型语言里，建议在母提示词后固定追加一段统一约束，而不是只在某些品质上额外补限制：

```text
这始终是一件可携带、可佩戴、可安装的小型饰品或便携模块，缩小后也必须一眼可读；
不要把它做成大型装置、场景机关、终极反应炉、展示型神器、神秘祭器或厚重机械总成；
允许轮廓、稀有感、能量强调和构筑气质有所变化，但不允许偏离“小型装备图标”的本质。
```

生成提示词补充规则：

- 提示词至少要同时包含这三层信息：功能方向、物件原型、视觉风格。
- 只写“发光核心、环形装置、模块、徽章、晶核”很容易导致同质化；必须补上更具体的原型锚点。
- 同一批图不要连续使用同一种轮廓语法，例如连续多个圆盘、护盾、八边形徽章或斜向芯片。
- 应主动混用不同的轮廓家族，例如细长型、厚重块状型、竖向舱体型、片状型、工具型、容器型、器官型、挂牌型、义体植入型，但最终都要落回清晰、可读、可辨认的风格化表达。
- 如果一件饰品的外观无法一句话说清“它是什么”，那通常说明原型还不够具体，继续生成只会越来越像抽象图标。
- 提示词里不要只写抽象风格词；应默认补上可执行的画面语汇，例如“粗黑描边、双层霓虹描边、图形化分块、高饱和霓虹分区、少量漫画式高光、贴纸改装感、街头赛博感”，让模型知道该往“图标化插画”而不是“真实工业渲染”收敛。
- 如果某个饰品表面可能需要文字、编号、标签或警示信息，应尽可能少，只保留少量必要信息，避免大段文本抢走主体识别、破坏轮廓阅读或让图标缩小时变脏。
- 不同品质之间允许有轮廓张力、局部能量强调、稀有感和构筑气质的差异，但不应通过“更多腔体、更多管线、更厚重材质、更像终极反应炉或神秘祭器”的方向来制造差别。
- 如果原型名称带有较强世界观词汇，应优先把它改写成小型部件说法，例如把“巨大视网膜镜”改成“义眼镜片模块”，把“巨型主阀”改成“厚重阀芯挂件”，把“母核”改成“封存法术匣核心”，把“树状结构”改成“骨枝中继簇”。
- 如果提示词里出现容易诱导“大型化、对称化、圣物化、海报化”的词，例如“核心、反应炉、器官、王座、神谕、母核、古神、巨型、祭坛、圣像、树状、主阀、终端、中枢”，必须同步写明“小型便携饰品 / 贴身模块 / 装备图标 / 非大型设备 / 非展示圣物 / 非场景装置”。
- 生成时优先使用“物件原型 + 功能方向 + 风格约束 + 负面排除”的完整结构；不要偷懒只发一个名字让模型自由发挥。
- 提示词应优先补“黑市医疗电子匣、街头改装贴片、配重槽、脉冲观察窗、校准点、警示片、荧光灼痕”这类具体结构词，而不是笼统写“更未来、更科幻、更高科技”。
- 提示词应优先补“更粗外轮廓、更夸张轮廓张力、更图形化分色、更少真实结构缝隙、更像游戏道具 icon concept”这类约束，而不是笼统写“更像漫画”。
- 提示词应同步加负面排除，例如“不要真实机械渲染图 / 不要真实医疗照片感 / 不要厚重 3D 反应炉感 / 不要产品海报感”，否则模型很容易把“赛博”误解成“更写实、更厚重、更复杂”。
- 如果是批量生成，同一批中应主动打散轮廓语法、原型家族和体块关系，避免模型把整批内容收束成同一种“圆形核心”或“对称徽章”模板。

推荐提示词结构：

```text
这是一件可装备的被动道具，主要功能方向是 <输出 / 攻速 / 暴击 / 生命 / 回复 / 防御 / 范围 / 移动 / 幸运 / 召唤 等>；
它的物件原型是 <输液舱 / 军牌 / 增压阀 / 义眼模块 / 人工心室 / 燃料电池 / 神经插栓 / 修复贴片 / 反应器 / 护身符盒 / 黑市药盒 / 战地识别牌 等>；
整体采用项目现有的黑底霓虹赛博风，扁平与半图标化表达，高对比热粉/电蓝/紫色主色，锐角科技线条，双层描边，轮廓清晰，留白充足，层级明确，并默认强调粗黑描边、图形化分色、贴纸改装感、少量漫画式高光和更鲜明的霓虹分区；如有需要，可少量加入街头感、涂鸦感或装饰符号，但不是默认必带；它仍然必须读起来像一件小型随身饰品、贴身模块或装备图标；不要 3D 物件海报感，不要写实摄影感，不要复杂背景，不要大型设备感，不要祭坛感。
```

- 推荐在实际出图时把提示词写成下面这个更完整的模板，尤其适合“没有额外上下文，只能靠文档本身”的情况：

```text
这是一件用于游戏 UI 的可装备被动道具原型图，主要功能方向是 <属性方向>；
它的物件原型是 <具体物件原型>，必须先让人一眼认出这是什么物件，再让人感受到它偏向什么属性；
它是小型随身饰品 / 贴身模块 / 挂件 / 盒 / 片 / 匣 / 镜片 / 阀芯 / 义体接口 / 便携器件，不是大型设备，不是场景装置，不是祭坛，不是神像，不是展示圣物；
整体采用黑底霓虹赛博风，强剪影，扁平与半图标化表达，高对比热粉 / 电蓝 / 紫色主色，锐角科技线条，双描边霓虹边框，轮廓清晰，留白充足，层级明确，少材质、少结构细节，漫画风，辨识度高；如果想更偏漫画 / 更偏赛博，优先加强粗黑外轮廓、图形化分块、高饱和霓虹分区、少量贴纸改装感和漫画式切面高光；
允许根据具体定位调整轮廓张力、局部能量强调和稀有感，但不增加大体量结构，不增加复杂管线，不增加厚重腔体，不把它做成反应炉、祭器或机械总成；
只画道具本体，不带字，不带 UI 面板，不带复杂背景，不带写实摄影布光，不带产品海报感；不要真实机械渲染图，不要真实医疗照片感，不要厚重 3D 反应炉感。
```

品质分布：

- 每个品质都应覆盖该品质允许的完整预算区间，不要把一整批内容都堆在某个窄档位。
- 同一批次设计时，建议同时包含低档、中档和高档样本；中高段可以略多，但不能让整批内容都贴着下沿。
- 如果某个品质长期只产出低档值条目，玩家会体感为“有品质但没强度差”；如果长期只产出高档值条目，则会压缩后续扩展空间。

品质边界：

- Common 以单一轻属性或单一轻方向为主，允许出现负属性来换取更有体感的正向收益，但仍应避免强机制或多个高价值属性同时出现。
- Rare 可以提供一个明确方向，允许一个主属性加一个低价值副属性，也允许引入中等价值负面属性来换取更强的主收益或更鲜明的构筑倾向。
- Epic 可以强化构筑倾向，但不应单独改变核心玩法结构。
- Legendary 可以承载构筑入口或高价值机制，但应有条件、代价、唯一性或明显方向。

价格修正：

- 商店可选性会提高实际价值，同等 BP 的饰品可以略高于参考价格。
- 宝箱或奖励可能绕过价格，因此不能只靠高价格平衡强饰品。
- 带负面属性、触发条件或低覆盖率的饰品可以低于参考价格。
- 经济收益、商店折扣和掉落收益类饰品要额外保守，因为它们会影响后续购买力。
- 允许少量负面属性，用来换取更有体感的正向收益；但负面必须真实影响构筑体验，不能只是形式上的装饰。
- 负面属性是可选手段，不是默认要求；高品质饰品允许存在纯正向大件，只要预算、价格、品质和获取入口能支撑其强度定位。
- 同一批次中应混合纯正向件、轻代价件、明显偏科件和少量高风险高收益件，避免整批内容都采用同一种“加收益再扣代价”的模板。

设计限制：

- 不要在低品质饰品中投放 2.2 表中的特殊机制。
- 不要把多个生存链路同时堆在同一件饰品上，例如高生命、高闪避、高减伤和高回复同时出现。
- 不要用高价格掩盖明显超预算的属性组合。
- 负面属性只能回收与其实际影响相符的 BP，不能用无关紧要的负面项抵消核心强机制。
- 饰品设计优先遵循“单一主方向、长期持有、可解释成本、可控重复”的原则；如果一件饰品需要靠多个高价值属性才能成立，优先拆分为多个独立饰品或降级为机制饰品。

## 3. 唯一性与重复

饰品默认可以重复获得，不因为已经持有同名饰品就从商店或奖励池中移除。是否唯一或限制持有数量只用于少数机制强度明显高于普通属性件的饰品。

| 饰品类型 | 默认重复口径 | 持有数量口径 | 说明 |
| --- | --- | --- | --- |
| 纯低值属性饰品 | 可重复 | 不设上限 | 例如低额生命、低额范围、低额移动速度。 |
| 明确构筑饰品 | 可重复 | 不设上限 | 例如高暴击、高攻速、特定攻击方向强化；通过 BP、价格、品质和权重控制强度。 |
| 复合生存饰品 | 可重复 | 不设上限 | 同时提供多条生存链路时，按 EHP 口径计价，但不默认限制持有数量。 |
| 经济饰品 | 通常可重复 | 按具体效果决定 | 折扣、经验、金币、掉落收益会滚雪球，应更依赖数值保守、品质、价格和权重控制。 |
| 中等或轻量机制饰品 | 按情况决定 | 不设上限或适量限制 | 例如轻量触发、低覆盖率机制、弱条件联动；如果叠加后改变玩法结构，应配置适量上限。 |
| 终极强机制饰品 | 默认唯一 | 1 | 额外武器槽、强制暴击等终局或强构筑入口。 |

重复饰品暂时不做额外价值衰减。设计时只按单件 BP、价格、品质、权重和波次开放评估；如果一件饰品重复后强度明显非线性放大，应优先把它归入机制饰品，并配置唯一性或适量持有上限。

商店和奖励池应能读取唯一性或持有数量规则。玩家已拥有唯一饰品时，该饰品不应继续进入普通商店、宝箱和奖励入口；如果需要转化，应明确转为金币、刷新券或同品质替代奖励。未配置唯一性和持有上限的饰品，默认允许继续出现。
