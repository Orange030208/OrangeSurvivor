# 界面动画系统配置指南

本文档说明项目内 UI 动画系统的配置方式、目标绑定规则，以及它和 LayoutGroup、动态生成 UI、卡牌动画之间的协作边界。

## 适用范围

- `UIMotionPlayer` 驱动的通用 UI 动画。
- `UIMotionDefinition` 中通过 Track 配置的显示、隐藏、悬停、按下、释放等动画。
- `CardMotionController` 驱动的卡牌类交互动画。
- 使用 LayoutGroup、ContentSizeFitter 或动态生成子项的 UI Prefab。

## 核心结构

### UIMotionDefinition

`UIMotionDefinition` 是动画数据资产，通常放在：

```text
Assets/GameContent/UI/Data/Motion/V2/
Assets/GameContent/UI/Data/Motion/V2/Generated/
```

它由多个 Clip 组成。每个 Clip 表示一个可播放动作，例如：

- `Show`
- `Hide`
- `Visible`
- `Hidden`
- `HoverIn`
- `HoverOut`
- `Press`
- `Release`
- `ClickPulse`

Clip 内部由多个 Track 组成。Track 是最小动画单元，只负责一个目标上的一种属性变化。

当前常用 Track 类型包括：

- `UIMoveMotionTrack`
- `UIScaleMotionTrack`
- `UIRotateMotionTrack`
- `UIAlphaMotionTrack`
- `UIGraphicColorMotionTrack`
- `UIImageFillMotionTrack`
- `UIMaterialColorMotionTrack`
- `UIMaterialFloatMotionTrack`
- `UISpriteSwapMotionTrack`
- `UISpriteSequenceMotionTrack`
- `UITMPTypewriterMotionTrack`
- `UICallbackMotionTrack`
- `UISidebarMotionTrack`

### UIMotionPlayer

`UIMotionPlayer` 是运行时播放入口。它挂在实际 UI 对象上，负责：

- 读取 `UIMotionDefinition`。
- 根据 ClipId 找到 Clip。
- 根据 Track 的 `targetKey` 解析目标对象。
- 播放 DOTween 动画。
- 管理不同 Channel 的冲突策略。
- 记录 Initial 快照，供 `Initial`、`InitialPlusOffset`、`InitialMultiplied` 等模式使用。

典型字段：

- `Definition`：动画资产。
- `Targets/Bindings`：目标绑定表。
- `Refresh Defaults On Enable`：启用时重新记录默认快照。
- `Stop All Channels On Destroy`：销毁时清理仍在播放的 Tween。

## Targets 和 Bindings

### targetKey 的含义

每个 Track 都有一个 `targetKey`。运行时会通过 `UIMotionTargetRegistry` 把这个 key 解析成真实 Transform。

默认 key 是：

```text
Self
```

如果不做任何绑定，`Self` 会指向 `UIMotionPlayer` 所在对象。

### Bindings 的作用

`UIMotionPlayer -> Targets -> Bindings` 是 key 到 Transform 的覆盖表。

例如：

```text
Key: Self
Target: VisualRoot
```

表示所有 `targetKey = Self` 的 Track 都不再作用于 `UIMotionPlayer` 所在对象，而是作用到 `VisualRoot`。

这常用于把动画从布局根节点转移到视觉根节点。

### 推荐 key 命名

项目内已有常用 key：

- `Self`
- `Root`
- `Front`
- `Back`
- `Frame`
- `Glow`
- `Title`
- `Description`

如果只是重定向原有动画，优先继续使用 `Self`。如果一个动画资产需要同时控制多个子对象，再新增语义化 key。

## 和 LayoutGroup 共存

LayoutGroup 会持续控制子物体的布局属性，例如位置、尺寸、排序和拉伸。动画系统如果同时修改同一个 RectTransform 的位置或缩放，就会产生互相覆盖。

### 错误结构

```text
LayoutGroup
└── Upgrade Container   <- LayoutGroup 控制，同时动画也修改它
```

这种结构中，动画 Track 如果作用到 `Upgrade Container`，就可能和 LayoutGroup 抢写 `anchoredPosition` 或尺寸。

### 推荐结构

```text
LayoutGroup
└── Upgrade Container   <- 只负责布局占位
    └── VisualRoot      <- 负责动画运动
        ├── Background
        ├── Icon
        ├── Text
        ├── Glow
        └── Shadow
```

外层 `Upgrade Container` 交给 LayoutGroup 管理。动画系统只操作 `VisualRoot` 或更深层视觉节点。

### Prefab 配置方式

在卡牌 Prefab 根对象上：

1. 保留 `UIMotionPlayer` 在 `Upgrade Container` 上。
2. 展开 `UIMotionPlayer -> Targets -> Bindings`。
3. 新增绑定：

```text
Key: Self
Target: VisualRoot
```

4. 确认 Motion 资产中的 Track 仍然使用 `targetKey: Self`。
5. 如果 Motion 资产包含 `UIAlphaMotionTrack`，确保 `VisualRoot` 上有 `CanvasGroup`。

这样动画资产不用改，所有原本作用到 `Self` 的动画会自动转到 `VisualRoot`。

## 卡牌动画配置

卡牌类 UI 通常使用 `CardMotionController`。

典型配置：

- `Motion Player`：同对象上的 `UIMotionPlayer`。
- `Profile`：对应的 `CardMotionProfileSO`。
- `Rest Root`：建议绑定到 `VisualRoot`，表示卡牌动画复位基准。
- `Dynamic Root`：建议绑定到 `VisualRoot`，用于悬停倾斜和待机浮动。
- `Shadow Root`：绑定 `Shadow`。
- `Shadow Canvas Group`：绑定 `Shadow` 上的 `CanvasGroup`。
- `Glow Canvas Group`：绑定 `Glow` 上的 `CanvasGroup`。

如果 `Auto Resolve Visual Root` 开启，`CardMotionController` 会尝试按名字查找 `VisualRoot`。但关键 Prefab 建议显式绑定，避免层级变化后静默失效。

## 动态生成 UI 的要求

动态生成的 UI Prefab 必须自包含所有动画依赖。

以奖励选择卡牌为例：

- 生成器只负责实例化卡牌 Prefab。
- 卡牌 Prefab 自己持有 `UIMotionPlayer`、`CardMotionController`、`CardQualityVisualController` 等表现组件。
- 卡牌 Prefab 自己配置 `Targets/Bindings`。
- 卡牌 Prefab 自己配置 `VisualRoot`、`Shadow`、`Glow` 等节点引用。

不要依赖场景中预先摆好的卡片实例来承载动画引用。否则运行时动态生成时会缺少绑定。

## Initial 快照规则

动画 Track 的 `Initial` 系列取值来自 `UIMotionTargetRegistry` 记录的快照。

快照记录时机：

- `UIMotionPlayer.Initialize`。
- `UIMotionPlayer.OnEnable`，当 `Refresh Defaults On Enable` 开启时。
- 主动调用 `UIMotionPlayer.RefreshDefaults()`。
- `CardMotionController.ConfigureForReuse()` 中根据 `CardMotionProfileSO.RefreshDefaultsOnConfigure` 刷新。

使用 LayoutGroup 时要注意：如果快照记录在 LayoutGroup 结算前，Initial 可能不是最终布局位置。动态 UI 通常应让布局根节点保持不动，只对 `VisualRoot` 记录和播放动画。

## 新增一个普通 UI 动画的流程

1. 创建或复用 `UIMotionDefinition`。
2. 配置 Clip，例如 `Show`、`Hide`、`HoverIn`。
3. 在 Clip 内添加 Track。
4. 给 Track 设置 `targetKey`。
5. 在 Prefab 的 `UIMotionPlayer -> Targets -> Bindings` 中配置对应 key。
6. 确认目标 Transform 上有 Track 需要的组件，例如 `RectTransform`、`CanvasGroup`、`Graphic`、`TMP_Text`。
7. 运行时通过 `UIMotionPlayer.Play(clipId)` 或业务控制器间接播放。

## 新增一个卡牌类 UI 动画的流程

1. 卡牌根对象作为布局占位节点。
2. 在根对象下创建 `VisualRoot`。
3. 把背景、图标、文本、光效、阴影放到 `VisualRoot` 或其子层级下。
4. 根对象添加或保留 `UIMotionPlayer`。
5. `UIMotionPlayer -> Targets -> Bindings` 配置：

```text
Key: Self
Target: VisualRoot
```

6. 如果 `Self` 动画里有透明度 Track，在 `VisualRoot` 上添加 `CanvasGroup`。
7. 根对象添加或保留 `CardMotionController`。
8. `CardMotionController` 显式绑定：

```text
Rest Root: VisualRoot
Dynamic Root: VisualRoot
Shadow Root: Shadow
Shadow Canvas Group: Shadow.CanvasGroup
Glow Canvas Group: Glow.CanvasGroup
```

9. 确认 `CardMotionProfileSO` 中的 ClipId 与 `UIMotionDefinition` 中的 ClipId 一致。
10. 在动态列表中只实例化 Prefab，不在代码中手动排版动画目标。

## 常见问题

### 卡片位置被 LayoutGroup 拉回

原因：动画作用到了 LayoutGroup 直接管理的子物体。

处理：

- 增加 `VisualRoot`。
- 把 `Self` 绑定到 `VisualRoot`。
- `CardMotionController.Rest Root` 和 `Dynamic Root` 也绑定到 `VisualRoot`。
- 如果透明度动画报警缺少 `CanvasGroup`，给 `VisualRoot` 添加 `CanvasGroup`。

### Hover 或 Press 没有效果

检查：

- `CardMotionProfileSO` 中的 ClipId 是否为空。
- `UIMotionDefinition` 是否包含对应 Clip。
- Track 的 `targetKey` 是否能在 `Targets/Bindings` 中解析到目标。
- 目标上是否有 Track 需要的组件。

### Reveal 每次复用状态不一致

检查：

- `CardMotionProfileSO.RefreshDefaultsOnConfigure` 是否符合预期。
- `UIMotionPlayer.Refresh Defaults On Enable` 是否开启。
- 动态生成对象是否在绑定完成后才播放动画。

### 动画资产引用了 Self，但实际应该动 VisualRoot

不需要改所有 Track。直接在 `UIMotionPlayer -> Targets -> Bindings` 中配置：

```text
Key: Self
Target: VisualRoot
```

这是推荐做法。

### 某个子层需要独立动画

不要复用 `Self`。新增语义 key，例如：

```text
Key: Glow
Target: Glow
```

然后把对应 Track 的 `targetKey` 改为 `Glow`。

## 配置检查清单

- Prefab 根对象是否只作为布局占位。
- 是否存在 `VisualRoot`。
- `UIMotionPlayer.Definition` 是否已配置。
- `UIMotionPlayer.Targets.Bindings` 是否把 `Self` 指向正确视觉节点。
- `Self` 指向的节点是否具备 Track 需要的组件，例如透明度 Track 需要 `CanvasGroup`。
- `CardMotionController.Profile` 是否已配置。
- `CardMotionController.Rest Root` 是否避开 LayoutGroup 直接控制的节点。
- `CardMotionController.Dynamic Root` 是否指向视觉运动节点。
- `Shadow`、`Glow` 引用是否完整。
- 动态生成 Prefab 是否不依赖场景中已有实例。
- 运行时播放前是否已完成必要的数据绑定和默认快照刷新。
