# 项目异味报告

生成时间: 2026-05-15 06:05:13 +08:00

审计范围: `Assets/Scripts` 核心运行时代码、Manager/Service/Controller、内容池链路、输入/设置链路、UI 框架核心、近期高频修改文件。

审计原则: 以当前代码实际行为为最高真实性来源。历史审计报告只作为对照，不作为当前事实。

## 总体结论

当前项目技术债等级为中高。主要风险不是单点语法错误，而是核心业务流程集中在少数大类中，目录看起来已经模块化，但编译层面没有 asmdef 边界。上轮已经修复的 `MonoSingletonBase`、旧 `GameInputService` 兜底加载、`PropertiesManager` / `AccessoryManager` 空引用问题，本轮不再作为当前缺陷列入。

本轮新增核对点:
- `GameContentRuntime` 与 `RunProgressionRuntime` 已具备 `SubsystemRegistration` reset 契约。
- `GameEventBus` 仍只有手动 `Clear()`，未看到自动生命周期清理。
- 内容历史持有者比上轮记录更分散: `ShopManager`、`RewardSelectionManager`、`DropManager`、`WaveSpawnExecutor`、`AddRandomWeaponCard` 均各自持有 `ContentHistoryState` 或静态历史。

## 异味分类索引

- God Object: `Weapon`, `UIManager`, `GameManager`。
- 过度耦合: `ShopManager` 购买路径，`SettingsPanelManager` 对输入/UI/显示/存储的直接耦合。
- 隐式依赖: `FindFirstObjectByType`, `GameInput.Instance`, `UIManager.Instance`, `GameContentRuntime.Provider`。
- 状态混乱: `RewardSelectionManager` 的队列/取消/暂停/弹窗状态，`GameManager` 的状态迁移版本/波末流程标志/暂停源集合。
- Update/Tick 热点: `Weapon.OnTick`, `WaveManager.Update`, `UIManager.Update`。这些并非全部滥用，但所在类职责过宽。
- 魔法值 / 魔法字符串: `Settings.*` PlayerPrefs key, `rewardSelection`, `popupGroup`, 属性修饰 `sourceId`, `ContentPoolScopeIds` 字符串作用域。
- 资源生命周期: `GameEventBus` 缺自动 reset；`GameInput` 使用 `DontDestroyOnLoad`，需要更明确的场景生命周期边界。

## 优先级建议

1. P0: 先拆 `Weapon` 攻击周期和 `GameManager` 主流程。两者是高频修改且回归成本最高的核心。
2. P1: 给 `GameEventBus` 增加自动 reset，并定版内容历史生命周期。
3. P1: 拆 `ShopManager` 与 `RewardSelectionManager` 的业务服务，移除购买和奖励流程中的全场景查找。
4. P2: 设置/输入链路显式依赖化，按平台配置修正校验规则。
5. P2: 分阶段引入 asmdef，让目录边界变成真实编译边界。
