# 架构风险报告

生成时间: 2026-05-21 06:15:26 +08:00

审计范围: 当前 Unity 项目的运行时架构、内容装配、主流程、UI 框架、数据导入、文档可信度和测试基线。

## 架构结论

当前架构可支撑短期迭代，但已进入 **中高风险维护区**。

项目有一些健康结构：`GameContentRuntime` 已使用 `SubsystemRegistration` reset；`GameContentCatalogSO.ValidateCatalog` 会阻断不完整 Catalog；内容池、局内推进、波末流水线、UI 框架、输入设置和战斗命中都有测试或局部抽象。当前 `dotnet build` 已通过。

主要问题是核心入口仍过大、运行时装配仍靠静态全局和场景查找、文档已经落后于实现。继续在这些大类中叠功能，会让后续每次玩法/UI/数值改动都触碰主流程和 UI 核心，回归成本会明显上升。

## SOLID 与边界评价

- 单一职责: `GameManager`、`UIManager`、`SettingsPanelManager`、`Weapon` 违反明显。
- 开闭原则: 内容池、Feature、波末流水线有扩展点；主流程、设置面板和武器运行时仍需要改核心类。
- 依赖倒置: 局部存在接口，但 `ShopManager`、`RewardSelectionManager`、`GameManager` 仍依赖具体 MonoBehaviour、静态入口和场景查找。
- 接口隔离: `IGameContentProvider` 相对清晰；UI 框架公开 API 较集中，内部实现过重。
- 里氏替换: 深层继承不是主要问题；主要风险是 MonoBehaviour 门面过大和静态状态。
