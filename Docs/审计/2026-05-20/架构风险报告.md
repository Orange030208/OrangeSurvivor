# 架构风险报告

生成时间: 2026-05-20 06:08:44 +08:00

审计范围: 当前 Unity 项目的运行时架构、内容装配、主流程迁移状态、文档可信度和核心模块边界。

## 架构结论

当前架构支撑短期迭代的能力已被 **迁移一致性风险** 明显削弱。项目有内容池、GameContentRuntime、局内推进、UI 框架、命中结算、对象池和 EditMode 测试等结构化模块；但主流程、场景装配、Catalog 资产和 UI 页面之间仍靠人工同步，导致删除角色选择流程时出现编译失败、Missing Script、Catalog 旧字段、文档旧流程同时存在。

短期必须先恢复“可编译、可启动、Catalog 可验证”的基本健康线。中长期再拆 `GameManager`、`Weapon`、`UIManager` 等高耦合核心。

## SOLID 与边界评价

- 单一职责: `GameManager`、`Weapon`、`UIManager`、`ShopManager`、`RewardSelectionManager` 明显超职责。
- 开闭原则: 内容池和 Feature 有扩展点；但主流程和默认角色/开局卡流程仍通过改核心类接入。
- 依赖倒置: 局部有接口，但主流程仍大量依赖具体 MonoBehaviour、静态入口和场景查找。
- 接口隔离: `IGameContentProvider` 正在变瘦，但资产迁移没有同步，说明接口变更缺迁移门。
- 里氏替换: 深层继承不是主要风险；主要风险是 MonoBehaviour 门面过大和静态状态。
