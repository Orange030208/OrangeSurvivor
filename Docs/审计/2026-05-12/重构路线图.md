# 重构路线图

生成时间: 2026-05-12 18:48:15 +08:00
目标: 优先降低崩溃风险，再收紧边界，最后拆大类

## 推荐顺序

### 0. 先修崩溃点

| 优先级 | 文件 | 目标 | 结果 |
|---|---|---|---|
| P0 | `Assets/Scripts/Entity/PropertiesManager.cs` | 缺少 `IPropGroupProvider` 时立即返回或提供空基底属性。 | 先消掉真实空引用。 |
| P0 | `Assets/Scripts/Entity/AccessoryManager.cs` | 初始饰品接口改成显式可选。 | 避免新实体/测试场景一挂就崩。 |
| P1 | `Assets/Scripts/Content/GameContentBootstrap.cs`、`Assets/Scripts/Content/GameContentCatalogSO.cs` | 校验失败阻断运行时。 | 让错误在入口暴露，不要延后到别的系统。 |

### 1. 建 asmdef 边界

| 优先级 | 文件/目录 | 目标 | 结果 |
|---|---|---|---|
| P0 | `Assets/Scripts/Core`、`Assets/Scripts/Gameplay`、`Assets/Scripts/UI`、`Assets/Scripts/Editor`、`Assets/Tests` | 按域拆程序集。 | 让依赖关系可见，减少伪模块化。 |
| P1 | `Assets/Scripts/OrangeUIFramework` | 作为独立框架程序集。 | 框架边界和业务边界分开。 |

### 2. 收口全局入口

| 优先级 | 文件 | 目标 | 结果 |
|---|---|---|---|
| P0 | `Assets/Scripts/Managers/MonoSingletonBase.cs` | 去掉自动创建对象。 | 入口更可控。 |
| P0 | `Assets/Scripts/Event/GameEventBus.cs` | 增加统一 reset 或限定作用域。 | 减少跨场景残留监听。 |
| P0 | `Assets/Scripts/Content/GameContentRuntime.cs`、`Assets/Scripts/RunProgression/RunProgressionRuntime.cs` | 只允许 bootstrap 显式注入。 | 把隐式状态改成显式状态。 |
| P1 | `Assets/Scripts/Input/GameInputService.cs` | 去掉 `Resources.Load` 兜底，改成场景或 bootstrap 绑定。 | 输入入口稳定下来。 |

### 3. 拆 Manager 主流程

| 优先级 | 文件 | 目标 | 结果 |
|---|---|---|---|
| P0 | `Assets/Scripts/Managers/GameManager.cs` | 拆成状态协调器、场景装配、暂停控制、UI 适配。 | 主流程不再一锅端。 |
| P0 | `Assets/Scripts/Managers/ShopManager.cs` | 拆出商品生成与购买执行。 | 购买和刷新不互相污染。 |
| P0 | `Assets/Scripts/Managers/RewardSelectionManager.cs` | 拆出奖励源和弹窗流程。 | 奖励队列更容易测。 |
| P1 | `Assets/Scripts/Managers/WaveManager.cs` | 拆出完成规则和刷怪执行。 | 新的波次规则更好接。 |
| P1 | `Assets/Scripts/UI/Instances/Child/SettingsPanelManager.cs` | 拆出设置状态、输入配置和确认弹窗。 | 设置页更容易维护。 |

### 4. 压缩重型运行时类

| 优先级 | 文件 | 目标 | 结果 |
|---|---|---|---|
| P1 | `Assets/Scripts/Weapons/Weapon.cs` | 把索敌、序列、投射物、命中窗口拆出去。 | 新武器类型更容易实现。 |
| P1 | `Assets/Scripts/OrangeUIFramework/Core/Runtime/UIManager.cs` | 拆出层级、池化、遮罩、诊断。 | UI 框架更容易演进。 |
| P1 | `Assets/Scripts/Entity/PropertiesManager.cs` | 拆出快照、累加器、映射器。 | 属性链路更清晰。 |

## 最值得先重构的部分

1. `PropertiesManager` 和 `AccessoryManager` 的崩溃点。
2. `GameManager` 的状态协调和场景装配。
3. `ShopManager` 与 `RewardSelectionManager` 的流程拆分。
4. `Weapon` 和 `UIManager` 的职责切片。

## 不建议现在做的事

- 不要先重写整套 UI 框架。
- 不要先给所有系统加一层更厚的抽象。
- 不要先碰没有证据支持的玩法重构。
- 不要在没有 asmdef 之前继续扩大默认程序集里的大类。
