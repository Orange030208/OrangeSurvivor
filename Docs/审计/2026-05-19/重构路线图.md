## 第一阶段建议

第一阶段只做 P0 和低风险 P1，不拆大类：

1. `GameEventBus` 自动 reset。
2. 数据导入默认禁删和报告落盘。
3. 修主文档旧术语。
4. 新增场景装配契约和 JSON 导入安全说明。

这些工作能立刻降低数据损坏、跨局状态污染和文档误导，不要求大规模改业务逻辑。

## 第二阶段建议

第二阶段处理高频变更类，但采用“先包边界、后搬逻辑”的方式：

1. `GameManager` 先抽纯状态机，不动 UI 页面实际打开方式。
2. `Weapon` 先拆 Gizmo/序列事件，保持攻击行为完全不变。
3. `ShopManager` 先把购买依赖从场景查找改成 Player context 注入。
4. `RewardSelectionManager` 引入 `RewardPauseScope`，先解决暂停成对释放。

## 第三阶段建议

第三阶段再做结构治理：

1. `UIManager` 内部拆分。
2. 敌人 Brain 脚手架统一。
3. 内容历史生命周期定版。
4. Combat modifier 缓存或注册化。
5. asmdef 分层。

## 回归测试建议

| 测试主题 | 推荐覆盖 |
| --- | --- |
| 事件总线 | reset 后无监听；订阅/退订 scoped 与 global 都正确。 |
| 数据导入 | Preview 有 deleteCandidates；默认 Apply 不删除；允许删除时报告列出删除路径。 |
