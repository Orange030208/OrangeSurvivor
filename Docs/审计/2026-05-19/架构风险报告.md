# 架构风险报告

生成时间: 2026-05-19 06:06:55 +08:00

审计范围: 当前 Unity 项目的运行时架构、Editor 数据导入架构、文档可信度和核心模块边界。

## 项目基线

- Unity: `2022.3.62f3c1`
- 渲染管线: URP `14.0.12`
- 主要依赖: UniTask、DOTween、NaughtyAttributes、Behavior Designer、Unity Input System、UGUI、MCP/UnitySkills。
- asmdef: `Assets` 下未发现业务 `*.asmdef`，自研代码主要编进 `Assembly-CSharp`。
- 自研目录信号: `Managers`、`Enemy`、`Entity`、`Weapons`、`Waves`、`Content`、`RunProgression`、`OrangeUIFramework`、`UI`、`Features`、`Combat`。

## 架构结论

当前架构还能支撑短期玩法迭代，但已经进入 **中高技术债** 区间。项目已经形成局部模块，例如内容池、波次执行、命中结算、UI 框架、局内推进；问题不在“完全没有架构”，而在模块边界靠约定维持，运行局级状态大量通过静态入口、事件总线和场景查找串联。

如果继续新增敌人、武器、奖励、主菜单和数值导入而不先收束核心边界，后续迭代会出现两类典型退化：

- 新功能为了接入主流程，不断改 `GameManager`、`Weapon`、`ShopManager`、`RewardSelectionManager`、`UIManager`。
- 文档无法指导开发，开发者只能 `rg` 和读大类源码，接手成本持续升高。

## SOLID 与边界评价

- 单一职责: `Weapon`、`GameManager`、`UIManager`、`ShopManager`、`RewardSelectionManager` 明显超出单一职责。
- 开闭原则: 内容池、Feature、波次 Modifier、UI Catalog 有扩展点；但主流程和武器仍需要修改核心类接入新能力。
- 依赖倒置: 局部存在接口如 `IWaveController`、`IAttackStrategy`、`IContentRandom`，但运行时仍大量依赖具体 MonoBehaviour 和静态全局。
- 接口隔离: 部分接口合理，但 `IUIManager` 之下的实现太大，接口稳定不能抵消内部耦合。
- 里氏替换: 当前深层继承不是最大问题，主要风险来自 MonoBehaviour 门面过大和隐式全局状态。

## 最危险模块

| 风险等级 | 模块 | 原因 |
| --- | --- | --- |
| 高 | 数据导入 | 直接删除资产，且影响可序列化引用；误操作成本最高。 |
| 高 | 全局事件与主流程 | 事件泄漏或状态错乱会影响整局游戏，定位困难。 |
| 高 | 武器运行时 | 高频扩展、高频变更、职责集中。 |
| 中高 | UI 框架 | 单类过大，所有页面都受影响。 |
| 中高 | 商店与奖励选择 | 内容池、暂停、UI、玩家组件、经济系统耦合。 |
| 中 | 敌人 Brain | 新敌人增长会带来重复状态机和物理判定逻辑。 |

## 项目健康度

- 技术债等级: **中高**
- 可维护性: **中等偏低**。局部系统有结构，但核心入口过大，文档可信度不足。
- 可扩展性: **中等**。内容池和 Feature 可扩展；主流程、武器、敌人 Boss 行为扩展成本偏高。
- 新人接手成本: **高**。根 README 缺失，主文档有过期类名，核心链路需要读大类源码。
- 重构风险: **中高**。直接拆大类风险高；应先补测试和安全门，再做无行为变化拆分。
- 潜在崩溃点: 数据导入误删、事件总线旧监听、场景引用缺失、UI 异步关闭/打开竞争、奖励暂停未释放。
