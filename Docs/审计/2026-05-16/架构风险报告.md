# 架构风险报告

生成时间: 2026-05-16 06:07:24 +08:00

项目层级判断: 长期迭代型小型 Unity 游戏项目。当前架构能支撑短期内容落地，但核心模块已经进入“可以继续加功能，但每次改动回归面偏大”的阶段。

## 技术基线

- Unity 版本: `2022.3.62f3c1`
- 渲染管线: URP `14.0.12`
- 主要依赖: UniTask、NaughtyAttributes、Unity Input System、TextMeshPro、UGUI、DOTween、Behavior Designer、Unity Test Framework
- 目录信号: 运行时代码集中在 `Assets/Scripts`，配置和内容资产集中在 `Assets/GameContent`
- asmdef: 本轮未发现任何 `.asmdef`，项目仍依赖默认 Assembly-CSharp / Assembly-CSharp-Editor 编译边界
- 测试: `Assets/Tests/Editor` 已覆盖内容池、数值资产、设置输入、奖励选择、武器运行时、波次等局部规则

## SOLID 与模块边界判断

- SRP 风险最高: `Weapon`、`UIManager`、`GameManager`、`SettingsPanelManager`、`ShopManager`。
- DIP 风险明显: 多处依赖 `GameEventBus`、`GameInput.Instance`、`UIManager.Instance`、`GameContentRuntime`、`RunProgressionRuntime`。
- OCP 风险集中在数值同步: `WeaponNumericAssetSync.ResolveAttackSequence` / `ResolveProjectileDefinition` / `ResolveSfxKey` 通过 switch 绑定 WeaponId，新增武器需要改代码。
- 伪模块化存在: 目录按模块划分，但没有 asmdef 和明确依赖方向，跨层调用靠约定。
- 数据流最不透明区域: `GameEventBus` 驱动的 GameManager / WaveManager / RewardSelectionManager / ShopManager 交互。
