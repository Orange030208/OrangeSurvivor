# 重构路线图

生成时间: 2026-05-14 06:10:04 +08:00
目标: 降低核心流程和玩法热点的长期维护风险，不做一次性大重写。
原则: 每一步都应保持序列化字段稳定，优先新增小型服务/适配层，再迁移调用点。

## 总体优先级

| 阶段 | 问题等级 / 优先级 | 问题描述 / 目标 | 文件路径 / 主要文件 | 修复建议 / 验收方式 |
|---|---|---|---|---|

| 2 | P0 | 拆 `Weapon` 运行时职责 | `Assets/Scripts/Weapons/Weapon.cs` | `Weapon` 保留 MonoBehaviour 门面；目标选择、属性结算、投射物模式、命中盒执行可独立测试。 |

## 详细路线

### P0-1 内容历史和文档同步

**问题等级**: 高
**影响范围**: 商店、升级奖励、宝箱、随机武器奖励、内容条件/权重规则。
**当前问题**:

- `Docs/统一内容池系统使用指南.md` 写成统一历史。
- `ShopManager`、`RewardSelectionManager` 各自持有 `ContentHistoryState`。
- `AddRandomWeaponCard` 使用静态 `ContentHistoryState`。

**推荐方案**:

1. 先做架构决定：per-run 统一历史，还是 per-domain 隔离历史。
2. 若选择 per-run，新增 `RunContentHistoryProvider`，由场景 Bootstrap 创建并传给商店/奖励/武器奖励。
3. 若选择 per-domain，文档改成当前真实模型，并说明隔离原因。
4. 修正文档中的 `ContentPoolPurpose`、`WaveSpawnExecutionService` 等过期名称。

**优先原因**: 成本低、影响广，能先恢复文档可信度，避免后续内容系统继续按错误模型扩展。

### P0-2 拆分 Weapon

**问题等级**: 高
**影响范围**: 武器、命中、投射物、特效、音效、属性。
**建议拆分顺序**:

1. `WeaponRuntimeStatsResolver`: 迁出 `RecalculateRuntimeStats`、攻击类型贡献、等级修饰解析。
2. `WeaponTargetingController`: 迁出 `TickTargeting`、`ResolveCurrentTarget`、瞄准方向逻辑。
3. `ProjectilePatternEmitter`: 迁出 `FireSingle`、`FireSpread`、`FireNova`、`BurstRoutine`。
4. `HitBoxAttackExecutor`: 从同文件移动为独立类，并为采样数量和重复命中写测试。
5. `WeaponDebugGizmoDrawer`: 迁出 Gizmos 和调试采样表现。

**验收标准**:

- `Weapon` 只保留生命周期、数据绑定和协调。
- 武器攻击、命中盒、投射物模式分别能单独测试或至少单独验证。
- 不改已有序列化字段名，必要时使用 `[FormerlySerializedAs]`。

### P0-3 拆分 GameManager

**问题等级**: 高
**影响范围**: 主菜单、角色选择、游戏、商店、暂停、GameOver、StageComplete。
**建议拆分顺序**:

1. `GameStateTransitionService`: 纯 C# 判断允许/阻止状态切换。
2. `GameUIFlowRouter`: 只负责根据 `GameState` 打开/关闭页面和构造页面上下文。
3. `GameSceneBinder`: 只负责查找/验证场景依赖。
4. `RunLifecycleCoordinator`: 负责波末、玩家死亡、结算和重新开始。

**验收标准**:

- `GameManager` 不再直接构造所有 UI 页面上下文。
- 玩家生成、地图生成、波次开始不混在状态切换函数里。
- 关键状态切换可用 EditMode 测试覆盖。

### P1-1 全局状态生命周期边界

**问题等级**: 中高
**影响范围**: 事件、内容 Provider、推进快照、输入、UI。
**建议**:

- 给 `GameEventBus` 增加 `[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)] Clear`。
- 给 `GameContentRuntime`、`RunProgressionRuntime`、输入模块补同类 reset 契约或确认已有契约。
- 建立场景启动自检，启动时输出当前 Provider、输入、UI、GameManager 绑定状态。

**验收标准**:

- 关闭 Domain Reload 后连续进出 Play Mode 不重复触发核心事件。
- 自动化测试不需要手动清理全局事件状态。

### P1-2 商店与奖励选择瘦身

**问题等级**: 中高
**影响范围**: 经济、装备、升级卡、宝箱、UI。
**建议**:

- `ShopRollService`: 只负责基于 `ContentRollContext` 生成商品。
- `ShopPurchaseService`: 只负责价格校验、货币扣除和装备应用。
- `RewardSelectionFlow`: 只负责请求队列、暂停/恢复和选择结果。
- `RewardApplicationService`: 只负责升级卡/饰品应用。

**验收标准**:

- `ShopManager` 购买路径不再调用 `FindFirstObjectByType`。
- 奖励选择取消、切状态、连续升级点有回归测试。

### P2-1 设置与输入解耦

**问题等级**: 中
**影响范围**: 设置页、键鼠/手柄重绑、显示确认。
**建议**:

- `GameSettingsService` 只保留加载、保存、规范化数据。
- 新增 `SettingsApplyService` 处理音频、显示、语言、输入应用。
- `SettingsPanelManager` 通过 `ConfigureOwner` 或页面上下文拿 `IInputActionProvider` 和 `IInputBindingStore`。
- `ValidateConfiguration` 根据平台 profile 检查启用功能，不再强制所有设置行都存在。

**验收标准**:

- 无输入重绑平台可以不配置 `rebindRows`。
- 设置面板单元/编辑器测试可传入假的输入提供者。

### P2-2 属性系统下沉

**问题等级**: 中
**影响范围**: 玩家、敌人、Buff、饰品、武器、商店价格。
**建议**:

- 抽 `PropCalculationEngine`，输入 base props、modifiers、mappings，输出 snapshot。
- `AttributeManager` 只负责与 Entity 生命周期和事件桥接。
- `sourceId` 从 string 升级为结构化来源，至少封装构造器，避免拼字符串分散。

**验收标准**:

- 属性默认值、映射、乘区顺序有 EditMode 测试。
- 新增 `PropType` 时测试能提示默认值和显示配置缺失。

### P2-3 asmdef 渐进落地

**问题等级**: 中
**影响范围**: 编译速度、依赖边界、测试。
**建议顺序**:

1. 先分离 `Assets/Scripts/*/Editor` 到 Editor asmdef。
2. 再分离 `Assets/Tests` 到 Test asmdef。
3. 最后按稳定模块拆 Runtime: Content、Combat、UI、Input、GameFlow。

**验收标准**:

- Editor 代码不能被 Runtime 引用。
- 测试能显式声明依赖，不再吃默认程序集的所有类型。

## 最推荐先执行事项

先执行 **P0-1 内容历史和文档同步**。原因是它改动小、影响广，并且当前文档与代码实际行为冲突会持续误导商店、升级卡、宝箱、刷怪和随机武器奖励的后续实现。完成后再进入 `Weapon` 拆分，收益最大。
