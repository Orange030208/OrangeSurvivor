# 架构风险报告

生成时间: 2026-05-14 06:10:04 +08:00
项目定位: Unity 2D Survivors 类小型到中长期项目。
审计原则: 以当前代码结构和运行时依赖为准。

## 技术基线

- Unity 版本: `2022.3.62f3c1`
- 渲染管线: URP `14.0.12`
- 关键包: Input System `1.7.0`、UniTask、NaughtyAttributes、DOTween、Unity Test Framework、Unity MCP、Unity Skills。
- asmdef: 当前 `rg --files -g '*.asmdef'` 无结果，项目运行时代码仍主要处于默认程序集。
- 主要资源组织: `Assets/GameContent/` 承载 Catalog、UI、Upgrades、Waves 等内容资源；运行时代码集中在 `Assets/Scripts/`。

## 总体健康度

| 维度 | 评级 | 说明 |
|---|---|---|
| 技术债等级 | 中高 | 核心流程大类过多，隐式全局入口多。 |
| 可维护性 | 中 | 业务能跑，但新需求需要理解多个 Manager 和事件链。 |
| 可扩展性 | 中 | ScriptableObject 配置化基础较好，但运行时编排类阻碍扩展。 |
| 新人接手成本 | 高 | 缺少根 README 和场景装配契约，文档部分类名过期。 |
| 重构风险 | 中高 | `Weapon`、`GameManager`、`UIManager` 改动牵涉主流程。 |
| 潜在崩溃点 | 中高 | 多个 `Awake`/`ValidateConfiguration` 直接抛异常，场景缺引用会启动失败。 |

## SOLID 与模块边界评估

- **单一职责**: `Weapon`、`GameManager`、`UIManager`、`SettingsPanelManager`、`ShopManager` 明显违反 SRP。
- **开闭原则**: 商店购买类型、奖励选择类型、UI 栈策略仍依赖集中修改大类；新增类型不够开放。
- **依赖倒置**: 多数 Manager 直接依赖具体 MonoBehaviour、静态单例或场景查找，而不是依赖接口和组合根。
- **数据层/逻辑层/表现层**: ScriptableObject 数据层基础较好；运行时逻辑仍大量留在 MonoBehaviour；UI 表现和应用服务在设置/商店/奖励中混杂。
- **伪模块化**: 目录结构看起来分模块，但没有 asmdef，且静态入口跨目录访问频繁。

| 文件路径 | 类 / 函数 | 崩溃/失败条件 | 建议 |
|---|---|---|---|
| `Assets/Scripts/Managers/WaveManager.cs` | `Awake` | 缺 `StageDefinitionSO`、`EnemyRegistry`、`ContentPoolSO`、`SpawnLocationPolicySO` 时抛异常。 | 在场景装配契约和启动自检中提前验证。 |
| `Assets/Scripts/Managers/GameManager.cs` | `ResolveSceneReferences`, `CreateShopPageContext`, `CreateStageCompletePageContext` | 缺 `UIManager`、`CharacterSelectionManager`、`WaveManager`、`EnemyRegistry`、`ShopManager` 等引用时抛异常。 | 把必填场景引用收口到 Bootstrap 验证。 |
| `Assets/Scripts/Weapons/Weapon.cs` | `ApplyCurrentConfiguration`, `ApplyVisualForwardAngle`, `RecalculateRuntimeStats` | `WeaponData`、`visualForwardTransform`、`EntityRenderer`、父级 `AttributeManager` 缺失时抛异常。 | Prefab 导入/保存时增加武器 Prefab 校验器。 |
| `Assets/Scripts/UI/Instances/Child/SettingsPanelManager.cs` | `ValidateConfiguration` | 任意设置行、分区、按钮或重绑行缺失时抛异常。 | 按启用功能校验，并用 Prefab 构建测试覆盖。 |

## 架构是否支撑后续迭代

当前结构能支撑短期内容配置和小规模玩法迭代；但如果继续扩展武器形态、奖励类型、商店机制、输入平台和 UI 复杂度，而不拆核心大类，项目会进入高回归成本阶段。最危险的不是某个单点 bug，而是主流程和战斗核心缺少可测试的纯逻辑边界。

## 最危险模块

1. `Weapon`：玩法新增频率高，职责最集中。
2. `GameManager`：所有状态切换和场景运行边界都经过它。
3. `UIManager`：全 UI 框架核心，体量大。
4. `RewardSelectionManager`：异步状态、暂停和奖励应用交织。
5. `ShopManager`：经济、内容池、装备和 UI 状态交织。
