## 最推荐先做

先执行 **P0-1 GameEventBus reset** 和 **P0-2 JSON 导入删除保护**。

原因:

- `GameEventBus` reset 是小改动高收益，可直接降低全局状态污染。
- JSON 导入删除保护与当前工作区删除 Buff 资产直接相关，继续放任会扩大内容资产风险。
- 文档修复紧随其后，避免旧术语继续误导后续实现。

## 分阶段建议

### 阶段 1: 生命周期与资产安全

- `GameEventBus` 增加 SubsystemRegistration reset。
- JSON 导入工具默认禁止删除 stale 资产。
- 补两类 EditMode 测试: 事件 reset、导入 Preview/Apply 删除保护。

### 阶段 2: 文档恢复可信

- 修正文档旧类名和旧术语。
- 新增 JSON 导入工具说明。
- 新增内容历史生命周期表。

### 阶段 3: 内容历史定版

- 决定 per-run / per-domain 策略。
- 推荐引入 `RunContentHistory`。
- 给商店、升级奖励、宝箱、武器奖励、掉落、刷怪补历史行为测试。

### 阶段 4: 核心大类小步拆分

- `Weapon`: 先拆 Gizmo 和序列事件，再拆攻击周期。
- `GameManager`: 先抽状态机，再拆波末流程。
- `UIManager`: 先拆 Root/Layer/Diagnostics。

## 风险控制

- 不做一次性大换架构。
- 每次只移动一个明确职责，并保留公开 API。
- 先拆纯逻辑和无行为变化辅助类。
- 涉及 Unity 序列化字段时保留字段名或使用 `[FormerlySerializedAs]`。
- 涉及资产/场景写入时必须先 Preview，再 Apply，再检查 git diff。
