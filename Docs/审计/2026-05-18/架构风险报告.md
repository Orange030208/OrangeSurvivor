# 架构风险报告

生成时间: 2026-05-18 06:10:15 +08:00

项目层级判断: 长期迭代型小型 Unity 游戏项目。短期继续做内容和小玩法可行，但核心流程、数据导入和全局状态需要先降风险，否则新增系统会持续压到少数大类和静态入口上。

## 技术基线

- Unity 版本: `2022.3.62f3c1`
- 渲染管线: URP `14.0.12`
- 主要依赖: UniTask、NaughtyAttributes、Input System、TextMeshPro、UGUI、DOTween、Behavior Designer、Unity Test Framework、UnitySkills/MCP
- 目录信号: 运行时代码集中在 `Assets/Scripts`，内容资产集中在 `Assets/GameContent`
- asmdef: 本轮未发现项目自有 `.asmdef`，仍主要依赖默认 `Assembly-CSharp` / `Assembly-CSharp-Editor`
- 测试: `Assets/Tests/Editor` 覆盖内容池、波次、奖励、设置、武器、屏幕震动等局部规则，但缺少事件总线 reset、JSON 删除保护、DOT 结算路径等关键测试

## SOLID 与模块边界判断

- SRP 风险最高: `Weapon`、`UIManager`、`GameManager`、`ShopManager`、`RewardSelectionManager`、`BuffController`。
- DIP 风险明显: `GameEventBus`、`UIManager.Instance`、`GameContentRuntime.Provider`、`RunProgressionRuntime.CurrentSnapshot`、`GameInput.Instance`。
- OCP 风险集中在数据导入: JSON 字段和支持的 Feature/Strategy 类型通过 switch/字符串控制，新增 Feature 或 Spawn Strategy 需要改导入器。
- 伪模块化存在: 目录分层存在，但无 asmdef 和依赖方向约束。
- 数据流最不透明区域: `GameEventBus` 驱动的 GameManager/WaveManager/RewardSelectionManager/ShopManager 交互，以及 ContentHistoryState 分散持有。

## 当前架构是否还能支撑后续迭代

可以支撑短期内容迭代，但不建议继续在当前结构上直接叠加大量新玩法。最需要先处理的是:

1. 生命周期污染: `GameEventBus` reset、静态告警状态 reset、全局输入/内容/推进入口边界。
2. 数据资产安全: JSON 导入删除行为、导入报告落盘、内容池引用校验。
3. 文档可信度: 旧类名、旧术语、缺失的 JSON/场景/波次位置策略说明。

在这些处理前，直接启动 `Weapon` / `UIManager` / `GameManager` 的大拆分风险偏高。
