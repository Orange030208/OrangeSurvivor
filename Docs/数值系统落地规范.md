# 数值系统落地规范

本文档只描述 `玩法数值规范.md` 如何映射到当前 Unity 工程的资产、字段和运行时结算。数值目标、BP、价格、波次压力和填表模板以 `玩法数值规范.md` 为准；本文件不重新定义数值强度。

## 1. 属性单位与边界

### 1.1 单位换算

- 百分比点：配置值 `1` 表示 `1%`。运行时需要 ratio 时统一换算为 `value / 100f`。
- 距离点：配置值 `100` 表示 Unity 世界空间中的 `1` 个距离单位。运行时需要物理距离或速度时统一换算为 `value / 100f`。
- 攻速点：配置值 `100` 表示每秒攻击 `1` 次。运行时每秒攻击次数为 `attackSpeedPoints / 100f`，攻击间隔为 `100f / attackSpeedPoints`。

### 1.2 统一边界入口

`PropertiesManager` 只负责保存和计算属性真实累计值，不在属性值本身上做有效值截断。消费侧边界，包括下限、上限、取整、百分比点换算、攻速点换算、距离点换算、价格折扣和概率有效范围，都应由 `PropValueUtility` 或其直接调用链统一处理。

禁止在 Controller、Strategy、Feature、UI 或测试辅助逻辑中重复定义同一属性的边界魔法值。新增边界规则时，先补 `PropValueUtility` 的统一方法，再让消费模块调用。

## 2. 局内推进与经济

### 2.1 推进曲线

局内推进曲线由 `RunProgressionProfileSO` 配置，并在运行时输出 `RunProgressionSnapshot`。它是波次、刷怪、掉落、商店和内容池条件共享的上下文，不按玩家实时 DPS 做橡皮筋追平。

`RunProgressionProfileSO.enemyPropScaleCurves` 可以按 `PropType` 配置任意属性的增长曲线。当前默认应覆盖：

- `MaxHealth`
- `Attack`
- `MoveSpeed`
- `AttackSpeed`

敌人缩放只作用于运行时属性修饰，不回写 `EnemySO` 或基础属性资产。

### 2.2 商店价格与内容池

商店由 `ShopManager` 从 `ContentPoolPurpose.Shop` 内容池抽取商品。商品最终价格由 `ShopPricingService` 统一计算；商店刷新、内容池价格倍率、局内价格倍率和玩家折扣只影响结算价格，不回写物品资产。

默认字段映射：

| 设计项 | 当前字段或系统 |
| --- | --- |
| 商品格数量 | `ShopManager.containersToAdd` |
| 刷新基础价 | `RunProgressionSnapshot.ShopRerollBasePrice` |
| 内容池价格倍率 | `ContentPoolEntry.PriceMultiplier` |
| 玩家折扣 | `ShopPriceDiscount` |

刷新价格按快照中的当前刷新基础价和局内商店价格倍率结算。每次付费刷新后，下一次刷新基础价按商店系统规则递增。

商店锁定商品应保留商品、等级和内容池价格倍率；进入下一波或刷新显示时，重新套用当前局内商店价格倍率和玩家折扣。

### 2.3 商店重复过滤

同一商店刷新结果中默认不允许完全相同商品。锁定商品应纳入当前展示结果的去重集合，否则会提高重复风险。

饰品过滤按以下规则落地：

- 已拥有的唯一饰品不再进入普通商店、宝箱和奖励入口。
- 非唯一饰品可以再次出现。
- 只有明确配置了持有上限时，才按上限过滤。
- 未配置唯一性和持有上限的饰品，默认允许继续出现。

## 3. 玩家与经验

### 3.1 玩家基础属性

玩家 1 级基础属性当前以 `CharacterDataSO.BasePropsAsset` 指向的 `BasePropGroupSO` 为入口。角色系统仍存在时，角色差异通过 `CharacterDataSO.ExtraProps`、初始武器、初始饰品或特殊效果表达。

如果后续移除角色系统，应保留一份统一玩家基础属性资产或等价配置来源，并继续使用 `玩法数值规范.md` 中的玩家基准。

### 3.2 经验曲线

玩家经验由 `PlayerLevelConfigSO` 控制：

| 设计项 | 当前字段 |
| --- | --- |
| 初始等级 | `StartLevel` |
| 初始经验 | `StartExperience` |
| 经验需求关键点 | `RequiredExperienceByLevel` |
| 单级经验需求下限 | `MinimumRequiredExperience` |
| 每级升级点 | `UpgradePointsPerLevel` |

经验需求结算：

```text
当前等级 <= 最后关键等级：
  在 RequiredExperienceByLevel 相邻关键点之间线性插值

当前等级 > 最后关键等级：
  按最后两个关键点的斜率继续外推

最终经验需求 =
  max(MinimumRequiredExperience, round(曲线结算值))
```

`ExperienceGain` 使用百分比点提高击杀经验获取。运行时应保留小数累计，再向下取整发放实际经验。

## 4. 升级卡

升级卡片不直接配置独立属性修饰字段。属性收益统一配置为 `UpgradeCardSO.SpecialFeatures` 中的 `PropertyModifierFeature`，运行时由 `FeatureHost` 安装后写入 `PropertiesManager` 参与统一属性结算。

升级卡落地要求：

- 升级卡当前按设计口径不配置机制卡，但 `specialFeatures` 容器本身保持通用，不在代码层按 Feature 类型过滤。
- 不通过 `MaxPickCount` 或同类数量上限控制升级卡。
- 同一升级卡可以重复出现和重复选择。
- 如果需要改善选择多样性，只做软性权重调整，不做硬移除。
- 最终有效值边界仍通过 `PropValueUtility` 统一处理。

## 5. 武器

### 5.1 资产与等级表

武器基础数据由 `WeaponDataSO` 提供：

| 设计项 | 当前字段 |
| --- | --- |
| 1 级基础价 | `WeaponDataSO.ItemPrice` |
| 每级基础数值 | `levelStats` |
| 五项同名属性收益率 | `WeaponDataSO.benefits` |
| 四项攻击类型比例 | 每级 `levelStats` 中的 `MeleeAttackUsagePercent`、`RangedAttackUsagePercent`、`MagicAttackUsagePercent`、`SummonAttackUsagePercent` |
| 每级持有者属性 | `HolderModifiers` |

武器自身只配置静态基础数据和等级表。玩家属性、升级卡、饰品和局内推进修饰只作用于运行时结算，不回写武器资产。

### 5.2 收益率结算

`WeaponsHolder` 的武器收益率修饰使用完整 `WeaponBenefitData`，外部特性可以同时调整同名属性收益率和四项攻击类型收益率。

所有收益率都使用百分比点：

- `100` 表示完整吃到玩家属性收益。
- `50` 表示只吃到玩家属性收益的一半。
- `0` 表示完全不吃该属性的玩家外部收益。

同名属性收益率只折算玩家属性、升级卡、饰品等外部来源带来的增量，不折损武器等级表里的自身基础值。`AttackSpeed`、`Range` 和 `KnockbackStrength` 会先使用 `PropertiesManager.GetPropValueWithAdditionalBase` 与玩家同名属性进入同一套属性乘区，再按武器收益率折算外部增量。

### 5.3 持有者属性

`HolderModifiers` 在武器启用或等级变化时按武器实例安装到持有者 `PropertiesManager`，卸下或禁用时移除。默认使用 `Add`，乘区必须按 `玩法数值规范.md` 的乘区风险规则单独核算。

## 6. 怪物与波次

### 6.1 怪物资产

怪物基础面板写在 `EnemySO.BasePropsAsset` 对应的 `BasePropGroupSO` 中，用于定义该怪物在 1 波附近的基础定位。

局内推进缩放由 `RunProgressionProfileSO` 根据波次统一提供，不回写 `EnemySO` 或基础属性资产。Boss、精英、快速、远程等额外压力通过 `EnemyRole` 或 `WaveEnemyTag` 叠加倍率表达。

### 6.2 波次资产

波次压力由单体属性和刷怪规模共同决定：

| 设计项 | 当前字段或结构 |
| --- | --- |
| 单波持续时间 | `WaveDefinitionSO.duration` |
| 生成频率 | `WaveSpawnPlan.spawnFrequency` |
| 每批生成数量 | `WaveSpawnPlan.spawnCountPerBatch` |
| 最大生成批次 | `WaveSpawnPlan.maxSpawnBatches` |
| 波内生成时间段 | `WaveSpawnPlan.normalizedTimeRange` |

配置波次时必须同时看单体怪物、总数量、同屏数量、时间分布和生成位置。

### 6.3 怪物配置流程

落地配置建议：

1. 先确定怪物定位：普通近战、重型近战、快速追击、远程怪、特殊怪或 Boss。
2. 按 `玩法数值规范.md` 的 1 波基准模板配置 `BasePropGroupSO`。
3. 确认敌人范围相关行为统一使用 `AttackRange`，攻击自身倍率同时作用于入场距离与实际覆盖。
4. 再按攻击动作评估实际威胁：前摇越短、命中越稳定、覆盖越大，`Attack` 和 `AttackSpeed` 越要保守。
5. 放入波次池前，先按目标击杀时间检查单体强度。
6. 最后按波次规模与压力预算调整数量、权重、标签、出现时间和生成位置，不用基础属性硬塞所有强度。
