# 工程映射与迁移清单

## 1. 目标

本文件不定义新强度，而是说明当前工程要如何承接本目录中的 `Brotato` 化数值体系。

目标是：

- 保持策划口径独立
- 明确当前代码和资产哪些地方要改
- 避免继续让旧数值体系反向约束新文档

## 2. 当前项目的关键前提

### 2.1 没有角色系统

后续不再以角色作为数值入口，因此：

- `CharacterDataSO` 不再承担职业/角色差异职责
- 只保留统一玩家基础属性入口即可
- 流派导向改由武器与商店完成

### 2.2 旧 BP 不再生效

后续若需要做数值审表、配置核对、调价、武器重写，不再参考：

- 旧 BP 单位
- 旧锚点兑换表
- 旧“普通奖励 / 构筑核心 / 终局效果”那套价值预算

新的判断依据是：

- 升级档位等价物
- 商店价格层级
- 正负词条代价
- 波次时序价值

## 3. 属性层映射建议

### 3.1 直接沿用的字段

| 新策划属性 | 当前字段 |
| --- | --- |
| Max HP | `MaxHealth` |
| HP Regeneration | `HealthRecoverySpeed` |
| Life Steal | `LifeSteal` |
| Damage | `Damage` |
| Attack Speed | `AttackSpeed` |
| Crit Chance | `CriticalChance` |
| Armor | `Armor` |
| Dodge | `Dodge` |
| Speed | `MoveSpeed` |
| Range | `AttackRange` |
| Luck | `Luck` |
| Melee Damage | `MeleeAttack` |
| Ranged Damage | `RangedAttack` |

### 3.2 需要重命名或重定义的字段

| 现字段 | 新用途建议 |
| --- | --- |
| `MagicAttack` | 重命名为 `ElementalDamage`，策划显示层与文档统一使用“元素伤害” |
| `CriticalPercent` | 从公共主轴降级为武器特性或少量特殊机制 |
| `WaveGoldRewardBonus` | 退出主经济轴，长期由 `Harvesting` 替代 |

### 3.3 需要新增的字段

| 新属性 | 原因 |
| --- | --- |
| `Harvesting` | 新经济主轴，不能长期用旧金币奖励字段替代 |
| `Engineering` | 新主流派轴，不能长期用 `SummonAttack` 混充 |

### 3.4 需要降级为次属性或内部字段的内容

| 字段 | 处理建议 |
| --- | --- |
| `Attack` | 仅用于武器或敌人基础值，不进入玩家常规成长主池 |
| `DamageReduction` | 从玩家公开主池移除，仅保留少量特殊机制使用 |
| `ExperienceGain` | 降为特殊经济项 |
| `ShopPriceDiscount` | 降为特殊经济项 |
| `PickupRadius` | 保留为手感功能项，不作为主价值轴 |

## 4. 系统层改动建议

### 4.1 玩家基础属性入口

后续应保留一个统一玩家基础属性资产，不再依赖角色差异。

推荐做法：

- 保留一份统一 `BasePropGroupSO`
- 所有局内基础属性从这份资产起步
- 角色差异相关入口不再作为主设计来源

### 4.2 升级系统

建议后续确认并逐步对齐：

- 升级默认 `4` 选 `1`
- 升级档位使用本目录定义的 I 到 IV 档
- 升级池中不再投放 `Attack`、`DamageReduction`、`ShopPriceDiscount` 等旧公共主词条

### 4.3 商店系统

建议后续确认并逐步对齐：

- 商店 `4` 格
- 前 2 店固定 2 武器
- 第 3 到 5 店至少 1 武器
- 采用武器已持有同名与同类别偏向，而非角色标签偏向
- 支持锁价、锁货、买空刷新、同名合成

### 4.4 武器数据

`WeaponDataSO` 和 `WeaponBenefitData` 非常适合承接新体系，但后续要重新填写设计口径：

- 类型平伤收益率必须强区分
- 暴击收益必须武器化
- 工程类武器和结构类效果不能默认吃满通用攻速和通用伤害

### 4.5 结构与工程

如果要做出 `Brotato` 风格工程流，后续必须补一条真实“结构体系”：

- 炮塔
- 地雷
- 医疗塔或功能塔
- 结构专属联动件

如果没有结构体系，只靠现有 `SummonAttack` 很难做出真正的工程 build。

## 5. 文档层处理建议

旧文档不建议立刻删除，但需要重新划边界：

- `Docs/玩法数值规范.md`
  - 继续保留给旧资产与旧工程字段核对用
- `Docs/数值系统落地规范.md`
  - 后续需要补一版“Brotato化字段落地规范”

在此之前，本目录应被视为新数值设计的唯一入口。

## 6. 推荐迁移顺序

### 第一步：锁新文档

先冻结本目录中的总原则、属性轴、经济轴和波次节奏，避免边做边改设计哲学。

### 第二步：补属性枚举和显示名

优先处理：

- 新增 `Harvesting`
- 新增 `Engineering`
- `MagicAttack` 改显示为 `ElementalDamage`

### 第三步：重写升级卡池

将升级卡改为：

- `Brotato` 风格主属性池
- 4 档升级数值
- 去掉旧主池中的过时属性

### 第四步：重写商店道具池

重点改：

- 价格
- 稀有度开放
- 正负词条比例
- 经济件时序

### 第五步：批量重写武器

重点改：

- 武器基础值
- 同名合成目标
- 类型平伤收益
- 暴击和范围收益
- 工程特殊口径

### 第六步：重调敌人和波次

最后根据新 build 实测来调：

- 小怪密度
- 精英节点
- 终局 Boss

## 7. 迁移完成的标志

当以下条件同时成立时，可以认为这套新体系真正接入工程：

1. 玩家面板主属性已改为 `Brotato` 主轴。
2. 商店主池不再依赖旧价值预算。
3. 升级池已改为新档位和新属性集合。
4. 武器成长不再默认统一吃满所有外部属性。
5. `Harvesting` 和 `Engineering` 已进入运行时和显示层。
6. 旧 `Attack` 与 `DamageReduction` 不再充当玩家公开主成长轴。
